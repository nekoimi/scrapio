# 输入来源与日常治理 O4 实施与验收记录

实施日期：2026-10-13。主平台 `scrapio`，数据库/API 全部使用独立 `co_` / `/api/v4` 域。O4-01～10 开发功能接通；真实网站、浏览器、重启并发及吞吐验收仍属于 CO-O4-R。本轮未改 scrapio-browser，也未触碰旧采集规则和数据。

## 1. 输入来源与冻结边界

入口支持手动、表快照与文件快照。表输入显式选表/当前 Schema、记录 ID 或 JSON 字段相等条件、最大行数以及来源列到采集器输入的映射。表记录取样按 ID 排序，在一个 REPEATABLE READ 事务中保存记录 ID、revision、原值、映射后值与整个请求指纹；读取超过上限或所选记录缺失会阻断，不静默取前几条。

O4 首版将 O0 的“大批次上限”收敛为 **1000 行、4MiB 来源快照、10秒操作期限/8秒单条SQL期限**。这一有限规模在单个事务中完成整个快照，不提供跨事务继续 MVCC 的假恢复。快照提交前失败，没有可使用的来源资产；用户必须重新预览并核对结果、指纹和条数。已提交的原请求用幂等键查回同一资产。确认快照后才保存/发布任务；正式运行在同一事务冻结所有根输入，随后 worker 每次最多物化10个工作项并持久化游标。恢复工作项只读取原运行输入，不读取当前表值。

文件支持含表头的 UTF-8 CSV、JSON 对象数组；最多768KiB、1000行。列映射显式配置，CSV 非字符串输入支持按JSON标量解析，再执行采集器类型/访问范围校验。预览标注行序号、错误、规范化输入重复对应行，保留原文件与完整检查结果。无效和重复行需要勾选“仅导入有效不重复行”，并确认指纹/有效条数；不能以“导入成功”掩盖部分导入。CSV格式损坏直接报告行号并阻断整份文件；没有 XLSX、压缩包或分片文件上传。

预览返回前100行；`GET /sources/{source_id}?offset=...&limit=...` 有界查完整检查结果。任务引用 `snapshot_id / snapshot_hash / count / accept_partial`；重复的手动输入仍保持独立来源，文件/表输入的重复行由用户明确确认排除。

## 2. 日常执行与触发

任务固定间隔计划为60秒～30天、UTC计算，明确引用任务版本和计划 revision。编辑用 CAS，计划触发以“计划ID+revision+原到期时刻”作为持久幂等键。触发创建、来源记录和下次时刻推进在同一事务提交，进程重启查询原键；结果未知不会换键再触发。停机期间合并一个到期执行，下一次推进到未来，不补放所有漏掉的历史时刻。

默认同任务/同命名空间不重叠，暂停或等待确认也属于活动运行。重叠触发记录 `skipped_overlap` 和原运行，计划页面显示下次执行时刻，工作台展示近期计划/API触发结果。旧调度没有修改或停用。

API正式触发复用 `POST /tasks/{task_id}/runs`，请求含具体 `task_version_id`、`namespace` 和 `Idempotency-Key`；响应丢失查询 `GET /operations/by-key`。**表/文件计划复用已确认快照，不自动查询最新表，也不是持续数据订阅**；新增目标需重新取样、保存并发布任务版本。自动动态表查询另行定义一致性/证据契约后扩展。

每阶段 `refresh_seconds` 为0～30天，0表示每次访问。成功历史按账号、规范化输入、采集器版本、保存和连接策略哈希记录，只有正式工作项完成并提交最后批次后才算成功；partial、limited、试采和已保存但未完成的项不充当成功记录。规范化输入或版本/策略变化会重新访问；不使用业务记录的更新时间计算TTL。

命中TTL的工作项标记 `skipped`，保留原成功运行/输入证据与原因。本次不访问、不重新发旧输出，其下游覆盖也被跳过，阶段/运行明确为部分覆盖。重试已有attempt不会突然转成TTL跳过；局部补采关闭TTL。连接 `created/changed` 仍只按本次保存决策传递，不能代表完整刷新。

## 3. 升级与局部补采

任务升级页面可比较同一采集器新旧版本的输入/输出Schema、定义及各revision样例，预演当前任务输入、映射、保存绑定的兼容性。应用需要显式确认并按任务revision保存草稿；之后再发布任务新版本。活动运行和既有计划保持原版本。

表Schema首版只允许新增可缺省字段，保留已有字段定义和唯一键。有活动写表运行时拒绝升级；已有记录不重写，保留原schema_version。升级后旧任务绑定会明确报 `SCHEMA_CONFLICT`，必须重新预演并发布；不自动更换表版本。字段类型变更、删字段或改唯一键需新建表。

任务归档检查活动运行、关闭计划并保留历史/来源；已发布任务引用的采集器不能归档。不开放硬删除，避免级联丢失已发布依赖。

`POST /runs/{run_id}/replay` 从指定阶段创建新运行，只保留该节点及其下游。来源三选一：原阶段工作项输入、原上游不可变输出经冻结映射、已确认的表快照。历史来源最多100个，映射展开后的历史补采根输入也最多100条；表快照最多1000条且受任务预算约束。历史输出选择会重新应用映射和过滤，显式选中的输出不因旧连接的created/changed发射策略自动排除。

可显式采用同任务的修复发布版本，先校验输入及保存Schema；历史输出缺失或不属于相应上游阻断，不代用表最新值。保留 `retry_of`、原input/output ID、mapping hash、目标版本和 `not_executed:阶段ID` 范围。原试采维持隔离写入0和试采预算，原版本保留离线页面证据；修复版本仍需要匹配的页面样例验证。原运行必须先终止，未知动作不能作为失败项自动重放。页面说明局部成功不算完整回归。

数据表可勾选当前加载的记录，选择已有采集器后进入正常单阶段任务配置，预览来源映射、输出表和预算再发布/执行。看数据或改配置不会自动执行，也不用重新跑榜单。

## 4. 工作台、容量与保留

`/app/co/home` 为新默认工作台；任务、采集器、运行、数据表各有独立页面，旧工作台仍可进入。统计只查询 `co_` 域。工作台呈现近期20次运行/触发、确认/暂停/部分覆盖/失败待办、10张近期数据表，以及容量/积压；运行链接继续到阶段、具体输入和来源链。它不是全量告警系统，历史运行和触发仍以分页/原操作查询为准。

全局配置（环境变量；compose已同步）：

| 配置 | 默认/范围 | 含义 |
| --- | --- | --- |
| `SCRAPIO_CO_HTTP_SLOTS` | 2，1..8 | HTTP工作项并发 |
| `SCRAPIO_CO_BROWSER_SLOTS` | 1，1..8 | 浏览器工作项并发 |
| `SCRAPIO_CO_SITE_INTERVAL_MS` | 500，0..60000 | 跨新任务的同站点工作项启动间隔；不是逐页网络请求速率 |
| `SCRAPIO_CO_ACTIVE_RUNS` | 20，1..100 | 每账号活动运行上限，含暂停/等待确认 |
| `SCRAPIO_CO_SOURCE_STORAGE_MIB` | 64，4..4096 | 每账号来源快照内容配额 |
| `SCRAPIO_CO_OUTPUT_STORAGE_MIB` | 256，4..4096 | 每账号不可变输出JSON内容配额 |
| `SCRAPIO_CO_SOURCE_RETENTION_DAYS` | 30，1..3650 | 未引用来源证据保留天数 |

并发、容量和速率为保守默认值，**没有真实环境吞吐实测**，能力响应明确 `defaults_measured=false`。站点新工作项启动节流通过持久时间锁协调；运行、阶段、输入物化和分发轮转，保留原有待处理队列/outbox/工作项/输出/时长预算，不依靠提高并发隐藏积压。worker空闲SQL轮询使用会话级SQL日志关闭，业务警告和错误保留；API SQL诊断仍遵循 `DB_SHOW_SQL`。

来源/输出容量账本与写入同事务，超过配额回滚当前事务，保留已提交证据。**配额计量JSON内容，不等于PostgreSQL磁盘大小**；业务记录、修订、观察、操作日志和索引的整体磁盘仍需部署监控。输出满额明确limited，调整容量后按证据局部补采；不会通过删除活跃证据自动腾空间。

worker启动1分钟后、以后每小时最多清理20个过期且未被任何草稿/发布版本引用的来源快照内容，留下过期状态和指纹。取用来源和清理共享事务锁，避免确认来源与清理竞态。运行自身拥有完整输入；不删除输入、工作项、已发布版本、outbox、输出、观察、修订和来源链；本轮没有自动运行历史清理。过期资产不能确认进入新运行，页面报告复现限制。

导出为 JSON，显式选记录或有限整表、最多1000条/4MiB、按ID排序、REPEATABLE READ边界，包含表Schema、记录修订/Schema版本与内容指纹。超界阻断，不能把截断结果伪装为全表导出；历史运行证据另查运行页，不混入当前记录导出。

## 5. API、迁移与部署

新增迁移 `2026_10_13_004`：来源快照、计划/触发、成功输入历史、站点节流、容量账本、任务归档及运行公平性时间索引字段。保持加法迁移，启动仍先完成迁移再启动 `coWorker/coTaskWorker`；没有新生命周期bean，也没有改变旧worker顺序。

新增实际接口：

- `GET /governance`，`POST /sources/preview`，`GET /sources/{source_id}`。
- `GET/POST /tasks/{task_id}/schedule`，`POST /tasks/{task_id}/upgrade-preview`，`POST /tasks/{task_id}/archive`。
- `POST /runs/{run_id}/replay`，`POST /tables/{table_id}/export`，`POST /tables/{table_id}/schema`。

请求所有权、严格JSON、1MiB body和变更幂等保护复用现有API。`co-o4.cjs`为O4实际OpenAPI生成补丁，替换O0计划中的source-check/import/cron接口，39个O2～O4挂载路由/方法与契约一致。HTTP运行不需浏览器；浏览器仍需 O1 的 `editor.isolated.v1`。本轮无需浏览器配套提交；使用缺该协议的旧服务会阻断浏览器任务。

Dockerfile现有多阶段构建已包含Go自动注册迁移及web资源，无需额外生成/拷贝或新增端口。compose增加容量/速率/保留与SQL日志开关；YAML继续采用现有DB/浏览器配置，本轮运行治理键直接读取环境变量。发布升级请保留PostgreSQL原卷和旧凭据。
