# D02：全样例回归与版本比较

状态：开发收尾，2026-10-10。真实 PostgreSQL 迁移、并发、页面和发版验收尚未执行。接口契约 `0.20.0-d02`，后续阶段 D03：异常策略与恢复判断。

## 使用流程

1. 在工作台保存规则与正常/缺字段样例，配置明确预期。样例区提供“检查全部保存样例、比较版本与复制历史草稿”入口。
2. 在“检查与发布”中的回归面板，执行当前草稿全样例回归，或选择基准发布版本与目标草稿/发布版本进行比较。
3. 请求只创建后台任务；页面显示冻结时间、revision、样例数、进度和任务历史。响应未知时按原请求键恢复，查询失败停止自动轮询；可取消活动任务，删除终态报告释放容量。
4. 查看每个样例的期望判断、记录数量、无效字段、基准判断及记录差异，定位当前提取步骤/字段。报告中的样例 revision、内容/预期哈希固定，不依赖后续样例编辑或删除。
5. 当前草稿与当前发布版本的比较完成后，阅读并确认差异，再执行原有发布检查与发布。首次发布没有历史基准，继续使用原有检查流程。
6. 需要历史规则时，“复制基准版本为新草稿”；打开独立新草稿，重新保存样例、确认输出、实时试采和发布。原草稿不会被覆盖。

## 数据与执行边界

- `v22_regressions` 共用 regression/comparison 类型；迁移 `2026_10_10_010`。独立 `v22RegressionWorker` 每秒领取任务，不依赖浏览器服务。
- 入队事务由 owner advisory lock 控制容量。一次 PostgreSQL SELECT 同时读取草稿、两端版本、全部样例和所属 capture，保持同一语句快照，避免“草稿先锁、样例后锁”与现有样例/发布流程互锁。
- 冻结两份完整定义、全部输入及角色、样例 revision、预期和哈希；SQL 读取前做原文/预期总量检查，再检查编码快照总量。缺失、损坏、空内容或超限输入明确不完整，不换输入、不访问网站补取。
- 每个方案现有上限 100 样例全部纳入；编码快照最多 16 MiB、报告最多 4 MiB，每个 owner 最多 2 个活动任务、100 个保留任务。超过预算整体拒绝或任务明确失败，不用部分结果冒充全样例通过。每份差异最多 200 项，超出显示 truncated。
- 队列等待最长 5 分钟，执行最长 30 秒、租约 45 秒；进度和完成写回限定 status/lease/deadline。取消不被迟到 worker 覆盖；过期任务失败并记录 INTERRUPTED，不自动重放。API 存储操作最多 5 秒，前端 D02 请求 8 秒。
- 使用共用 `extract.v1`，支持 HTML list/detail 和 JSON list。任务 `succeeded` 只表示报告生成完成；目标期望判断单独为 passed/failed/unconfigured/incomplete。空样例批、无明确预期不能判定通过，输入/预期损坏或提取截断不能判定完整。
- 比较两端始终使用同批冻结输入及预期。定义按 JSON Pointer 比较，数值保持精度；缺失与 null 区分。记录按索引位置对齐，以稳定 field_key 比较转换值、错误和有效性，顺序变化也显示差异。不能据此声称正式数据新增/更新/删除。
- 差异与断言中的长值显示片段，完整值哈希独立保留；比较在裁剪前进行，不用片段判断相等。样例预期变化使用新预期分别判断两端，并不重用历史检查结果。
- 冻结原文不在 API 返回，列表省略报告正文；查询/取消/删除/复制均限定 owner。SQL 静默上下文避免原文与规则出现在 SQL 调试输出中。
- 离线回归不验证导航、登录、分页动作、详情访问或远程浏览器可用性，不写正式记录，不派发插件，不自动发布，也不解除质量问题。

## 发布和历史版本保护

已有发布版本时，PublishVersionInput 增加 `comparison_id` 与 `confirm_differences=true`。服务端要求：比较成功、目标为当前草稿、基准为当前发布版本、revision/规则 hash 匹配、定义差异未截断、样例批的 ID/revision/角色/内容及预期 hash 全部与当前发布清单匹配。样例增删改后需重新比较。目标样例是否可发布仍由原有全样例检查、实时试采、Schema、能力与过期证据检查决定，离线报告不替代它们。

发布版本新增 `difference_review JSONB`，独立保留比较 ID、两端 hash、输入批 hash、定义差异和确认人/时间。删除离线报告后仍可查看发布摘要；旧版本默认 `{}`，runtime_config 和旧正式运行不变。

`v22_version_restores` 持久记录历史版本到新草稿的关联，owner/version/collector/revision 检查与建草稿同事务。幂等查询先于 revision 检查，响应丢失可以找回原新草稿。每个 owner 最多 100 个复制关联；不自动清理关联或覆盖源草稿。复制仅复用历史定义并移除旧 output 确认，不复制样例、发布指针、运行或计划。容量与长期保留策略后续接 D05。

## 接口

| 接口 | 用途 |
| --- | --- |
| POST /collectors/{collector_id}/regressions | 当前草稿全样例回归，202 |
| POST /collectors/{collector_id}/version-comparisons | 同批输入的草稿/版本比较，202 |
| GET /collectors/{collector_id}/regressions | 全部保留回归/比较历史，最多 100 条 |
| GET /regressions/by-key | Idempotency-Key 恢复原任务 |
| GET /regressions/{job_id}、/version-comparisons/{job_id} | 共用任务进度/报告，kind 区分 |
| POST /regressions/{job_id}/cancel | 取消 queued/running |
| DELETE /regressions/{job_id} | 删除终态报告与输入；原 key 随后失效 |
| POST /collectors/{collector_id}/version-restores | 确认后复制历史定义为新草稿 |
| GET /version-restores/by-key | 恢复原复制结果 |

两类创建任务共用 owner 请求键空间，异 kind/输入复用同 key 返回冲突。历史复制使用独立请求键空间。任务与复制均有 fingerprint；明确删除任务后原 key 的保留保证终止。

## 发版验收

- [ ] 真实迁移与重启；旧版本默认 review、新版确认摘要、worker 注册可用。
- [ ] owner/collector/version/capture 授权；同 key 并发、异输入、容量与响应丢失恢复。
- [ ] 样例编辑/删除/创建与入队并发，只看到一次完整输入批；后续编辑不影响旧报告。
- [ ] worker 停机、租约过期、取消/完成竞争、排队超时、报告/快照预算；旧租约不可写回。
- [ ] HTML 列表/详情、JSON、正常/缺字段、无预期/无样例、输入缺失、规则缺步骤、截断；不产生网络动作或正式数据。
- [ ] 草稿对版本、版本对版本、精确大整数、长值与记录重排，规则/字段差异和不完整提示。
- [ ] 发布前比较绑定当前发布版本/草稿/样例批；样例变化必须重新比较；实时试采/Schema/能力检查仍阻止非法发布。
- [ ] 复制历史版本与 unknown 响应恢复，新草稿输出重新确认，原草稿/版本/调度/运行保持原样；手机/键盘/字段定位可用。
