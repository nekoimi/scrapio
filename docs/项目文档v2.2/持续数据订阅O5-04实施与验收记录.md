# 持续数据订阅 O5-04 实施与验收记录

> 2026-10-14：首版开发收尾，真实发版验收待 O5-R。任务执行仍是有限运行，持续的是订阅输入交付。没有启动浏览器、访问真实网站或执行全量构建。

## 1. 场景与范围

榜单任务正式保存电影表，独立详情任务订阅其中的 `detail_url` 和 `movie_id`；详情表变化再触发独立评论任务。每条订阅引用确定的任务版本、来源表 Schema 和输入映射，不改写采集器，也不把一次任务改成永远不结束的运行。

入口在编排任务的「日常运行」→「持续数据订阅」。选固定任务版本和来源表，逐字段映射，明确选择「回补当前记录 + 后续变化」或「仅创建后的变化」，设置每批数量并确认。可暂停、恢复、结束，查看积压、水位、阻断原因和最近20批运行。工作台容量区显示变更证据配额和阻断订阅数。

首版只订阅 `co_records` 经正式 `CommitBatch` 保存的新增及实际更新：事件保存的是最终生效的整条记录值，而非原始候选。未变化记录、失败/冲突候选、试采、仅传递输出不生成事件。删除、旧数据域、外部数据库 CDC、绕过平台的直接 SQL 修改不在范围内。历史数据不会伪造历史变更；需要已有记录时明确回补。

## 2. 事务事件与水位

- 每张表使用 `co_table_streams.sequence`。写页先按表ID顺序锁定对应计数行，再锁业务记录；事件、记录修订、观察、运行输出、outbox和检查点同事务提交。
- 计数行锁直到提交才释放。序号按同表事务提交次序分配，不使用自增序列或 `updated_at`：后提交的事件不能越过尚未提交的低序号。
- `co_record_changes` 保存表/序号、记录ID、revision、Schema版本、created/updated、有效值、观察ID及配额计数；记录/revision唯一。重复提交已保存页不会重发事件，事务失败连同计数回滚。
- 回补创建时取得同一计数锁，冻结当前记录与水位，再由后续批次继续消费水位之后的变化。两者没有间隙；同一记录后续更新有独立事件，不按当前表值覆盖旧事件。

只轮询变更表的持久游标，空闲时不扫描业务表。默认每秒检查一轮，最多20个订阅；按上次检查时间轮转。每轮每订阅最多生成一批，有正式活动运行就等待，保留未消费事件，不使用计划的 overlap skip 丢弃变化。

## 3. 交付、恢复和失败

`co_subscriptions`保存冻结配置、事件游标、回补快照/进度、revision和状态。`co_subscription_batches`保存来源范围、数量、运行ID和唯一批次键。创建运行、全部输入及来源快照、批次回执、触发记录和游标前进同事务；异常回滚，下一轮从原游标再试。运行创建返回不确定时，数据库已提交的批次不会重复生成。

交付游标表示输入已进入持久运行，**不表示采集成功**。失败/partial/limited/取消的已交付运行不会自动重新创建批次；从运行详情使用既有重试或局部补采，避免外部动作重放。活动运行暂停也会阻止后续订阅批次交付。

每条运行输入保留 subscription_id、事件序号或回补行、记录/revision、Schema、原始值及观察来源。回补和变更均使用冻结值，不在恢复时重新读取当前表。此次运行显式冻结输入批次；已发布版本的人工/快照来源保持原样，手动/API/计划触发仍使用其原来源。

来源Schema变化、缺序号、游标过期、字段映射失败、URL不在允许范围时：订阅改为blocked、禁用、保留游标和未消费证据，页面显示错误位置/原因。没有自动跳过坏行或读取当前整表替代缺失证据。全局活动运行配额暂满时等待；一个订阅暂时失败不阻止该轮其他订阅。

创建/控制使用原幂等键和操作结果查询；控制要求expected_revision。配置不原地换版本或映射：先结束旧订阅，再明确选择新配置与初始策略。暂停保护游标，恢复只允许ready且任务未归档；结束是终态，释放未交付回补及游标保护，已经生成的运行继续。归档任务会暂停订阅，历史证据保留。

## 4. 防环路

创建时按来源表→任务所有正式保存表构建订阅图，校验新增边不会形成自环或跨订阅环路。暂停/blocked的保留订阅也参与检查，防止恢复后出现环路。图编辑用事务advisory lock串行；任务版本及保存绑定固定。

例如电影表→详情表→评论表可用；评论任务回写电影表且电影订阅链继续消费时拒绝 `SUBSCRIPTION_CYCLE`。结束旧订阅后可显式创建新路径。首版不提供循环轮次或自动循环终止策略。

## 5. 容量与保留

- 每人最多20个未结束订阅，每任务最多一个；每批1..100条，并受任务工作项预算限制。
- 初始回补最多1000条/4MiB，超过上限拒绝，不截断。可先做有限快照任务，再使用仅未来模式。
- 入口输入仍受64KiB对象、数组100项、采集器Schema和允许域约束；同批输入集合受既有手动源512KiB预算，超出会阻断，需要降低batch_size后重建。
- 回补快照计入来源JSON配额，全部交付或结束后释放；运行已经拥有来源副本。变更事件独立计入 `SCRAPIO_CO_CHANGE_STORAGE_MIB`，默认128MiB，每条有效值加256字节估算元数据，范围4..4096MiB。
- `SCRAPIO_CO_CHANGE_RETENTION_DAYS`默认30，范围1..3650天。清理按同表连续前缀执行，每表每轮最多1000条、每轮最多20表；表按上次清理时间轮转。
- 只有超过保留期、且所有未结束订阅已交付的连续事件才能删除。暂停/blocked订阅会持续保护未消费事件，可能超过30天；可处理阻断、结束不需要的订阅或调整配额，不自动丢弃。
- 配额耗尽时正式页保存整体回滚，运行标记limited并报告`CHANGE_STORAGE_LIMIT`，不能以“保存成功但无订阅事件”降级。工作台展示使用量；JSON估算不包含索引、表文件及完整运行历史，部署仍需磁盘监控。

## 6. 接口与部署

| 接口 | 用途 |
| --- | --- |
| `GET /api/v4/tasks/{task_id}/subscriptions` | 当前及最近历史订阅、游标/积压/错误，最近20批运行 |
| `POST /api/v4/tasks/{task_id}/subscriptions` | 幂等创建，显式confirmed及初始模式 |
| `POST /api/v4/tasks/{task_id}/subscriptions/control` | pause/resume/retire，幂等键及revision CAS |

示例请求：

```json
{
  "task_version_id": "published-detail-task-version",
  "table_id": "movie-list-table",
  "schema_version": 1,
  "schema_hash": "confirmed-source-schema-hash",
  "mapping": {"url": "detail_url", "movie_id": "movie_id"},
  "initial_mode": "backfill",
  "batch_size": 20,
  "enabled": true,
  "confirmed": true
}
```

新增迁移`2026_10_14_003`；按现有迁移流程先完成DDL，再启用新版worker/API和前端。迁移只初始化现有表的事件水位为0，不扫描或改写历史记录。compose已补充变更配额/保留期配置；本轮不改变scrapio-browser协议或要求升级浏览器。OpenAPI由`co-o5-subscriptions.cjs`生成并纳入接口检查。
