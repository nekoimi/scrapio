# B04：全链路试采

开发收尾日期：2026-10-10。B04 把已保存方案编译为新的 `trial` 执行计划，复用 `extract.v1` 与 `internal/output`，不借用旧 workflow 充当新方案运行。真实数据库、浏览器及页面联调留待发版验证。

## 使用流程

1. 保存入口、动作、提取字段，在 B03 确认数据表和输出配置。
2. 在方案底部「全链路试采」选择离线或实时，设置时间、文档页、输出候选、详情预算。
3. 离线模式为每个提取步骤指定 list 快照，可使用当前快照或已保存样例的输入；输出角色为 detail 时必须提供 detail 输入。输入来自同 owner/方案的成功快照，不接受客户端候选记录。规则、输入内容/hash 和 Schema 在创建事务内冻结，后续修改草稿或样例不影响此次任务。
4. 实时模式填写 1～5 个完整页面 origin，明确确认会执行保存动作及 HTTP POST；浏览器使用全新会话，从入口开始，不复制编辑会话的登录状态。HTTP/JSON 使用 A07 的请求、凭据引用、超时、重定向与快照脱敏规则，不依赖浏览器。
5. 创建立即返回 202/试采 ID。后台执行并保存有序事件；界面通过 SSE 和状态轮询展示进度、具体步骤与角色、文档来源、逐字段原值/输出/错误和保存预判。
6. 失败步骤可定位到草稿定义，字段错误可返回字段配置；当前草稿 revision 不同则禁用旧证据的定位，避免把旧字段误指到新规则。
7. 取消请求幂等；排队任务立即取消，在途任务先标记 cancel_requested，再由执行器停止派生、关闭独立会话。创建响应丢失时按原请求键查询，不自动再执行。刷新页面可从最近历史恢复。

## 执行契约

| 范围 | 当前行为 |
| --- | --- |
| 支持步骤 | `navigate`、`action`（A04 支持的动作）、`record_set`、`json_records`；最多 50 步，未知步骤创建时明确拒绝 |
| HTML 实时 | 按序执行动作，取固定 HTML 文档，用共用解释器提取；详情入口必须唯一且能解析 href，直接导航详情后按 back/navigate-list 返回，并检查返回 URL |
| 翻页 | 使用保存的 link/click 定位器，最多检查两页；第二页仍有下一页时标记有限验证；连续翻页运行在 C01 扩展 |
| 页面角色 | 分开保存 list/detail 提取证据和父记录序号；输出仅使用 B03 明确绑定的步骤/角色，不隐式合并同名列表/详情字段 |
| 离线 | 仅消费冻结输入；动作被跳过，详情/翻页路径不执行，明确标记 limited；提供 detail 输入可验证详情字段，但不声称验证了真实访问及父子关联 |
| 输出 | 同一输出角色的全部文档候选累计做一次预判，同批跨页同键不同值仍冲突；共享 Schema、精确复合键、更新及空值策略；不写正式记录/观察/修订，不调用插件 |
| 状态 | queued/running/succeeded/partial/limited/failed/cancelled，停止原因与失败步骤/角色分开保存；部分字段无效或输出阻断不会标成完全成功 |

时间预算 5～120 秒；提取文档页 1～10（列表和详情均计入），输出角色累计候选 1～20，详情最多 0～5。每个记录计划自身的 max_records/max_details 仍生效。文档结果与内容总预算 8 MiB，输出预判 2 MiB，单文档沿用 1 MiB 快照限制。页面预算是提取文档数量，不是所有资源请求/动作访问的数量；动作步数、时间和有限两页路径共同约束试采。

预算截断、提取覆盖截断、离线跳过路径都标记 limited。没有候选、字段/映射/类型错误及同键冲突作为诊断返回；已有文档后路径失败保留 partial 证据。过早因预算或路径失败停止时可能尚无输出预判，不能把缺失预判解读为可保存。

实时来源检查在入口及显式导航前、动作结果和快照后执行；跨来源详情/下一页 href 不派生。浏览器 click 的目标和网站内部重定向只能在动作后检查，因此来源设置不是网络沙箱，不能保证网站没有加载其他来源的资源。取消也不能撤销已发生的 POST/点击/输入；RPC 取消后在途浏览器操作仍可能完成，独立会话关闭和三分钟 TTL 做收尾，后续动作不再派生。需要浏览器级网络拦截或登录配置时另行补协议，界面不能隐藏这些边界。

## 持久化与恢复

迁移 `2026_10_10_001` 新建 `v22_trials`、`v22_trial_documents`、`v22_trial_events`。全部使用新产品域，不导入旧采集数据。

- 创建事务按 owner/请求键串行化、检查 revision 和已确认输出兼容性，冻结定义、配置、输入内容和 Schema。定义 hash 使用 CanonicalJSON，避免 JSONB 重排/数字表达变化破坏冻结校验。
- 单实例后台 worker 从 PostgreSQL 原子领取 queued 任务（SKIP LOCKED），一次执行一个；每人最多三个排队/运行任务，最多 100 条历史。页面展示最近 20 次；终态可显式删除释放容量。
- 每次步骤状态和文档保存都会增加 event_seq。SSE 支持 `Last-Event-ID` 或 `after`，每批最多 50 事件、连接窗口 45 秒；重连从上次序号继续，事件流不可用时用状态/结果接口恢复。
- 每个新动作/快照/输出阶段前通过持久化进度检查取消状态；另有在途取消监控和总超时。结束时状态、摘要与终态事件同事务保存。
- 服务重启时 running 任务标记 SERVICE_RESTARTED，尝试关闭其独立会话；点击/输入/POST 不自动重放。queued 任务仍可领取，但排队超过十分钟不再执行，标记 QUEUE_EXPIRED。当前按单实例设计，不支持两个控制平面同时启动恢复。
- B05 已接入当前 revision、实时试采证据与全样例检查，不能仅依据 trial_id 存在或 limited 状态放行。被版本引用的试采拒绝独立删除，合法整方案删除允许延迟外键级联；真实事务待发版验证。

## 接口

| 接口 | 用途 |
| --- | --- |
| `POST /api/v3/collectors/{id}/trials` | 带请求键，冻结并排队，202 与 Location |
| `GET /api/v3/collectors/{id}/trials` | 最近 20 次 owner 隔离历史 |
| `GET /api/v3/trials/by-key` | 用 Idempotency-Key 恢复原创建请求 |
| `GET /api/v3/trials/{id}` | 状态、冻结 revision/hash、范围/预算、摘要 |
| `GET /api/v3/trials/{id}/results` | cursor 为文档事件序号，每页 1～10 文档 |
| `GET /api/v3/trials/{id}/events` | 有序 SSE，不携带浏览器画面或完整文档内容 |
| `POST /api/v3/trials/{id}/cancel` | 幂等取消请求 |
| `DELETE /api/v3/trials/{id}` | 仅未被发布版本引用的终态可删除，否则 409；不影响正式表 |
