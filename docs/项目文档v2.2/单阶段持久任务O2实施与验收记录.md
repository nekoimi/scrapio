# 单阶段持久任务 O2 实施与验收记录

日期：2026-10-13。对应 [分阶段实施 TODO](采集器独立化与任务编排分阶段实施TODO.md) 的 CO-O2-01～11、CO-O2-D；CO-O2-R 保留待发版验收。

O2 已接通“独立采集器发布版本 → 单阶段任务 → 冻结输入 → 持久工作项 → 逐页保存 → 数据与来源 → 失败输入补采”。旧采集器、任务、API 和数据保持原样，新页面只查询 `co_` 域。浏览器沿用 O1 的独立 context 协议，本阶段没有修改 scrapio-browser。

## 1. 使用入口与操作顺序

1. 在“独立采集器”完成规则检查并发布版本，点击“创建单阶段任务”；也可以直接进入“编排任务”新建。
2. 选择确定的采集器版本，输入网址列表或结构化 JSON 对象数组，检查每一行的错误。最多 100 行；相同网址的不同输入仍有独立来源标识。
3. 选择独立数据表或按输出 Schema 新建表。确认字段映射、唯一键、合并/替换和 null 策略，可使用与所选版本定义哈希一致的最近采集器测试结果预演保存决策。没有对应测试结果时，可先发布任务再隔离试采。
4. 确认工作项、输出、待处理队列、浏览器槽位及总时长预算，保存任务草稿并发布。发布校验输入和保存绑定；采集器的实时发布证据仍由 O1 保证。
5. 选择已发布任务版本进行隔离试采或正式执行。两者使用同一份冻结定义与 worker；试采保存隔离运行证据，不更新正式记录及记录修订。
6. 在“任务运行”查看准备进度、工作项、尝试、检查点、候选诊断、不可变输出和事件。暂停在当前安全页批次后生效；取消保留已提交数据。
7. 在“任务数据表”查看正式记录及最近 100 次观察/修订，沿来源返回运行与输入。原运行结束后，可仅对 `failed` 工作项创建原版本补采运行，保留 `retry_of` 与原工作项范围。

页面路径：

| 页面 | 路径 |
| --- | --- |
| 任务列表/新建/编辑 | `/app/co/tasks`、`/app/co/tasks/new`、`/app/co/tasks/:id` |
| 运行列表/详情 | `/app/co/runs`、`/app/co/runs/:id` |
| 数据与来源 | `/app/co/data` |

表单、按钮、确认弹窗和抽屉使用模板项目 Element Plus 组件；主内容区沿用现有布局滚动。列表只拉取摘要，运行轮询使用 `summary=1`，避免每次携带完整冻结输入/规则。事件按序号轮询恢复，页面最多展示最近 300 条，完整历史仍保存在数据库中。

## 2. 冻结对象与独立数据模型

迁移版本 `2026_10_13_002`，只新增 `co_` 表。O1 迁移先执行，worker 在数据库生命周期成功后启动。

| 对象 | 实现 |
| --- | --- |
| 任务草稿 | `co_tasks`：revision、`task.v1`；O2 仅一个入口阶段，`edges=[]`、`source.kind=manual` |
| 任务发布版本 | `co_task_versions`：不可变 manifest、版本号、草稿 revision、明确采集器版本引用 |
| 保存契约 | `co_data_tables`、`co_schema_versions`：逻辑表、字段、唯一键、Schema 版本与哈希 |
| 运行/阶段 | `co_runs`、`co_stage_runs`：formal/trial、控制代次、输入关闭条件、汇总和事件序号 |
| 根输入 | `co_run_inputs`：触发事务中保存完整输入快照、ordinal、稳定来源；物化进度可恢复 |
| 工作项/尝试 | `co_work_items`、`co_work_attempts`：输入哈希、租约令牌、检查点、退避、命令身份与回执查询记录 |
| 当前记录与历史 | `co_records`、`co_observations`、`co_record_revisions`：业务去重、每次观察、实际变化修订 |
| 运行输出 | `co_run_outputs`：本次原始输出值、输出身份、Schema、保存决策及来源；不读取合并后的表值替代输出 |
| 有序事件 | `co_run_events`：运行内严格递增序号；失败事务不会推进事件序号 |

物理列使用 `values_json`、`current_schema_version` 避开 PostgreSQL 关键字；对外结果值投影为 `values`。同运行的阶段/输入/工作项使用复合外键，业务唯一键锁按排序获取；索引覆盖领取、运行分页、候选诊断和记录来源查询。

## 3. 事务、恢复与控制约定

实现入口为 `internal/co/tasks.go`、`runs.go`、`save_batch.go`、`task_worker.go`，执行器新增 `collector.ExecuteDurable`。

- 触发幂等：owner、操作、资源和幂等键联合记录请求指纹。相同请求返回原结果，换参数报冲突；同任务、同 namespace 有活动运行时返回原活动运行。响应丢失保留原键，查询未命中不直接换键触发。
- 输入准备：先完整冻结最多 100 条手动输入，再按队列预算分批物化工作项。`preparing_cursor`、根输入、工作项和准备事件同事务推进；物化未完成仍可消费已准备输入。全部准备完成才关闭阶段输入。
- 领取/心跳：短事务按运行 → 阶段 → 工作项锁顺序处理，提交校验令牌、数据库租约期限及控制代次。旧 worker 无法继续保存。网络和浏览器访问在事务外执行。
- 页批次：当前记录、观察、必要修订、不可变输出、来源、检查点和事件一起提交；后续 O3 outbox 应加入这里，不另开一个结果之后的临时分发事务。
- 输出幂等：同工作项、同输出身份、同内容跳过；内容变化返回 `OUTPUT_CHANGED_ON_REPLAY`，原输出保持不变。`unchanged` 仍产生观察和有效输出，invalid/conflict 只保留诊断。
- URL/游标：在可重现且无需重放入口动作时从已提交下一页恢复，保留输入/定义哈希和已见页面摘要。点击/load_more 或需要入口动作时明确从工作项入口重采，已提交输出仍受身份保护。
- 自动重试：HTTP GET 的短暂连接故障有界退避，最多 3 个尝试；输入、规则、来源、Schema 和输出冲突不会自动反复访问。批次提交未确认先按检查点恢复；只读边界外的浏览器/POST 不据此自动重放。
- 浏览器中断：动作前持久记录 command_id，成功后记录 resolved；原回执查询不重新执行动作。租约过期仅在已提交、可重现 URL 检查点且无未决动作时自动恢复，其余进入 `awaiting_confirmation`。服务重启/回执消失仍视为未知。
- 人工确认：可查询原尝试/session 的回执，再明确停止该项，或确认从入口重采。重采提示会再次执行网页动作，保留旧输出身份保护。等待确认属于活动状态，不能自动报告完成或加入仅失败补采。
- 暂停/取消：暂停停止新领取/物化，已经授权的当前页允许在控制代次约束下保存后暂停；取消在运行锁内拒绝后续提交，保留原数据、命令记录及来源。总时长预算按触发后的实际经过时间计算，包含排队与暂停时间。
- 汇总：输入已关闭且无排队/运行/待确认项才按成功、失败、部分完成或预算受限汇总；已保存部分结果后失败不会被显示为全部成功。

全局池通过 `SCRAPIO_CO_HTTP_SLOTS`（默认 2）、`SCRAPIO_CO_BROWSER_SLOTS`（默认 1）配置，范围 1..8；任务自己的 `browser_slots` 再限制该运行。浏览器仍需要 O1 兼容的独立 context 能力。

## 4. 实际 API 与 O0 契约调整

全部挂载在受认证的 `/api/v4`，查询均验证 owner。准确请求/响应见 [OpenAPI](编排O0/openapi.json)，由 `co-o2.cjs` 和既有生成器维护。

| 能力 | 实际接口 |
| --- | --- |
| 任务/草稿/版本 | `GET/POST /tasks`、`GET /tasks/{id}`、`GET/PUT /tasks/{id}/draft`、`GET/POST /tasks/{id}/versions` |
| 输入/保存预演 | `POST /tasks/input-preview`、`POST /tasks/save-preview`；同步只读预演 |
| 运行触发 | `POST /tasks/{id}/runs`，明确 `task_version_id` 与 `namespace=formal/trial` |
| 运行/控制/补采 | `GET /runs`、`GET /runs/{id}`、`POST /runs/{id}/control`、`POST /runs/{id}/retry-failed` |
| 项/输出/诊断 | `GET /runs/{id}/work-items`、`/outputs`、`/observations`、`/work-items/{item}` |
| 事件 | `GET /runs/{id}/events?after=N`，每次最多 100 条，使用 `next_sequence` 续读 |
| 原命令/人工决策 | `GET /runs/{id}/work-items/{item}/attempts/{attempt}/commands/{command}`、`POST /runs/{id}/work-items/{item}/resolve` |
| 表/记录/来源 | `GET/POST /tables`、`GET /tables/{id}`、`GET /tables/{id}/records`、`GET /records/{id}` |
| 确定采集器版本 | `GET /collector-versions/{id}` |

控制请求要求 `expected_control_epoch`，避免过期页面控制新状态。所有状态变更 POST 使用幂等键；PUT 草稿使用 expected_revision。事件采用实际中间件下可恢复的有界 JSON 轮询，O0 草案中的 SSE、独立 trials/replays/publish-checks 路由未作为已实现接口保留。

O2 的试采使用已发布单阶段任务版本；O0 的草稿多阶段/离线试采契约仍是 O3 的设计输入。文件/数据表来源、阶段连接、连接过滤和下游持久派发尚未开放，不以旧 list/detail 实现替代。
