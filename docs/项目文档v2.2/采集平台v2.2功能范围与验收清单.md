# scrapio v2.2 功能范围与验收清单

> 依据：[v2.2 产品规划与需求](采集平台v2.2产品规划与需求.md)。本文先确定用户能完成什么，再约束页面设计；不以现有 API、表或组件作为功能上限。
>
> 状态：待真实目标验证的功能基线。P0 是首个可用版本的闭环；P1 是持续使用；P2 是可选扩展。旧采集器和旧数据留在原处，均不算 v2.2 验收样本。

## 1. 完整能力链

```text
输入目标 → 打开/操作页面 → 选记录 → 选字段 → 验证样例
       → 确认数据表 → 有界试采 → 发布 → 首次正式运行
       → 看数据/导出 → 定时更新 → 发现异常 → 修复并验证
```

每一段都有明确的**输入、可见反馈、失败出口和下一步**。不允许把“采集方案已保存”“预览能显示 HTML”当成完成一段链路。

## 2. P0：从 URL 到正式数据

| 能力组 | 必须支持的操作和反馈 | 暂不纳入首个闭环 |
| --- | --- | --- |
| 目标输入 | 单个 URL 起步；网页和 JSON 接口两种入口；区分在线获取与粘贴样例；地址校验、重定向及错误说明 | 站点目录、批量种子 URL、站点自动发现 |
| JSON 请求 | GET/POST、受限查询参数与 JSON 请求体；认证采用凭据引用；响应树选择数组和字段；请求预览隐藏秘密 | 任意协议、自动逆向网页全部接口 |
| 交互浏览器 | 页面画面可交互；浏览/点选/录制模式显式切换；前进后退、刷新、当前地址、加载状态；页面与 DOM/元素证据对应 | 多标签页协同、任意浏览器插件 |
| 元素点选 | 悬停高亮；选中当前元素及同类元素；扩大/缩小范围、撤销、手工选择器；给出命中数和样本值 | 只凭截图 AI 识别 DOM、全自动规则承诺 |
| 页面动作 | 点击、输入非秘密文本、等待元素、滚动；步骤可重排/删除/单步重放；动作前后状态和失败原因可见 | 任意鼠标轨迹、验证码自动处理、文件上传 |
| 记录发现 | 单页、一页重复项、列表到详情、JSON 数组；在列表点选详情链接；预览实际要访问的详情 URL；有界验证下一页入口 | 无限制递归、任意分支图；连续分页运行归 P1 |
| 字段提取 | 选文本、链接、图片地址、属性；字段命名、必填/多值、基础清洗和类型转换；跨至少两个样本项验证匹配 | 媒体下载、OCR、复杂跨页面关联 |
| 样例与诊断 | 保存页面、JSON、截图和动作结果；正常、字段缺失两类样例；显示规则位置、命中数、原值和输出值 | 大规模自动生成样例集 |
| 数据表确认 | 根据预览建议字段；用户确认名称、类型、唯一键、空值处理；显示首批候选的新增/更新/未变/无效 | 自动推断唯一键后无确认发布 |
| 有界试采 | 使用与正式执行相同规则，限制页面数和耗时；展示访问页、候选、字段失败、预计写入；明确不写正式数据和不投递外部动作 | 全站扫描 |
| 发布和运行 | 发布检查列出阻断项；不可变版本；首次正式运行后显示真实记录及来源；0 条有效结果不能显示“已完成” | 定时、API 触发归 P1 |
| 新旧隔离 | 新首页、方案、数据、运行和搜索都不混入旧数据；旧路由仍可独立访问 | 自动迁移或合并旧数据 |

字段定位必须支持**相对于重复记录容器**提取；列表到详情必须可复现“打开详情、返回或重新定位列表”的语义。方案基础管理需支持继续草稿、复制为草稿和归档；字段/步骤改动应使受影响的验证结果过期。P0 需能打开正式记录及来源，复杂筛选与导出按 P1 交付。

“数据表”是逻辑集合，动态字段经 Schema 版本校验后写共享记录存储；新增字段不应隐式改变旧记录或新建一张物理业务表。详见[动态数据表与记录模型](动态数据表与记录模型.md)。

P0 最低验收组合：**静态 HTML 单页、JSON 数组、需要浏览器点击或滚动的列表详情页**各一个真实目标。每个都要能从新建走到正式数据；浏览器目标必须通过交互点选完成规则配置。若某目标需登录，应额外验证受控凭据流程，不能把密码存进录制动作。

### 2.1 浏览器编辑器的前置能力

当前 `proto/fetch.proto` 的 `Execute` 是一次性请求，返回 HTML、截图和动作结果；它不能直接承载持续编辑会话。产品需要一个受控的交互会话协议，至少能：

1. 创建/恢复/关闭有生命周期与超时的页面会话；隔离不同用户或草稿。
2. 获取画面与页面状态，并把用户事件精确发给该会话。
3. 在指定页面状态下命中元素、返回 DOM 定位信息、匹配数、边界与样本值；支持高亮。
4. 执行单个动作并返回结果，维护页面状态；操作失败可重试或回到可解释的检查点。
5. 把录制步骤转成正式运行可执行的规则，并在发布前逐项重放验证。

具体画面传输、事件通道和会话持久化方式由阶段 0 技术验证选择。未通过真实浏览器验证前，不能把“静态截图上画高亮”算作可视化编辑完成。

## 3. P1：日常运行、数据使用与维护

| 能力组 | 用户操作 | 验收结果 |
| --- | --- | --- |
| 连续发现 | 选择下一页链接、按钮或加载更多；设置页数、重复/空页停止、详情数、域名范围 | 实际访问树与预算一致，重复 URL 不重复采；受限结束可见 |
| 种子与调度 | 单 URL 已发布方案可手动/定时/API 触发；后续增加受限多种子列表；可暂停、恢复和查看下次运行 | 重启后定时继续，触发来源与版本可追溯；暂停不会误删任务 |
| 数据工作区 | 搜索/筛选/排序、保存常用视图、记录详情、字段变化、来源证据、CSV/JSON 导出 | 查询与导出采用相同过滤条件；大结果集异步交付并有上限 |
| 运行中心 | 首屏显示访问、发现、有效、写入、失败及未覆盖；向下看页面、动作、字段、文档 | 部分成功、失败、取消和受限结束含具体影响与下一步 |
| 异常待办 | 连续失败、有效记录骤降、字段失配、浏览器不可用、调度停滞进入待办 | 可从待办进入受影响方案/运行；无基线时不编造异常 |
| 修复回归 | 从失败页面创建样例/草稿；改规则；多样例对比；发布新版本；验证下一次运行 | 旧运行不变，用户能判断修复前后记录差异和是否恢复 |
| 凭据与会话 | 为确需授权的目标引用凭据/浏览器会话；测试有效性；过期提醒 | 秘密不出现在规则、样例、日志、截图可读元数据及导出中 |
| 使用边界 | 请求间隔、并发、任务和页面预算、保留期、存储容量 | 超额原因明确；管理员可判断容量和浏览器健康 |

## 4. P2：复杂目标与集成

- **高级规则与脚本**：可视化规则生成后允许查看/编辑 CSS、XPath、JSONPath；JS 分为浏览器页面脚本和纯数据转换，各自限制权限、输入、输出与超时。高级修改不能被再次进入可视化界面静默覆盖。
- **AI 辅助**：建议点选范围、字段、失败原因；展示发送内容、模型、成本上限与候选样本；用户确认后才写入草稿，经过同一预览和发布检查。
- **外部动作**：对正式记录的新增/更新显式订阅，投递、重试、失败与采集运行分开看；云盘和 aria2 按需接入。
- **多来源合并**：新方案复用已有数据表时，预览字段映射、唯一键冲突和更新策略；保留多来源证据。

P2 不补救 P0 的页面点选失败，也不成为创建常见任务的必填步骤。

## 5. 跨阶段的关键状态与边界

| 情况 | 产品应做什么 |
| --- | --- |
| URL 可打开但页面元素不可定位 | 显示画面与 DOM 证据差异、具体原因，允许换取样方式或进入高级规则；不生成“已验证”规则 |
| 点选匹配 0 个或过多元素 | 高亮当前范围，显示匹配数与样本；阻止把必填字段当作通过 |
| 录制动作可能提交表单或触发外部事务 | 区分“选元素”和“执行动作”；有风险的实际动作明确确认，并记录结果 |
| 页面跳转、登录失效、浏览器断线 | 保留草稿和已完成步骤；显示会话状态与恢复入口；无效会话不得继续发布 |
| 列表无详情/下一页 | 展示终止原因和当前覆盖范围；预期应有数据却为 0 时不能标正常成功 |
| 试采与正式运行结果不同 | 对比输入快照、页面变化、版本、预算和写入决策；不能静默归因为站点问题 |
| 草稿未保存或发布失败 | 保留编辑上下文、错误位置和样例；重新进入可继续 |
| 数据表 Schema 变化 | 预览历史数据和其他方案受影响范围；只发布新版本，不暗改旧记录 |

## 6. 页面设计的输入条件

前端设计必须覆盖三条端到端任务：**首次建方案与入库、第二次打开看数据、从异常修复并确认恢复**。每个页面需同时定义空、加载、成功、无结果、部分成功、失败和能力不可用状态。设计必须标注按钮触发的后端行为、是否访问目标网站、是否正式写入、是否执行外部动作。

详见[前端管理界面 v2.2 重设计](前端管理界面v2.2重设计.md)。
