# 多上游联合输入 O5-03 实施与验收记录

日期：2026-10-14。本轮交付CO-O5-03a联合输入首版，只修改scrapio主平台。CO-O5-03b按键Join、批次屏障/聚合未实现；CO-O5-03父项及O5-R保持未勾选。

## 1. 场景与配置

两个榜单分支都输出电影地址，汇入一个详情阶段，再交给评论阶段。各来源到达即可执行，不需要等待另一个榜单的对应电影；每条连接独立生成完整详情输入。不能把来源A的电影ID与来源B的URL拼成一条记录。

任务编辑器操作：

1. 新建独立阶段并固定采集器版本，配置保存或仅传递结果。
2. 在共享下游的「阶段输入」选择「联合输入」，添加上游连接，逐条选择来源端口、过滤、展开与输入映射。
3. 每条来源分别载入样例并预览。切换连接清除旧预览；无效JSON阻止切换或添加，避免遗失待修正输入。重复的来源阶段/端口/目标连接会拒绝。
4. 在运行策略选择保留所有输入，或按规范化完整输入合并。合并范围仍为同运行、同阶段；不同版本/阶段不共享工作项。
5. 保存并发布任务版本后执行。运行详情逐条展示上游阶段、端口和状态，以及输入是否关闭。删除一个分支保留仍可从其他路径到达的共享下游。

## 2. 契约与完成条件

| 项目 | 本轮语义 |
| --- | --- |
| `stage.input_mode` 缺省或 `single` | 保留原单上游语义 |
| `stage.input_mode=union` | 多条来源独立映射，不做字段Join或批次聚合；只用于非入口 |
| 图限制 | 单入口无环，1～20阶段、最多60条连接、每个非入口1～5条输入连接 |
| 连接身份 | `(from, to, port)`唯一；同上游的不同命名端口可进入同一目标 |
| 映射契约 | 每条连接独立满足下游所有必填字段；缺失字段不能从另一来源补齐 |
| 输入关闭 | 全部上游阶段终止，且各自待派发计划已排空；不能因一个上游完成或队列暂空就关闭 |
| 正常空态 | 已确认空态且完成检查点提交的上游正常结束，不阻塞其他来源 |
| 失败/部分失败 | 已成功的其他来源可以继续，最终保留上游不完整状态，不宣称完整成功 |
| 预算受限 | 继续沿用全运行工作项、输出、派发、时长及队列预算；受限来源传递受限状态 |

状态结算改为稳定拓扑序，每个共享后代只处理一次，所有父状态先计算。多个父都成功才传播正常关闭；失败/部分失败优先传播不完整，仅有受限则传播受限。暂停或待确认不是终止态，不能关闭共享下游；未知动作仍按原回执机制处理。

晚到来源在运行仍活动且上游尚未结束时正常进入。开启重复输入合并后，即便同阶段的原工作项已完成，晚到的相同完整输入仍保留来源和合并回执，共享已有执行结果，不再次访问或派发。运行终止后不接受额外外部推送；这不是持续订阅或跨运行时间窗口。

## 3. 持久化、恢复与局部补采

复用运行输入快照、持久outbox、派发幂等、lineage、租约与检查点；本轮没有新增数据库迁移。输入模式随任务版本和运行Manifest冻结，活动运行不读取最新草稿。各来源独立写入既有派发计划，按全运行容量施加背压；阶段只有在父计划耗尽后才终止。恢复按既有持久计划和游标继续，不在内存中等待另一分支或保存Join缓存。

局部补采使用历史上游输出时新增可选 `edge_id`：仅一条输入连接时可缺省，多条时必须明确选择；严格校验历史输出属于所选上游阶段和端口，使用所选版本映射，不能代用最新业务表值。原工作项/表快照来源不接受 `edge_id`。

只执行所选阶段及其下游，所选阶段改为新的根输入；共享后代只接收保留路径的来源。`retry_scope`记录未执行阶段及 `not_executed_edge:<id>`，修复版本按实际目标版本计算排除范围。原运行和版本不改变，原试采补采继续保持试采隔离。局部成功不等于全图回归。

能力接口报告 `input_modes=[single,union]`、最多5条输入连接/60条总连接，并明确Join及批次聚合未支持。OpenAPI追加 `co-o5-union.cjs`；原单上游任务兼容，无需修改浏览器协议。
