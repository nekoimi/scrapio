# 独立采集器 O1 实施与验收记录

日期：2026-10-13。对应 [分阶段实施 TODO](采集器独立化与任务编排分阶段实施TODO.md) 的 CO-O1-01～09、CO-O1-D。

O1 开发接通输入驱动的独立采集器编辑、获取、当前页提取、有界分页、样例测试和发布。正式任务、保存绑定、调度与多阶段派发属于 O2～O4，尚未实现；CO-O0-R、CO-O1-R 的真实验收仍保留。旧模型、解释器、数据和调度继续原行为。

## 1. 入口与操作闭环

入口为 `/app/co/collectors`，主导航增加“独立采集器”。新建时只填写名称，在独立工作台完成：

1. 声明 `url`、`movie_id` 等输入字段及结构化样例，可直接从详情/评论地址开始。
2. 配置 HTTP HTML、HTTP JSON 或浏览器获取、允许来源及受控凭据；浏览器可配置入口后的动作。
3. 配置当前页记录容器及字段。点选组件接入 v4 会话，保留文本所在链接、多样本校准、逐条命中检查和手动 CSS/XPath；链接属于普通字段。
4. 声明可选分页、空态、预算、恢复方式和输出身份。输出只有 `records` 端口，不绑定正式表。
5. 保存后创建实时或离线异步测试，查询原操作，查看候选、逐字段命中/类型、页面及检查点。保存有限快照与预期，回归时比较当前规则输出。
6. 使用当前草稿的实时测试作发布检查，冻结为不可变版本。正式执行预留单阶段任务入口，由 O2 开放；不存在第二套“采集器正式运行”。

表单、按钮、确认弹窗使用 Element Plus 和现有工作台样式。工作台按输入、获取、当前页规则、分页/输出、测试、发布分区；链接无需声明详情角色，无固定详情路径或返回列表配置。路由/关闭页面保护未保存规则，冲突不会覆盖本地草稿。

JSONPath 首版只支持 `$`、`.key`、`[index]`、`[*]`，不支持脚本、过滤器或递归查询。多值 JSON 字段使用显式 `[*]` 定位，不隐式展开数组。HTTP 支持 GET/POST；浏览器入口不伪装 HTTP 请求体能力。

`identity_fields` 是候选输出的稳定身份，区别于正式数据表唯一键。输出 Schema hash 包含 port、fields、identity_fields，不包含提取定位器；仅规则变化不伪装成字段 Schema 变化。

## 3. 数据、事务与生命周期

新增迁移 `2026_10_13_001`（`internal/db/migrate/migrate_co_o1.go`）：

- `co_collectors`：用户所属、草稿 revision、定义及归档。
- `co_collector_versions`：不可变发布定义、三个 hash、解释器/发布版本、能力/来源/凭据引用、证据；collector+版本号/revision 唯一。
- `co_operations`：owner+operation+resource+Idempotency-Key 唯一，指纹拒绝同键异参；保存冻结测试/会话/命令、状态与结果。
- `co_samples`：冻结输入、有限快照、预期。
- `co_sessions`：独立编辑会话归属、冻结定义/输入、有效期；不保存授权明文或 DOM 引用。

数据库准备后通过独立 concrete bean 注册 `coCollectorWorker`。领取用短事务和 `FOR UPDATE SKIP LOCKED`；网页访问不放在写事务中。启动时将原 running 操作标为未知/失败，不自动重放，queued 可继续领取。排队超过 10 分钟拒绝执行。相同定义重复保存不提升 revision。

列表用创建时间/id 倒序和有界游标分页。归档不删除历史版本；被发布版本引用的测试不可删除。样例删除不会改变已经冻结进测试 payload 的输入/快照。

此阶段没有租约续跑、正式记录、工作项、outbox、task/run 或调度实体；这些仍按 O2/O3 独立实现，不通过当前测试 worker 代替。

## 4. 预算、证据与发布

定义最多 256KiB；输入/规范输出每条 64KiB；输入/输出各 1..30 字段；动作最多 50；输出身份 1..5 个必填非空单值标量。定义预算最多 100 页、10000 候选、600000ms。

采集器测试在定义预算内进一步限制为 **3 页、100 候选、60 秒**，候选证据最多 1MiB。每用户最多 3 个活动测试、10 个待处理操作；每采集器最多 100 条测试历史、20 个样例。快照最多 3 页、每页 256KiB；样例保存/导入及结果接口为有限证据，不是无限网页资产库。旧测试/样例有清理入口，发布引用不可清理。

仅缺少记录不报告零输出成功，需要显式空态标识。JSON 空态要求 marker 对应 true；HTML 要求明确标识元素。结束、invalid、partial、limited、unknown 分开，离线样例不执行动作，未覆盖页不能算完整成功。回归比较保存的规范候选值，差异不报告通过。

发布检查要求：定义有效、证据对应当前 revision/definition hash、实时获取、候选有效及能力/凭据仍可用。允许明确页/记录预算截断的有效实时证据，返回覆盖警告；不允许 unknown、字段无效、离线或缺页证据代替实时发布。检查有效期 10 分钟，发布再检查能力/凭据并在短事务内核对 revision/check/hash。

O0 的分页契约在 O1 细化 `cursor_parameter` 和 `empty_marker`；样例接口明确为从测试 evidence_id 保存，或显式导入 input/snapshots/expected_outputs，不假装已有未实现的 asset_ids 服务。OpenAPI 的 O1 接口标记 implemented，O2+ 仍 planned。聚合 Operation.result 为有界多态对象，另提供 TestResult、SampleView、SessionView、版本等具体投影。

## 5. 命令未知、凭据与浏览器组合

主平台先记录 command_id，再执行网页动作。确定的参数/定位器拒绝直接定位错误；网络结果未知查询原回执，不发第二次动作。编辑会话的未确认操作在数据库中阻断后续动作。测试未知动作保留原会话至有限 TTL，可通过 `/operations/{id}/receipt` 再查询。浏览器回执仍是内存数据：服务重启/会话过期后不能证明原动作未发生，需要人工核对。

前端保存未确认请求的 operation/resource/key，用原请求查询恢复；恢复不自动重发。实际终态 unknown 与“响应没收到”分别处理，清除本地等待不会解除后台未知命令阻断。

HTTP 凭据复用受控引用解析与来源/用户限制，支持 `${secret:name}` 和 `${credential:UUID}`；浏览器用后者的受控 Cookie 凭据。定义、样例及操作不接受认证字段明文，不持久化已解析密钥。已发布凭据引用在执行时再次检查；密钥本身不冻结进版本。

浏览器配套 commit：**`89c4a1b`**（scrapio-browser master）。新主平台连接旧浏览器时不会改成共享 tab；HTTP 功能仍可使用。协议 probe 证明服务支持隔离扩展，不证明目标网页或浏览器进程实际就绪。Cookie/storage/context 和站点行为由真实验收核对。
