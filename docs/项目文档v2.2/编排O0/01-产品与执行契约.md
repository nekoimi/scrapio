# O0 产品与执行契约

日期：2026-10-13。覆盖 CO-O0-01/03/04/08。主依据为[优化方案](../采集器独立化与任务编排优化设计方案.md)。JSON形状见 [OpenAPI](openapi.json) 与 [基线](fixtures/baseline.json)，本文定义 Schema 无法表达的行为约束。

## 1. 对象与首版边界

Collector 是可独立测试/发布的输入→输出能力；Task 是编排流程；Run 是一次试采或正式任务执行。Stage 使用固定 CollectorVersion，WorkItem 对应一个冻结输入，可访问多页、产出多条记录。RunOutput 是这次工作的规范结果，Record 是业务表当前状态。

旧采集方案同时承担提取、详情处理和调度，新模型将其拆开。列表/详情/短评只是采集器名称/业务用途，不存在必填 page_role、detail_fields、return_list 等发布字段。

首版一个入口，每个非入口一个上游，一个输出端口 `records`；允许分支与显式数组展开，拒绝回环、断连、多上游和任意脚本节点。采集器内部仅当前记录提取及有界分页；一个页面操作可导航到目标页，但不隐式为发现的每个链接启动子采集器。

初始产品上限：每任务 12 阶段、24 连接；采集器输入/输出各最多30字段；输入/输出每条规范JSON最大64KiB；定义256KiB；映射模板最大2048字符；单批最多100结果且总量1MiB。手动输入最多100条，O4物化最多10000条/32MiB/10秒事务，超过拒绝。分页、站点并发与存储预算可在限制内调低。默认浏览器执行2槽、单站点1槽；这些是首版保守默认值，O4实测后显式调整，不声称已做容量测量。

## 2. 字段与类型

字段键为 `[a-z][a-z0-9_]{0,63}`，显示名独立；已发布版本的键不可在原位更改。类型支持 string、url、integer、number、boolean、date、datetime、json，使用 `multiple` 声明数组。首版 integer 限于安全整数，number 为有限数；电影/评论ID用string，不转换大整数；金额精确值暂用string而非浮点。

必填表示字段必须出现，可空表示允许显式null。默认值仅用于缺失，不覆盖null、空串或空数组；默认值也按类型校验。必填单值string/url默认禁止空串，允许空需显式 empty_allowed。数组不默认展开，必填数组禁止空数组；元素不得隐含null。未知输入字段默认拒绝，不默默拼进请求。

date为ISO日期，datetime必须带时区；url为不含用户信息的绝对HTTP(S)地址。合法URL仍必须通过访问范围检查。json不得作为直接URL/模板变量、连接过滤的可比较标量或唯一键。

输出规范化按采集器字段契约运行，不因保存表有旧值而“补全”本次输出。输入透传必须在输出fields中声明 `source:input`；输出的提取字段缺失保持缺失，nullable的null和清空空串有不同保存含义。

## 3. 输入绑定与连接

Binding 有三种：`{kind:field,path:"input.url"}`、`{kind:constant,value:...}`、`{kind:template,value:"...{{input.movie_id}}..."}`。模板只做字符串插值，无代码/函数/条件执行；占位符只允许声明的标量字段。完整URL引用不编码整个地址，查询参数/JSON请求体由各自结构化绑定编码，不靠拼字符串转义请求。

执行获取绑定使用 `input.*`；阶段连接使用 `output.*`，数组展开时另有 `item`/`item.*`。祖先输入不自动继承，需上游显式透传为输出。连接无输入源时显示哪个目标字段缺失，映射失败属于运行错误，不计入“正常过滤”。

过滤支持 all/any 组合下的 nonempty、eq、neq、contains，最多十条；操作符校验字段类型。missing/null/空串/空数组使nonempty为false，比较缺失返回false。首版没有任意表达式。展开配置选一个已声明数组字段，无展开时整条结果映射一次；空数组记过滤0输入，有效数组按冻结顺序ordinal生成标识，重新消费同一输出沿用ordinal。

连接emit策略默认 `valid`，包括created/updated/unchanged；`created`或`changed`是用户显式选择（changed含created+updated）。无效和冲突候选不派发；计入诊断。仅变化不能当成评论定期刷新策略。

## 4. 获取与输出契约

三种获取方式：http_html、http_json、browser。请求可以使用输入字段，步骤首版支持navigate、click、input、wait、scroll及提取；需要外部副作用的动作要标识 replay_class=receipt_required。HTTP POST不默认认定只读，可只做明确批准的read-only请求；未知副作用先查回执/确认。

输出fields源自css/xpath/jsonpath、input或constant，指定extract(text/link/image/attribute)、属性名及已有清洗/校验。定位、输入映射与清洗分别报错。输出端口只有records，不绑定业务表，不要求唯一键；正式阶段保存映射才确认表唯一键。

分页模式none、url、cursor、click、load_more。记录/页数/时长预算不可缺；结束依据可为next_missing、empty_verified或明确标识。缺少选择器命中、登录页、验证码不能直接当空结果成功。恢复等级为url_or_cursor（重新打开核对）或restart_item（从头重采、已有输出幂等），禁止标成resume_dom。

业务写入的missing默认保留旧值，explicit_null按批准策略清空；本次运行输出仍保留missing，不从合并后的记录取值。新候选没有有效业务键计invalid。单批混合有效/无效可部分提交，数据库失败整批回滚。

## 5. 版本与发布

定义标识固定为collector.v1、task.v1，解释器co.interpreter.v1；发布契约co.publish.v1，冻结definition_hash与input/output_schema_hash。任务阶段保存collector_version_id、表/schema版本与哈希、映射、策略。旧解释器仍处理旧对象，拒绝将新定义交给旧提取器。

采集器发布检查：输入/步骤/输出合法、测试证据对应当前revision、能力可用、预算/访问范围明确；不要求表。任务发布检查：图结构、采集器确定版本、必填映射、输出绑定、能力及有界试采证据。检查结果check_id与revision/内容哈希绑定，草稿变化即过期。已发布任务引用不会自动升级采集器最新版。

试采namespace为trial，正式为formal，各自run/output/work_item/outbox不混用。试采允许持久有限证据并驱动下游试采，不写正式record或派发插件。离线只能验证样例覆盖的获取，实时和预算截断明确展示。

## 6. 工作项状态与转换

| 当前状态 | 可转入 | 条件 |
| --- | --- | --- |
| queued | running、cancelled | 领取有效租约；或运行取消 |
| running | succeeded、partial、limited、failed、retry_wait、awaiting_confirmation、queued、cancelled | 完成批次后结束；已知暂态只读错误退避；动作未知等待；暂停在安全检查点重入队列 |
| retry_wait | queued、cancelled | 到期/预算允许，或取消 |
| awaiting_confirmation | queued、succeeded、partial、failed、cancelled | 可靠回执与人工恢复方案，不能当“未执行”自动重放 |
| 任意终态 | 无 | 重试失败输入创建新的补采运行，不把旧终态改回running |

重新领取租约过期running前查询未确认动作；未知保持awaiting_confirmation。领取生成新令牌；attempt只增加执行尝试，不进入结果唯一键。提交时锁运行/阶段/工作项并校验令牌和有效期。succeeded/partial/limited/failed/skipped/cancelled为终态，awaiting_confirmation是活动项。

运行为queued→preparing→running→终态；preparing可失败/取消，暂停可在preparing/running发起。暂停过程中为pausing，物化/worker在安全边界停止后paused；resume还原preparing或running。阶段为waiting、running、pausing、paused及终态；waiting必须显示等待上游/物化/资源的具体原因。

取消为控制标记，UI可显示cancelling；不额外伪造completed。关闭派发/领取，已提交数据保留；动作未知在cancelled摘要保留pending_external_receipt，独立诊断仍可查原回执。取消不能证明外部动作未发生。

## 7. 阶段关闭与事件顺序案例

阶段同时具备sources_closed、incoming_pending_dispatch=0、active_items=0才可结束。root在物化完成后关闭输入；下游在上游全部终态、对应outbox已消费/取消后关闭。paused不关闭输入，awaiting_confirmation不当完成。

案例A：上游已提交结果→派发进程退出→下游队列为空。下游仍waiting/running，outbox重启后生成输入，不能先成功。

案例B：结果批次回滚→worker退出。输出/表/检查点/outbox均无新提交；恢复读取旧检查点，不派发不存在的结果。

案例C：派发和关闭并发。按run→拓扑stage→item→output/dispatch的锁顺序，关闭者先复核outbox；dispatcher在同一run锁下创建子item并消费outbox，不能关闭后追加。

案例D：cancel与dispatcher并发。同一run控制行串行：先消费则子item记录后续取消；先cancel则outbox标cancelled不建子item。取消不删除已有来源。

案例E：点击后断网。查询原command_id，不新建动作；无可用回执进入awaiting_confirmation；源未关闭，不让任务报告全部成功。

终态汇总固定：用户取消为cancelled；有错误且至少一项成功/部分输出为partial，否则failed；无错误有预算截断为limited；正常已结束为succeeded。过滤/增量跳过按策略为正常范围，零输出仅在结束依据已验证时成功。partial和limited仍保留独立错误/预算计数，不靠一个状态隐藏范围。

## 8. 页面契约与原型走查

新页面拟议路径 `/app/co/tasks`、`/app/co/collectors`、`/app/co/data`、`/app/co/runs`，避免覆盖旧/app路由。首页主动作新建任务，制作采集器辅助；一个采集器正式使用即创建单阶段任务。

采集器编辑样例输入、当前页记录/字段、可选分页、输出校验，不显示固定详情/返回列表。任务页阶段卡片只设置输入映射/表/版本与策略，提取规则跳采集器，不复制字段编辑器。

[原型](prototype.html)为本地单文件模拟，覆盖三阶段/单阶段切换、样例输入、映射错误、过滤、unknown receipt、保存冲突、试采与发布、部分失败与补采、数据来源；不调用v4或浏览器。使用蓝灰模板风格、main滚动、独立dialog窄宽度，正式实现使用web模板组件。mock数据及simulate动作始终可见。

真实用户走查仍待完成；本轮离线脚本只核对逻辑与基本DOM事件，不代表已视觉验收。
