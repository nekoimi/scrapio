## 本轮主要决策

1. 新 API 为 `/api/v4`，定义为 `collector.v1`、`task.v1`，新解释器为 `co.interpreter.v1`；与旧 `publish.v1`、v3/list-detail 解释器区分。
2. 新实体和业务数据均使用 `co_` 物理表域。新任务不自动引用/修改 v22 业务数据；字段规范化、去重等纯逻辑评估后复用。凭据存储可经所属用户校验桥接既有受控凭据服务。
3. 采集器只发布输入/执行/输出；正式表与 Schema 绑定属于任务阶段。非入口阶段单上游，可分支，不开放 Join。
4. 输出派发使用本次已持久化规范值；表的合并后当前值不补齐本次缺失字段。unchanged 默认可继续派发。
5. 每批次保存业务记录、观察/输出、检查点与 outbox 原子提交；未知动作不重新执行；输入关闭与 outbox 耗尽共同决定阶段结束。
6. O4 表输入使用一次有界 REPEATABLE READ 事务完整物化输入快照；不在跨事务分块时丢失快照一致性。超出预算拒绝并建议缩小范围，后续再做长快照优化。

## 完成状态

本轮完成设计产物与离线核对，不修改生产 Go/Python/Vue、路由、迁移或启动服务。新 API 和实体尚未实现；原型没有网络采集和数据库写入。

CO-O0-02 的基线整理使用明确标识的合成样例。此前用户已提供 Top250 地址并实测过列表/详情链路；这些属于用户报告，不能据此确认当前环境或评论页面行为。

CO-O0-R 继续待验收：没有可用远端浏览器/Manager 环境，遵循不运行耗时联调的偏好，本轮不访问豆瓣、不启动本机浏览器。短评入口、登录、稳定 ID、分页、凭据跨工作项复用及新 context 隔离尚待现场确认。原型可打开走查，视觉与真人交互验收未完成。
