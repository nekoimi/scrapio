# scrapio v2.2 前端管理界面重设计

> 依据：[产品规划](采集平台v2.2产品规划与需求.md)与[功能范围及验收](采集平台v2.2功能范围与验收清单.md)。状态：页面与交互方案，尚非已验证的视觉原型。
>
> 目标：自用/小团队的可视化采集工具，参照八爪鱼类工具“打开网页、点选数据、配置动作、试采运行”的任务方式。重新设计应用外壳与业务页面，旧界面和旧数据独立保留。

## 1. 重设计原则

1. **工作对象是网页和数据**：创建时主区域是可操作的目标页面；普通用户不必先填 Schema 或选择器。
2. **整个任务保留上下文**：页面、步骤、当前选择和数据预览同屏；试采失败回到具体步骤，不另开一串弹窗。
3. **日常使用有明确入口**：首页看更新与待办，方案页维护规则，数据页消费结果，运行页解释过程。
4. **新产品独立呈现**：不继承后台模板的菜单管理、部门、示例页、磁力、下载、STRM 和旧工作流导航。
5. **状态和操作可信**：实时页面/保存样例、试采/正式运行、草稿/已发布分别标明；不可用能力给出原因。

当前 `web/src/router/route.ts` 同时注册 workspace、旧磁力、下载、采集、运维和后台模板菜单；`workspace/layout.vue` 又提供一层工作区导航。新设计使用**一个独立应用外壳和唯一导航源**，由新路由直接进入新页面，不在旧 layout 中再次嵌套新侧栏。此结论来自路由/布局代码核对，不是已完成的线上视觉审查。

## 2. 信息架构

```text
scrapio
├─ 首页                 开始采集、最近数据、需要处理、最近运行
├─ 采集方案             方案列表、概览、编辑工作台、版本、样例、调度
├─ 数据                 数据表、记录、来源、变化、保存视图、导出
├─ 运行                 运行列表、运行详情、页面证据与失败修复
└─ 设置                 浏览器、凭据、容量、成员、操作记录
```

只有一套全局导航。一级页面使用轻量侧栏；采集编辑器切为宽屏工作台，只保留返回、方案名、草稿状态和主要动作，让目标页面占据足够空间。文件夹/标签作为列表筛选，项目不作为创建前置条件。

### 2.1 页面地图与建议路由

以下路径是新产品路由建议，不是现有后端 API 契约。

| 页面 | 建议路由 | 主要目的 | 优先级 |
| --- | --- | --- | --- |
| 首页 | `/app/home` | 开始新采集、继续草稿、看数据和异常 | P0，趋势/待办 P1 |
| 方案列表 | `/app/collectors` | 查找、继续配置、运行或暂停方案 | P0 |
| 新建 | `/app/collectors/new` | 选择网页/接口，输入 URL | P0 |
| 方案概览 | `/app/collectors/:id` | 版本、运行、目标数据表和健康 | P0，调度/健康 P1 |
| 可视化工作台 | `/app/collectors/:id/edit` | 页面点选、步骤编辑、字段与试采 | P0 |
| 样例/版本 | `/app/collectors/:id/samples`、`versions` | 样例验证、版本对比和修复 | P0 基础，完整回归 P1 |
| 调度 | `/app/collectors/:id/schedule` | 时区、执行计划、预算与启停 | P1 |
| 数据表列表 | `/app/data` | 找到已采集结果 | P0 |
| 数据表详情 | `/app/data/:id` | 记录浏览、筛选、变化与导出 | P0 浏览/来源，其他 P1 |
| 运行列表/详情 | `/app/runs`、`/app/runs/:id` | 查看结果、解释失败、恢复维护 | P0 首次运行，完整中心 P1 |
| 导出任务 | `/app/data/:id/exports` | 查看进度、下载当前筛选结果 | P1 |
| 设置 | `/app/settings/:section` | 服务、授权、容量和身份 | P0 浏览器健康，其他按依赖交付 |

记录详情、字段编辑、元素选择说明用上下文面板；可分享对象保留稳定 URL。列表离开再返回保留过滤、排序与滚动位置。

## 3. 首页和首次使用

### 3.1 新用户首页

页面标题“把网页变成你的数据”。一个明显的 URL 输入区与“开始采集”按钮；下方提供“网页”“JSON 接口”“导入样例”三种入口及适用说明。不预填自动运行的站点，不显示旧数据库数量。

输入 URL 即进入工作台，草稿在首次取样或首次编辑时建立。保存失败明确标为“仅本地未同步”，不得伪装成已持久化。可以退出并稍后继续。

### 3.2 有数据后的首页

首屏依次显示：需要处理的问题、最近使用的数据表和有效更新时间、最近方案及下次运行。所有数字可进入对应数据或运行。空待办表示“当前没有需要处理的问题”；没有基线写“尚未形成基线”。首页不展示无意义的任务总数墙。

## 4. 方案列表和概览

方案列表默认表格，可按名称、域名、状态、最近运行和标签筛选。每行展示名称、目标、输出表、发布版本、最近结果和下次运行；主要操作为“编辑”“运行”“看数据”，其他放入更多菜单。

方案概览上方给出下一步：未完成草稿→继续配置；已发布未运行→首次运行；正常→看数据；异常→查看影响与修复。下方局部导航为“概览 / 编辑 / 样例 / 版本 / 调度”。复制方案会生成独立草稿，不带入运行和正式数据。归档/删除要说明对定时、数据表和证据的影响，不能连带删除共享数据表。

## 5. 可视化采集工作台

### 5.1 布局

```text
返回方案  方案名称  草稿/同步状态                保存  试采  发布
┌────────────────┬─────────────────────────┬─────────────────┐
│ 采集步骤       │ 地址、加载状态、浏览模式 │ 当前选择/字段   │
│ 打开入口       │                         │ 命中与样本值    │
│ 页面操作       │   可交互的目标网页      │ 范围修正        │
│ 列表/详情      │   悬停与选中高亮        │ 类型/转换/校验  │
│ 翻页           │                         │ 操作确认        │
│ 提取字段       ├─────────────────────────┴─────────────────┤
│ 保存数据       │ 数据预览 / 步骤结果 / 错误                │
└────────────────┴───────────────────────────────────────────┘
```

这是信息布局示意，视觉原型另行制作。默认目标网页是最大区域，侧栏宽度可调整，底部数据表可收起。JSON 模式将网页区域替换为可选择的 JSON 树，并展示请求参数。

### 5.2 模式与点选

| 模式 | 点击网页的效果 | 页面反馈 |
| --- | --- | --- |
| 浏览网页 | 真实点击并导航，默认不保存动作 | 当前 URL、加载/连接状态；可显式“加入步骤” |
| 选择记录 | 选中容器或链接，不触发网页动作 | 当前元素、相似项、命中数、记录/详情链接候选 |
| 选择字段 | 选字段并生成规则，不触发网页动作 | 文本/属性/链接候选、样本值、字段名和命中高亮 |
| 录制操作 | 真实执行并记录可重放动作 | 动作名称、参数、前后页面、成功/错误、停止录制 |

模式标签固定可见，并支持快捷切换。选中元素后右侧展示“提取文本 / 提取链接 / 提取图片地址 / 选择同类 / 作为详情链接 / 作为下一页”。仅展示当前能力能执行的选项。每次产生修改可撤销；鼠标点选有等价的 DOM 树和规则输入入口。

不在普通点击时自动执行提交、发送等业务动作。需要的动作明确展示影响并确认；密码只引用受控凭据，不作为可见动作参数保存。

### 5.3 步骤与有限循环

左侧呈现有序步骤，支持选择、重排、删除、单步试行；校验明显无效的顺序。列表展示“每条记录”子步骤，列表到详情明确“发现详情 URL → 打开详情 → 提取字段”；翻页显示终止条件及循环范围。字段定位相对于记录容器，避免每个重复项都读到页面第一个标题。

详情可用 HTTP 打开或在浏览器导航；若浏览器进入详情后需要返回列表，编辑器显式显示回到列表的策略并试行验证。下一页链接、点击按钮和加载更多分别说明是否导航、是否复用页面、何时开始提取，不能统一成只有一个 URL 文本框。

### 5.4 字段与底部数据预览

字段表显示名称、样本值、类型、必填/多值与规则状态。选择一列就高亮来源；点击错误值进入对应字段。新字段可重命名、删除、排序；清洗/转换有处理前后对比。支持相对 URL 解析、空白处理、数字/日期转换的基础选项，具体执行边界以功能契约为准。

底部展示当前预览范围及记录数，不能把前 10 条样本写成完整结果。数据表字段由这些预览逐渐建立，到保存步骤才确认唯一键和更新规则。首次至少有一个可查来源；不要求预先定义磁力字段。

### 5.5 会话和编辑状态

工具栏区分：页面加载、连接中、浏览器不可用、会话过期、页面已变化、规则待验证。断线保留草稿、动作和样例；重新连接不能假定旧页面状态依然存在，应从检查点恢复或重放步骤。单步动作只作用于编辑会话，正式任务使用独立运行状态。

草稿自动保存显示“保存中 / 已保存 / 保存失败”；支持手动保存。关闭有未同步改动的页面要提醒。修改 URL、上游动作或记录容器后，下游验证显示“需重新验证”，旧预览可保留但显式标为过期。

## 6. 试采、样例与发布

### 6.1 有界试采

在工作台开启试采面板，设置页数、详情数、最长时间和实时/离线来源。展示实时执行步骤、页面访问路径、候选和预计保存动作；支持停止。失败后保留成功候选和错误证据，一键定位工作台中的失败步骤。

试采可能访问真实网站并执行明确选择的页面动作，但**不写正式记录、不投递记录插件事件**。离线试采只能验证保存输入上的规则，不能测试导航、登录或浏览器动作可用性。

### 6.2 样例和版本

样例面板展示来源页、角色、获取时间、预期结果和最近验证。浏览器动作在真实测试中验证；字段/发现/校验在保存快照上回归。版本对比使用同批样例显示记录数量与字段差异；历史版本恢复生成新草稿，不改写历史运行。

### 6.3 发布检查和首次完成页

发布面板按“页面与动作 / 字段与唯一键 / 样例 / 范围预算 / 输出目标”列出检查项。每个阻断项可定位；未交付能力不能出现在可发布配置中。确认后发布不可变版本，再提供“运行一次”。

首次正式完成页显示版本、实际访问、有效记录、写入决策和一条真实记录。主要动作“查看全部数据”，次要动作“设置定时”。无有效结果则显示未完成及原因，提供返回规则、查看失败证据的入口。

## 7. 数据与运行

### 7.1 数据表

列表显示数据表名称、记录量、最近有效更新时间和来源方案。详情首屏是业务数据表格，提供过滤、排序、列显隐、保存视图及导出。字段定义与质量放在局部页签，不遮挡数据。导出确认展示过滤条件、列、格式、预计数量和上限；后台任务显示进度、结果有效期和下载入口。

记录详情使用侧面板，展示字段值、前后变化、最近观察、来源 URL；点击来源进入对应运行页面证据。历史原文过期明确显示已清理，不能生成假的原文预览。

### 7.2 运行列表与详情

运行列表区分试采/正式运行，并展示方案、版本、触发来源、状态、记录结果和耗时。详情首屏回答“拿到什么、缺什么、为什么结束”，随后显示页面树、动作、字段、错误和证据。大树分页/按层加载，不把所有任务一次返回。

“重试失败页面”说明复用哪个版本、哪些输入、是否正式写入；规则有错误时推荐先修复，不自动用草稿重跑历史正式任务。服务端确认的取消/重试能力才开放按钮；P0 仅要求首次运行及结果浏览，完整控制随 P1 验收。

### 7.3 修复入口

从首页待办或失败页面点击“修复方案”，自动带入方案、失败步骤、历史输入和当前发布版本。已有草稿则让用户选择继续或另建，不覆盖。修复后回归、对比、发布、正式验证，问题只有在恢复条件满足后解除。

## 8. 设置与新旧隔离

设置仅围绕新产品：浏览器服务能力/连接测试、凭据与会话、运行容量、存储保留、成员与操作记录；JS/AI/集成按 P2 增加。后台模板的菜单/部门/演示功能不进入新导航。

建议新应用以 `/app` 为独立路由根，登录后默认进入新首页；旧 URL 继续由旧壳承接，或在实施时迁到独立地址。设置可提供一个“打开旧版”链接，进入后明确标识旧版；不用新窗口内的 iframe 把旧页面混入新产品。旧数据不自动导入，不影响新首页的空状态、统计或搜索。

新界面的菜单、页面状态、API 客户端和业务样式独立组织；可复用经过验证的基础组件和认证，不直接继承旧菜单配置。`web/` 可继续作为工程目录，不要求仅为隔离而建立第二个前端仓库。

## 9. 视觉与交互基准

- 中性浅灰/蓝灰画布、白色内容区、蓝色主要操作；绿色只表示通过/健康，橙色关注，红色失败。避免大面积绿色和后台模板主题选择器。
- 应用外壳保持简洁，不展示“Go 控制平面 / PostgreSQL”等实现信息。工作台强调网页、选中范围和结果，减少通用 KPI 卡片。
- DOM 悬停、选中、相似项和错误项使用不同线型/标签，同时有文字与匹配数；不只依赖颜色。
- 桌面优先在 1440×900 和 1280×800 核对工作台；窄屏可浏览数据/运行、修改简单配置。复杂页面点选在空间不足时提示使用桌面，不虚构与桌面等效的操作能力。
- 键盘焦点、清晰标签、DOM 树替代输入、减少动画、表格横向滚动和大文本折叠是基础要求。

这些是后续原型的约束，尚不冻结组件尺寸和视觉稿。新原型须完整表达工作台模式与反馈；v2.1 原型仅作历史参考。

## 10. 页面与需求覆盖

| 页面任务 | 功能需求 | 必须展示的异常 |
| --- | --- | --- |
| URL 到页面点选 | V22-01～06 | 获取失败、元素失配、动作失败、会话断开 |
| 输出、试采、发布 | V22-07～10 | 无效候选、预算截断、未保存、发布阻断 |
| 连续运行与数据使用 | V22-11～14、17 | 无下一页、零新增、凭据过期、部分成功、导出失败 |
| 修复及恢复确认 | V22-15～16 | 样例缺失、旧证据过期、版本冲突、恢复验证失败 |
| 扩展 | V22-18～21 | 脚本超时、AI 未确认、费用限制、插件失败、映射冲突 |

## 11. 原型与前端验收顺序

1. 先走通**新用户首页 → 网页点选 → 列表/详情 → 字段 → 试采 → 发布 → 首次数据**，同时验证浏览器交互协议可行。
2. 再走通**首页更新 → 数据过滤/变化/导出 → 运行结果解释**。
3. 最后走通**异常 → 失败证据 → 草稿修复 → 回归/对比 → 发布 → 恢复**。

每条任务都需空/加载/失败状态；原型使用示例数据必须明确标识。视觉检查覆盖桌面与窄屏，再用真实 API 和浏览器验证按钮行为。新旧导航、搜索、计数、样式及返回路径的隔离也是验收项。

本文只定义重设计方案，不在当前轮修改前端代码。后端/浏览器/前端的拟议接口和逐项对接任务见[接口落地与页面对接待办清单](采集平台v2.2接口落地与页面对接待办清单.md)；开始实现前仍须制作交互原型并验证真实目标。
