# AI 辅助建议与验证 O5-07 实施与验收记录

日期：2026-10-14。本轮完成 CO-O5-07 首版开发；真实模型、站点效果、成本与真人页面验收继续归 CO-O5-R。

## 交付范围

AI 为用户选择的具体问题提出候选，确定性执行仍由现有采集器解释器和任务映射器负责。旧工作流 AI 接口保持原有行为，新能力使用 `/api/v4/ai/*` 与 `co_ai_suggestions`，不自动调用模型、不修改已发布采集器/任务或活动运行。

| 页面 | 显式选择 | AI 能提供 | 采用影响 |
| --- | --- | --- | --- |
| 独立采集器 → 测试与样例 | 保存样例、输出端口 | 已有元素字段的 CSS/XPath/JSONPath、提取方式/属性 | 仅修改已有字段规则，草稿 revision +1 |
| 任务 → 上游连接 → 连接样例预览 | 当前连接、上游保存样例、端口内预期行序号 | 下游已声明标量输入的 input.X/output.X 绑定 | 整任务校验后更新该连接，草稿 revision +1 |
| 运行 → 工作项抽屉 | 带结构化错误的工作项 | 错误说明、人工排查建议 | 只读，不恢复或重跑工作项 |

映射样例必须与固定上游发布版本的 revision 一致。首版不编辑 Join/batch、数组展开、连接转换、过滤条件、常量或模板。定位建议不新增字段、不更改字段类型、稳定身份、转换、记录定位、获取/动作、访问来源或分页；采集器其他端口保持不变。

## 操作闭环

1. 保存草稿，明确选择样例/端口、连接或失败项，点击「准备发送预览」。此步骤不调用模型。
2. 检查将发送的脱敏正文/结构化信息、来源、模型、提示版本、大小及 hash；确认后才发送一次模型请求。
3. 候选通过严格 JSON 解码，再在本地完整冻结样例上运行现有解释器。展示定位/映射前后差异、实际命中、类型及身份错误、预期数据比较。模型只看到第一张有界页面；确定性验证使用保存的1～3张页面。
4. 用户核对样例，分别点击「确认验证结果」「接受候选」「采用到当前草稿」。采用事务重新校验模型/网关/提示版本、候选证据和原草稿 revision/hash，任务映射另重建完整 manifest；失败全部回滚。
5. 采用后重新实时测试、检查并发布。离线样例的有效命中不保证真实站点泛化准确率，也不能替代发布证据。

故障解释不提供采用/恢复按钮。未知响应和断线查询原建议或原 operation；页面保留原幂等键，不能用新键再次调用同一建议。未启动或未完成的调用不是已通过。

## 模型范围、脱敏与预算

复用已有 `ai_assist` 配置和 OpenAI-compatible Chat Completions 网关，`base_url` 填完整请求端点。HTTPS 为默认；HTTP 只接受 localhost/127.0.0.1。本轮无需浏览器协议更新，不新增 SDK 或模型依赖。

```yaml
ai_assist:
  enabled: false
  base_url: https://your-gateway.example/v1/chat/completions
  api_key: "" # 部署环境注入 AI_ASSIST_API_KEY，不在仓库保存密钥
  model: your-model
  max_requests_per_day: 10
```

模型接收的字段声明不包含默认值、凭据引用或转换样例。HTML 移除脚本、样式、表单、iframe、事件和敏感属性，链接移除查询/片段；JSON/输入输出按敏感字段递归脱敏。失败解释只发送错误码、位置及状态，不发送输入、网页、凭据或完整 manifest。脱敏属于明确规则，不声称识别所有自然语言中的私人内容；发送预览供用户最后核对。

每次提示最多24KiB、输出最多1000 tokens、网关响应64KiB、单次网络20秒。默认每账号每日10次，按数据库日历统计；失败、未知都计入。只报告模型 token 用量，网关未报告时显示未知；价格未配置，因此金额明确未知。新域额度不与旧工作流 AI 历史合并。

调用前以短事务持久化 `calling`、原 operation 和 called_at，再在事务外访问模型。响应丢失进入 `unknown`，60秒未回写的调用经查询标记未知；无自动网络重试、无重定向。已收到拒绝、无效JSON或超预算响应为失败，也不自动重发。配置变化使旧候选不可采用；提示版本固定 `co.ai.assist.v1`。

保存的原始冻结样例留在本地数据库，只投影脱敏提示和有限候选证据。占用已有输出JSON容量预算；结束/失败/已采用建议可以显式清理样例、提示、候选及重复准备证据，释放预留容量。保留 called_at/状态墓碑和原请求身份，因此清理不会重置每日调用次数，也不撤销已采用草稿。

## 接口、迁移与部署

新增迁移 `2026_10_14_005`；表 `co_ai_suggestions` 保存来源、草稿hash/revision、模型/网关指纹、状态、候选和验证hash。调用operation外键延迟到提交检查，保证一笔事务同时写入原调用身份。部署新Go版本时执行现有自动迁移，随后部署新web；无需同时更新 scrapio-browser。

| 接口（/api/v4 前缀） | 行为 |
| --- | --- |
| GET /ai-capabilities | 当前模型、开关与预算 |
| POST /ai/prepare | 持久准备与发送预览 |
| GET /ai/suggestions | 指定资源最近20条建议 |
| GET /ai/suggestions/{suggestion_id} | 查询原调用、状态和证据 |
| POST /ai/suggestions/{suggestion_id}/call | confirmed + 提示 evidence_hash，一次调用 |
| POST …/validate、…/accept、…/apply、…/reject | 分别确认验证、接受、采用、结束；采用需 expected_revision |
| DELETE /ai/suggestions/{suggestion_id} | confirmed，清理已结束的证据，保留额度墓碑 |

所有写操作要求 Idempotency-Key。相同键相同参数查询原结果，不重新调用；不同参数返回幂等冲突。读写均按 owner 隔离。OpenAPI 生成链新增 `编排O0/co-o5-ai.cjs`。
