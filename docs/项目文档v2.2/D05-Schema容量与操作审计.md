# D05：Schema、容量与操作审计

状态：开发收尾；实际 PostgreSQL 迁移、并发、页面和发版验收尚未执行。范围仅为 `/api/v3` 与 `v22_*` 数据，不读取、迁移或清理旧 magnets/resources。浏览器服务协议不变。

## 数据字段设置

入口为数据表的“字段设置与 Schema 历史”，路由 `/app/data/:id/fields`。修改显示名称、类型、可空、多值或新增/移除非唯一键字段后，先检查影响，再明确确认发布新 Schema。

Schema 影响预览保存用户、表、期望版本、拟发布字段、依赖摘要和十分钟有效期。展示字段前后变化、历史记录总数与版本分布，以及关联草稿、不可变版本、活动正式运行、调度、有效 API 触发凭据和保存视图。最多读取 201 个依赖，超过 200 个阻断；历史值最多离线抽查 100 条，明确显示抽样是否完整。不读取目标网页，不进行历史值转换或补填。

所有字段通过 B03 的 Schema 校验；历史值检查复用输出类型/必填规则。新增可空字段的历史缺失视为合法稀疏数据，新增必填字段或原值不符合新类型会列出记录标识和原因。历史不兼容是影响提示，原记录仍按旧版本合法保留，不能把抽样结果当成完整历史校验。

唯一键字段组合、顺序和类型/多值结构不允许在原表改变，否则既有 canonical key 可能关联到错误实体。这类修改需要新建数据表。字段标识是持久身份，重命名保留 field_key；删除字段不删除旧 JSON 值，重新使用同一标识会关联原值，应谨慎操作。最多 100 个 Schema 版本；未应用检查每表保留最近 20 份，已应用检查作为幂等提交凭据保留。

启用的关联调度和活动正式运行会阻断发布；先暂停调度、等待运行结束，再重新预览。确认在逻辑表行锁下重查 owner、有效期、期望版本及依赖摘要，记录变化也使原检查失效；插入不可变 `v22_data_table_schemas` 新行、推进当前表版本、标记原检查已应用并写入提交审计，属于同一事务。同一个 check_id 重复确认返回原 applied_version，不再次发布；其他变更后的确认返回 409。

旧 Schema、旧记录、观察、修订、版本和查询快照不在此次发布中改写。已发布旧版本继续保留；正式创建/写入及输出确认沿现有 Schema 版本/哈希校验拒绝旧绑定。关联方案需要重新确认输出、试采和发布。保存视图保持原查询，引用不存在字段时需修复查询，不能静默忽略筛选。后续正式采集对同一实体的正常更新依然按 B06 写入新观察/修订，属于新的业务写入。

## 容量与保留

设置路由 `/app/settings?tab=retention`，包括使用量、活动预留、可编辑规则、固定任务上限和清理预览。

| 内容 | 规则 |
| --- | --- |
| 编辑资产池 | capture 正文 + sample 截图 + 活动 capture 预留；默认 512 MiB，可配 16～4096 MiB |
| 无引用输入正文 | 默认保留 7 天，可配 1～365 天；到期后由显式清理释放，不自动清理样例输入 |
| 每次输入预留 | 1 MiB；在数据库 owner 资产锁内预留，成功/失败完成时置换，超时预留释放后的迟到结果重新检查容量 |
| 样例截图、修复输入副本 | 插入之前使用同一 owner 资产锁检查实际大小；不能通过这些入口绕过资产池上限 |
| 查询和导出 | 维持 C03 预算：单次 10000 条/16 MiB、查询默认 30 分钟、导出文件 24 小时、元数据 7 天；既有 worker 继续处理过期回收 |
| 长期数据 | 正式记录/页面证据、版本/试采/回归冻结证据和操作审计单独保留，不纳入编辑资产池、不在此次清理范围 |

规则按 owner/revision 保存。容量不能降至已用 + 当前预留以下，修改天数不立即释放资产。既有使用量超过默认上限时原资产保留，新增资产返回 `ASSET_CAPACITY`，需要调高上限或管理不需要的证据。编辑池是逻辑有效负载大小，不能当成 PostgreSQL 物理磁盘、索引/WAL 或整个系统总容量承诺。正式数据和长期证据增长需要另行规划磁盘与备份。

清理先生成明确资产列表、数量、预计释放字节、规则 revision 和十分钟期限；每批最多 200 项，保留最近 20 份未应用预览。仅包含：

- 超过保留天数的 succeeded/failed 输入正文，且无样例、输出检查、试采、正式观察或修复引用。
- 已过期且无导出引用的查询快照。
- 已过期且不处于 queued/running 的导出文件。

全部样例输入（包括未手动保护的样例）与截图保持保留，受保护证据不会因腾空间自动删掉。冻结的试采、版本与回归证据不在清理范围；试采输入通过新增 `v22_trial_capture_pins` 明确保护，迁移从 fixed_inputs 补齐已有引用，删除允许删除的终态试采才释放其 pin。输出检查与正式观察的引用也保持保护。凭据（含撤销记录）上限仍为 100，清理不会删除凭据或重用历史凭据身份。

确认在 owner 资产锁内重查规则、期限、每项状态/哈希/大小和引用。样例/输出检查/试采读取输入时持有 SHARE 锁；清理先取输入 UPDATE 锁，再用新语句重查引用。任何资产被并发引用、改变或既有 worker 提前回收，整批回滚并返回冲突，应重新预览。发布与清理都是显式确认操作。

输入正文释放后保留原行、request key、fingerprint 和原始 hash，变为 failed / `INPUT_EXPIRED`，不会把历史请求当成新请求再次访问网站。请求/身份元数据、已应用清理结果继续保留；实际磁盘释放取决于 PostgreSQL 的 VACUUM 等维护。确认同一个 check_id 返回原结果，不重复清理。未知响应页面保留原检查标识并重试同一次确认。

## 身份与操作记录

设置页提供凭据、容量、身份与成员、操作记录四个分类，不引入菜单、部门或大团队组织管理。身份页复用 `/me`，只显示当前账号与独立工作区边界；不列举其他账号，尚不支持共享工作区、邀请、成员修改或权限分配。

`GET /operations` 是 owner 隔离的游标列表，每页最多 50 条，展示操作者、模板动作、对象标识、时间、请求 ID、状态和允许的数字摘要。从本轮开始记录新产品变更，不补造历史审计。请求正文、URL、headers、用户标签、提取值和凭据秘密不进入该日志；非 UUID 的 caller request ID 只存 hash。

认证 `/api/v3` 的 POST/PUT/PATCH/DELETE 由中间件在调用业务处理前记录 `started`。审计不可写返回 503，业务尚未执行；读取和 SSE 不受此写入依赖影响。正常接口响应更新 `succeeded` 或 `rejected`，500 或进程中断分别为 `outcome_unknown` 或遗留 `started`，必须回到资源查询原请求，不能仅凭日志推断业务未提交。

Schema 发布、规则修改和清理另有与业务同事务的 `committed` 数字摘要。这明确区分请求成功和事务提交；其他既有业务不是自动变成全量事务审计。API-key 外部触发、后台调度/worker 沿已有 run trigger_source、版本、API-key/调度事件记录来源，本轮没有把全部后台事件写进设置操作日志。操作记录长期保留、无删除接口，长期归档策略仍需单独设计。

## 接口与迁移

| 方法 / 路径（`/api/v3`） | 用途 |
| --- | --- |
| GET /tables/{table_id}/schema-history | 不可变版本历史 |
| POST /tables/{table_id}/schema-checks | 期望 Schema 版本 + 拟修改字段的影响预览 |
| POST /tables/{table_id}/schema-checks/{check_id}/confirm | confirmed=true；同检查幂等发布 |
| GET /settings/retention | 当前规则、资产/预留使用量和固定限制 |
| PUT /settings/retention | revision 乐观锁保存 |
| POST /settings/cleanup-checks | 预览清理资产，不立即释放 |
| POST /settings/cleanup-checks/{check_id}/confirm | confirmed=true；同检查幂等清理 |
| GET /operations | 当前 owner 的操作记录游标页 |

OpenAPI 版本 `0.22.0-d05`；新增能力 `supports_schema_changes`、`supports_retention_settings`、`supports_operation_audit`。迁移 `2026_10_10_013`（`migrate_v2_2_21.go`）新增治理表和试采输入 pin；不改变现有记录值与旧业务表。治理 SQL 使用 4 秒 statement_timeout/API 5 秒/前端写请求 8 秒，保持有限等待。

## 发版验收

- [ ] PostgreSQL 首次/重复迁移、现存试采 pin 补齐、owner 隔离、表不存在及外键约束；旧 magnets/resources 保持原状态。
- [ ] 字段重命名/新增/移除/类型/多值/必填、唯一键拒绝、旧记录/观察/修订/版本/快照不变；新正常采集记录与来源可追溯。
- [ ] 历史类型抽样、可空缺失、超过 100 条提示；超过 200 依赖/100 Schema 版本、活动运行/启用调度阻断，暂停后重新预演成功。
- [ ] 预览与发布间草稿/记录/Schema/调度/视图变化、并发输出绑定/正式提交、未知响应同 check_id 核对；关联方案重绑、试采、发布后恢复执行。
- [ ] 多 capture/截图/修复并发争用预算、reservation 完成/失败/超时/迟到、默认上限低于已有用量、降低容量失败与规则 revision 冲突。
- [ ] 全部样例、保护样例、输出检查、试采 pin、版本、正式观察、修复和冻结回归证据均不被清理；引用创建与清理竞争不损坏输入。
- [ ] 200 项批次、十分钟期限、规则修改/worker 回收冲突整批回滚；同 check_id 幂等、INPUT_EXPIRED 正文清空但旧请求不重发网络。
- [ ] 容量计数、过期导出/查询预算、SQL timeout、数据库中断、审计不可写拒绝变更、进程中断的 started 与实际资源核对。
- [ ] 日志操作者/owner/模板动作/安全摘要准确，无秘密/正文/任意请求 ID；读接口/SSE 正常，API-key/调度来源与正式运行可追溯。
- [ ] 页面字段保留本地编辑、预览失效/未知确认重查、设置分类离开提醒、快速路由/刷新/错误/键盘和窄屏验收。

回退：停用新增治理入口与能力旗标，保留已经生成的 Schema/检查/pin/审计表及数据，不回写旧记录，不删除已发布版本。
