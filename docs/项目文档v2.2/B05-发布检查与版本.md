# B05：发布检查与版本

开发收尾日期：2026-10-10。B05 将已确认输出的草稿、样例和实时试采证据绑定为一次发布检查，再原子生成不可修改的发布版本。正式运行和记录写入在 B06 接入；本阶段没有执行真实数据库迁移或浏览器/UI 联调。

## 使用流程

1. 保存入口、动作和字段，在 B03 确认数据表、映射、唯一键和更新/空值策略。
2. 为每个提取步骤的 list 角色保存通过且包含有效记录的正常样例；配置详情提取时，detail 角色也需要正常样例。至少保存一个明确断言空值或预期错误的 `missing_field` 样例。
3. 使用当前已保存 revision 从入口完成实时试采。离线输入可以检查字段，但不能替代发布所需的实时路径证据。
4. 在「检查与发布」刷新试采历史，选择试采。查看范围、预算和覆盖限制；仅由已知有限覆盖造成的 limited 需要显式勾选接受。
5. 执行发布检查，查看阻断项并定位到步骤/字段。通过后在 15 分钟内填写版本说明并确认发布；规则、样例、Schema 或能力变化后必须重新检查。
6. 查看版本列表、发布摘要、冻结规则/Schema/运行配置和发布时样例证据。发布不增加草稿 revision，不阻止继续编辑，也不改写旧版本。
7. 请求响应丢失时使用原请求键查询。刷新/离开页面后本地等待键保存在 sessionStorage；查询结果未知时不会自动再发布。

## 发布门槛

| 项目 | 当前要求 |
| --- | --- |
| 草稿与输出 | 当前 revision、可编译的 `trial` 计划、入口一致，输出与 B03 确认绑定相同，Schema 版本/hash 及字段映射兼容 |
| 解释器与能力 | `publish.v1` / `extract.v1`；网页须具备 editor.v1 会话、动作、快照协议及已保存动作支持；JSON 检查 HTTP/凭据可用性，不要求浏览器 |
| 试采 | 同 owner/方案、当前 revision 和定义 hash，24 小时内完成，live 且已明确确认；取消、失败、partial、无输出预判或 0 候选均阻断 |
| 输出预判 | Schema 兼容、有候选、无 invalid/conflict，所有行的决策只能为 created/updated/unchanged；预判不锁定将来数据库中的记录值 |
| 样例 | 所有当前保存样例都用共用解释器重新提取及比较；未配置断言、差异、未预期字段错误、无效输入及截断不能通过；各提取角色具备正常样例，至少一个有明确断言的缺字段样例 |
| 检查有效性 | 绑定定义、Schema、输出确认、试采、样例集合/revision/内容与预期、当前协议能力 hash；15 分钟有效，发布事务内重读依赖并核对 |

limited 只有以下覆盖警告可明确接受：`EXTRACTION_TRUNCATED`、`DETAIL_BUDGET_REACHED`、`RECORD_BUDGET_REACHED`、`LIST_PAGE_LIMIT_REACHED`，停止原因须为 `BOUNDED_OR_OFFLINE_PATHS`。由截断导致输出预判不 ready 时，还须有兼容 Schema、有效行，且只有 `PREVIEW_INCOMPLETE` / `DATABASE_STATE_MAY_CHANGE` 警告。离线跳过动作、失败步骤/角色、未知警告、缺失输出、字段错误和同键冲突仍然阻断。

能力检查只做无副作用协议探测和凭据引用校验，不启动浏览器或访问目标站点，不保证发布后远程 Chromium/站点持续可用。网页协议探测总预算 4 秒；检查/发布存储事务预算另为 5 秒。正式运行还需 B06 再检查运行条件、确认范围和预算，不直接继承试采的 `confirmed` 授权。

## 存储与保留

迁移 `2026_10_10_002` 新建 `v22_publish_checks`、`v22_versions`，为方案增加可空 `published_version_id`。版本保存编号、定义/Schema/运行配置副本、解释器版本、能力与证据清单 hash、发布人/说明及检查/试采/输出证据引用。插入版本与更新方案当前发布指针在同一事务内完成；草稿的 status/revision 与发布指针独立。

- 检查与发布都要求 `Idempotency-Key`，按 owner/操作串行化；相同键不同输入拒绝，同一检查最多创建一个版本。原发布键重放返回原版本，不要求旧检查仍在有效期内；换键重用检查仍须通过有效期和依赖检查，版本说明不一致拒绝。
- 发布检查保留最近 20 条未发布候选及所有已发布引用；每方案最多 100 个版本。列表按版本号倒序分页，每页 1～50 条，不携带完整规则/证据。
- 发布时样例证据复制输入内容/来源、预期、提取结果及比较结果，累计最多 8 MiB；诊断最多 512 KiB。后续编辑或删除原样例、轮换 B02 检查历史不会改写版本证据；不复制样例截图或动作输入。
- 被版本引用的试采禁止独立删除；输出检查清理排除版本引用，发布检查清理排除版本引用。延迟外键允许合法整方案删除事务的级联完成，具体迁移与并发行为待发版验收。
- 全部使用 v22 新产品域和 owner 过滤，不导入旧 workflows/records，不派发插件，不写正式记录/观察/修订。

## 接口

所有路径前缀为 `/api/v3`，沿用现有认证与结构化响应。完整 Schema 见 [接口契约](阶段0接口契约草案.yaml)，版本 `0.11.0-b05`。

| 方法与路径 | 用途 |
| --- | --- |
| `POST /collectors/{id}/publish-checks` | 当前 revision + trial_id + accept_limited，返回检查与阻断项；检查不通过也保存证据 |
| `GET /collectors/{id}/publish-checks/by-key` | 按 Idempotency-Key 恢复原检查 |
| `GET /collectors/{id}/publish-checks/{check_id}` | 读取检查摘要、清单与能力快照 |
| `POST /collectors/{id}/versions` | 当前 revision + check_id + note，原子发布版本 |
| `GET /collectors/{id}/versions` | limit / cursor（版本号）分页 |
| `GET /versions/by-key` | 按 Idempotency-Key 恢复原发布 |
| `GET /versions/{version_id}` | 不可变规则/Schema/配置及摘要 |
| `GET /versions/{version_id}/evidence` | 发布检查与自包含样例证据副本 |

检查过期、依赖或请求键冲突为 `409 PUBLISH_STALE`；阻断为 `409 PUBLISH_BLOCKED`；revision 冲突沿用草稿最新版本响应；事务取消/超时为 `408 CHECK_TIMEOUT`，需查询原请求结果。不可访问的他人对象返回 404。
