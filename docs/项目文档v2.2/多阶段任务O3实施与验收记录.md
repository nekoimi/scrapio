# 多阶段任务 O3 实施与验收记录

日期：2026-10-13。对应 CO-O3-01～11、CO-O3-D。开发收尾与真实发版验收分开记录，CO-O3-R 保持未完成。

## 1. 本轮交付

| 范围 | 实际实现 |
| --- | --- |
| 多阶段契约 | `task.v1` 支持 1～20 阶段、一个手动入口、每个非入口恰好一个上游，可分支，不支持 Join/循环。同采集器可多次引用；阶段冻结具体版本与独立表绑定。 |
| 连接映射 | `field` 支持 `output.key`、`input.key`、数组展开后的 `element`；常量为 JSON 值；模板为 JSON 字符串，支持 `{{output.key}}`、`{{input.key}}`、`{{element}}`。不执行表达式或脚本。 |
| 过滤与展开 | 首版单条件 `exists/equal/not_equal`。`exists` 表示存在且非 null；比较字段缺失属于 invalid。只展开已声明输出数组，最多 100 元素；空数组产生零项。元素标识包含冻结序号与内容哈希，重复值仍保留各自来源。 |
| 保存与传递 | 阶段各绑一张表。`emit=valid` 默认传递 created/updated/unchanged；`created` 仅新增；`changed` 为新增及变化。invalid/conflict 仅留观察，不产生可消费输出。同表多阶段因未定义合并策略而阻断保存/发布。 |
| 持久分发 | 保存业务决策、不可变运行输出、映射快照展开计划及检查点在同一事务。分发器每轮最多处理 10 元素；创建下游输入、工作项、来源链与分发回执一并提交。唯一键为输出/连接/展开序号；恢复继续计划游标。 |
| 阶段关闭 | 分发与关闭均先锁运行，再锁阶段；按拓扑顺序计算状态。入口物化结束、工作项终态且 outgoing outbox 耗尽后，才关闭下游输入。等待上游、分发、背压、确认、受限和失败分别可见。 |
| 控制及隔离 | 单项失败默认继续，已提交输出仍可流转；共享凭据/服务故障或 `pause_stage` 阻断相关阶段，其他可执行分支可继续。运行暂停阻止新领取/分发；取消终止待分发计划并保留已提交数据。未知动作不自动重放。 |
| 基础容量 | 工作项、输出、待处理队列和 outbox 有预算。待分发元素默认最多 10000；单输出映射快照最多 512KiB。先派发已有计划，再物化新入口；为尚未物化的入口保留工作项预算。生产阶段有积压时暂停新领取。阶段按最近领取时间轮换，站点按活动项数优先，HTTP/浏览器分别使用有界执行池。 |
| 任务工作台 | 纵向阶段卡片及分支缩进、所选阶段配置、上游/版本选择、独立表绑定、连接字段映射、真实测试样例预览、过滤/展开与保存决策预演；编辑规则跳回独立采集器工作台。未保存修改与响应丢失的原操作查询沿用 O2 保护。 |
| 完整试采 | 使用已发布任务版本驱动全图，可实时或离线。试采最多 100 工作项、500 输出、每项 3 页/100 条/60 秒、总计 120 秒；原采集器更小预算仍生效。正式业务记录/修订写入 0，不调用外部交付插件。缺少离线页面或动作证据显示具体失败，不冒充完成。 |
| 诊断与来源 | 阶段输入、输出、工作项计数、保存决策、过滤、已派发/待派发及异常；分发回执页保留冻结下游输入。正式记录→观察→工作项→上游输出/映射→根输入，可最多回溯 20 阶段。 |

## 2. 数据库、接口与运行兼容

新增迁移 `2026_10_13_003`（`internal/db/migrate/migrate_co_o3.go`），建立 `co_dispatch_plans`、`co_dispatches`、`co_lineage` 与索引，补充阶段阻断/领取时间、工作项站点字段。复合外键约束运行与 namespace 归属。仅修改新 `co_` 域，不迁移或删除旧任务/业务数据。

O2 单阶段历史 manifest 继续可读；O3 使用 `stage_manifests` 按工作项阶段选取冻结执行定义。试采预算调整形成运行快照，不修改发布任务版本。HTTP/浏览器执行仍复用独立采集器与 O1 隔离协议，本轮不修改 scrapio-browser 仓库。

新增实际接口（均在 `/api/v4`、要求身份及 owner 关联校验）：

- `POST /tasks/mapping-preview`：确定上下游版本、连接、上游输入/输出样例，返回 ready/filtered/invalid、展开元素身份及映射哈希。
- `GET /runs/{run_id}/dispatches`：游标分页查询分发及映射诊断。

扩展原接口：任务创建/保存/发布接受多阶段图；运行触发支持 `trial: {mode, documents}`；运行详情附阶段统计；工作项详情附递归 `lineage`；任务摘要附阶段数。OpenAPI 生成器、合成基线、实际路由检查已同步。首版过滤收敛为单条件，替换 O0 提案中的 all/any 多条件形式。

离线 `documents` 按阶段 ID 提供 `{url, format, content}` 数组，每阶段最多 20 页，每页最多 512KiB，总样例最多 768KiB，整个 HTTP 请求最多 1MiB。离线执行使用 HTTP worker 槽位，不需要远端浏览器，但不能模拟未提供证据的网页动作。

## 3. 恢复和容量边界

页提交后产生背压时，只有无入口动作、非 POST、URL/游标可恢复的路径自动释放执行槽位并按已提交检查点续跑。点击式/不可重放路径进入 awaiting_confirmation，提示确认重采或停止。outbox 单页无法容纳或输出预算超额时，该页完整回滚并标为受限；此前保存的结果保留，需缩小页批次或显式调整新任务版本预算。

暂停不撤回已发生网页动作；取消后旧租约不能继续保存/派发。待分发计划不读取业务表最新值，业务记录更新不会改变下游输入。共享故障暂停后恢复解除阶段阻断，已终态失败项仍保留失败；中间阶段局部补采属于 O4，不伪装成完整重跑或把中间输入交给入口。多阶段 `retry-failed` 返回 `SCOPED_RETRY_REQUIRED`，单阶段原版本补采继续保留。

容量治理是单实例基础保护，首版串行运行控制锁优先保证正确性；不宣称严格站点速率控制、跨运行绝对公平或大规模吞吐已验证。站点/容量管理、历史输入源、调度、升级与局部补采继续属于 O4。

## 4. 短时验证

使用已安装依赖，无全量测试、前端完整构建、真实站点访问或服务启动。

```powershell
go test ./internal/co ./internal/collector ./internal/api/v4 ./internal/bootstrap ./internal/server ./internal/db/migrate -run '^TestCO|^TestControlWorkersHaveIndependentRegistryKeys$' -count=1 -timeout 10s
node scripts/verify-co-o1.cjs
node scripts/verify-co-o2.cjs
node docs/项目文档v2.2/编排O0/verify.cjs
```

定向检查涵盖图与映射校验、空数组/重复元素、模板范围、过滤与缺失区分、租约控制、实际路由与身份保护、9 个相关 SFC 编译及 co 脚本类型、29 个 O2/O3 路由方法契约、响应丢失幂等键、13 项离线文档/基线检查。

已运行开发 PostgreSQL 的可选临时 Schema 检查（测试体约 5 秒、硬超时 15 秒），仅创建并最终清理 `co_o2_test_*` Schema，使用合成页面与身份，不访问 public 应用表：

- O2 保存/租约/重试/Schema 冲突兼容；三阶段与复用采集器分支，独立四表，单项失败隔离。
- unchanged 仍传递、试采不写业务记录/修订、两跳来源链、owner 隔离。
- 保存后分发前保留 pending，不因队列空提前完成；重复执行分发不重复建项。
- outbox SQL 故障注入验证输出/计划/检查点一起回滚；修改业务当前值验证下游只读冻结输出。
- 暂停时不派发、恢复继续、取消时有 pending 仍不创建子项。
- 数组展开计划在容量 1 下分块派发；生产项背压释放槽位；新根输入不抢占待分发计划的容量。

这些检查不等于真实强杀恢复或并发压力验收。UI 样式已沿用模板组件并完成定向编译检查，实际浏览器显示和交互验收仍需发版确认。
