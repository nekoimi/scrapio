## 1. 实施方式与完成口径

- 按用户任务交付：每项待办同时有后端行为、浏览器依赖、前端入口和验收证据。API 返回成功或页面有按钮不足以勾选完成。
- 浏览器交互协议先验证，再冻结接口；原型使用 mock 时明确标记，不据此确认可视化采集可用。
- 后端维护 OpenAPI 和浏览器消息定义；前端从契约生成/校验类型，禁止直接绑定数据库模型或复制旧 workflow JSON 作为新编辑器模型。
- 阶段完成更新记录、执行必要验证并提交 commit；实际部署/浏览器/站点验证未完成时单独保留未勾选，不以代码测试替代。
- 不估算固定日期；完成阶段 0 后结合原型与真实浏览器验证拆分工期。

### 1.1 阶段顺序

```text
阶段 0：真实目标、原型、交互协议、契约
       ↓
阶段 A：新应用外壳 + 方案草稿 + 浏览器会话与点选
       ↓
阶段 B：提取/输出 + 样例 + 试采/发布 + 正式数据（P0 闭环）
       ↓
阶段 C：连续分页 + 调度 + 数据消费 + 完整运行中心（P1）
       ↓
阶段 D：异常诊断 + 修复回归 + 凭据/容量治理（P1）
       ↓
阶段 E：JS / AI / 集成 / 多来源合并（P2，逐项进入）
```

这套拆分是接口和页面的实施顺序；对应产品规划的 A 交付需本清单 A、B 都完成。产品规划的持续使用/维护分别对应本清单 C、D。需登录的首批目标必须将 D04 凭据支持提前，不能用手写密码动作暂代。

### 2.2 建议的通用响应约定

```json
{
  "data": {"id": "123", "revision": 4},
  "request_id": "req-..."
}
```

列表使用 `data.items`、`next_cursor` 和 `has_more`，稳定排序；需总数时明确 total 是精确值还是估算。业务 ID 对浏览器使用字符串避免 int64 精度问题；时间使用带时区的 RFC3339，调度另存 IANA 时区。

```json
{
  "error": {
    "code": "STALE_PAGE_STATE",
    "message": "页面已变化，请重新选择元素",
    "retryable": false,
    "stage": "inspect",
    "step_id": "step-2",
    "field_key": null,
    "path": "steps[1].locator"
  },
  "request_id": "req-..."
}
```

最少覆盖：未认证、无权限、对象不存在、草稿冲突、能力不可用、会话过期、页面状态过期、规则失配、动作失败、预算超限、候选无效、发布阻断。原始异常、密码、Cookies 和上游密钥不得透出。

## 3. 核心 API 与前端对接地图

## 4. 必须冻结的 DTO 与状态

| 契约 | 必须字段与语义 | 对接注意点 |
| --- | --- | --- |
| Collector/Draft | id、名称、入口类型、output_table_id（可空）、published_version_id、revision、definition_version、steps、验证依赖 | 未确认输出前允许保存草稿；step_id/field_key 稳定，用于错误定位和重排 |
| BrowserSession | session_id、collector_id、revision、状态、expires_at、page_state_id、viewport、能力与通道信息 | 生命周期与用户绑定；重连不等于页面恢复 |
| ElementInspection | page_state_id、element_id、定位候选、match_count、样本值、相对容器、bounds、支持操作 | 临时元素 ID 不是持久化选择器；页面变化拒绝过期引用 |
| ActionResult | command_id、类型、状态、前后 page_state_id、时长、错误、录制定义候选 | 浏览行为与草稿修改分开；敏感参数只有引用 |
| Preview/Trial | revision、输入哈希、scope、budget、network_accessed、dry_run、访问路径、字段诊断、候选、预判保存决策 | 旧 revision 响应不能覆盖当前预览；明确是否实时访问 |
| PublishedVersion | version_id、definition_version、Schema 版本、定义/样例/能力哈希、发布者及时间 | 已发布不可变；历史版本恢复生成草稿 |
| Run | version_id、trigger_type、状态、预算/覆盖、数量汇总、停止原因、页面链接、实际保存结果 | 状态由服务端定义；0 新增且都未变可以正常，不等于 0 有效 |
| Record/Observation | record_id、Schema 版本、values、唯一键、首次/最近观察、来源 URL、run/version/document 引用 | 原文不存在返回证据状态，不伪造来源内容 |

会话状态建议：`creating/ready/busy/disconnected/expired/closed/failed`；运行/试采统一基本生命周期 `queued/running/succeeded/partial/limited/failed/cancelled`，另设业务停止原因。草稿是否有效、方案是否归档、运行健康分别表示，不塞进一个含糊 status。

- 草稿新增 `http_request`、`json_records`。RFC 6901 Pointer 支持根数组、嵌套/转义键和相对字段；服务端保留大整数，返回未命中/匹配总数/截断，最多检查 20 条、30 字段。未知 request/plan 字段不静默忽略。基础 JSON 检查只读保存输入，不替代 B01 转换/必填/多值等共用解释器。
- 凭据使用 `${secret:name}` 引用，由配置指定环境变量、准确 origin、owner IDs 和认证头；只有运行时注入，不保存实际秘密。已知秘密键/精确凭据回显基础脱敏，HTML 移除脚本/样式和输入值；保留规范化快照与其哈希，不承诺任意敏感信息自动识别。D04 继续提供完整凭据管理。
- 页面接入 HTTP 请求编辑、离线 JSON/HTML、分层 JSON 树、数组/字段选择和固定快照检查；JSON 入口不创建/恢复浏览器会话。旧 revision 快照可检查新规则，结果过期明确提示。冲突保留本地修改，可明确重新加载；高级配置不被表单覆盖。传输/存储失败保存原请求键，恢复仅 GET 查询，不重发；结束本地等待需要明确确认且不撤销原请求。
- `dry_run` 仅说明不写正式业务记录，不表示 POST 无外部副作用；未知恢复结果的 network_accessed 为 null。快照不是 B02 样例，也未接入发布、调度或插件。
- 已通过 capture 纯单元检查（请求约束、Pointer 转义/缺失/精度、脱敏、离线无网络、POST 重定向/结果未知、大小预算、凭据 owner/origin 与私网阻止），Go 相关 API/repo/router 编译及三个 Vue 组件编译。没有全量测试、真实站点/浏览器/数据库联调，按用户要求留给发版。
- 操作及配置见 [A07 使用说明](A07-HTTP与JSON入口使用说明.md)；[OpenAPI](阶段0接口契约草案.yaml)已更新至 `0.6.0-a07`。
