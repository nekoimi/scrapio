# C03：查询、视图和导出

状态：开发收尾，2026-10-10。本轮只执行短时边界、契约、编译和相关 Vue/TypeScript 检查。真实 PostgreSQL 迁移、并发更新、重启、取消和页面验收留待发版。下一项为 C04 完整运行中心。

## 数据工作区

数据表页 `/app/data/:id` 增加 AND 筛选、排序、列显隐、保存视图和导出确认。应用条件后得到固定查询快照，页面显示匹配总数、捕获时间与有效期。条件写入 URL 的 `q`，回到同一地址可以重新查询该条件；URL 不永久保存快照或历史分页位置。记录行显示当时修订，详情/来源继续使用 B07 接口，详情读取当前修订，可能已与列表快照不同，历史修订可在详情中核对。

可增加最多 8 个条件，使用当前 Schema 的稳定 `field_key`，不按列显示名称拼 SQL。

| 字段 | 条件 | 说明 |
| --- | --- | --- |
| 标量文本 | eq/ne/contains/empty/not_empty | contains 区分大小写，按字面子串匹配，不解释 `%` 或正则 |
| integer/number | eq/ne/gt/gte/lt/lte/empty/not_empty | 按数值比较；输入及规范化响应用十进制字符串，保留大整数 |
| date/datetime | eq/ne/gt/gte/lt/lte/empty/not_empty | 使用已有字段转换规则规范化日期；比较规范日期/UTC 时间字符串 |
| boolean | eq/ne/empty/not_empty | 接受明确布尔值或符合转换规则的输入 |
| 多值/JSON | empty/not_empty | 当前不提供数组元素、嵌套 JSON 路径或复杂表达式查询 |

empty 包含缺失、JSON null、空字符串和空数组。普通比较不把缺失/null 当成“不等于”；要筛选缺失请使用 empty。排序支持标量业务字段及 `@first_observed_at/@last_observed_at/@revision` 三个元数据字段，数值按 numeric、文本按 `C` 排序，空值末尾；同值按 record_id 决定稳定顺序。`@` 前缀避免业务字段名与元数据名称碰撞。

列显隐和筛选/排序一起应用，至少保留一列；导出列按快照中的列顺序生成。未应用条件会提示，导出入口要求先应用。视图保存筛选、排序和列，不复制记录，每张数据表最多 30 个。新建使用客户端 UUID，更新/删除检查 revision，保存丢响应可用原 UUID/请求重试；更新冲突保留本地编辑，明确结束本地等待不撤销服务器操作。离开或刷新未同步页面会提醒。

## 查询一致性

`GET /api/v3/tables/{id}/records` 的 `query` 参数是 JSON 编码的 RecordQuery，最多 8 KiB；省略为默认查询。分页大小 1～50，默认 25。

第一页面使用 PostgreSQL SERIALIZABLE 的一致可见快照读取目标 Schema、匹配数量、值和排序，持久化为 `v22_data_snapshots`。serializable 并发冲突会使该查询失败，可重新查询；不会返回半个快照。`captured_at` 是捕获记录时间，不声称能按这个墙钟时刻重新构造数据库的全部提交状态。后续页面和导出直接使用固定记录，避免按时间截止重查时混入迟提交数据或可变修订。

返回新增 snapshot_id、captured_at、expires_at、total、规范化 query、Schema 和 schema_version。游标为 `q:<snapshotUUID>:<offset>`，与 owner、table、query 绑定，续页需提交相同条件/排序/列；其他 owner/表不能读取该快照。过期或被淘汰返回 410，改变条件复用旧游标返回 409。刷新/应用从第一页重新捕获当前数据。

每个快照最多 10000 条、序列化结果 16 MiB；超限明确拒绝，不把截取当完整结果。默认保留 30 分钟，每个 owner 最多 5 个没有排队导出引用的快照，新查询淘汰其中最旧快照，因此很早的分页链接可能在默认有效期内返回 410。正在导出会保留其快照直到任务结束，文件生成后与原快照独立。这个有界策略适用于当前自用/小团队单实例产品，超大数据检索和流式导出不在本轮范围内。

## 导出确认与任务

数据页显示确切匹配数量、列、规范化条件、捕获时间与格式，勾选确认后创建异步任务。`/app/data/:id/exports` 显示排队/生成/成功/失败/取消/过期、已处理行、总行数、文件大小、截止时间和冻结条件；可刷新、分页、取消或授权下载。新增任务可按链接定位；本轮采用显式刷新，没有伪造实时进度。

POST 必须携带页面已确认的 snapshot_id 和完全一致的规范化 query；只导出这份快照，不在排队后重新执行当前筛选。快照已过期或无法找到则返回 410，条件/列与快照不一致为 409，先重新应用条件再确认。即使后台采集修改值、增加记录或更新目标 Schema，任务仍使用确认时的固定值/顺序/列和 Schema。

| 接口 | 行为 |
| --- | --- |
| GET/POST `/api/v3/tables/{id}/views` | 视图列表与完整配置保存 |
| PATCH/DELETE `/api/v3/views/{id}` | 完整配置更新或带 expected_revision 的删除 |
| GET/POST `/api/v3/tables/{id}/exports` | 稳定历史分页与创建异步任务 |
| GET `/api/v3/exports/by-key` | 用 Idempotency-Key 查询原请求 |
| GET `/api/v3/exports/{id}` | 任务状态与冻结条件 |
| POST `/api/v3/exports/{id}/cancel` | 取消 queued/running；不删除正式记录 |
| GET `/api/v3/exports/{id}/download` | owner 授权、未过期、成功文件，长度/hash 校验后附件下载 |

所有接口沿用管理员认证，不开放给 C02 的触发凭据。所有读取/写入按 owner 与新逻辑表绑定，不查询旧磁力/资源/旧导出数据。每个 owner 最多 3 个活跃导出、20 个有效 queued/running/succeeded、200 条保留任务记录；每文件最多 10000 条/16 MiB。文件 24 小时到期，状态/请求键保留 7 天后清理，幂等保证以此保留窗口为界。

创建要求 1～128 字符 Idempotency-Key，同键同请求返回原任务，异请求返回 409。输入指纹包含表、快照、格式、确认与查询；未知结果前端保存原键，只查询原任务，不自动生成另一任务。成功响应 202 代表入队。结束本地等待不撤销任务，需要先检查任务列表。

独立 `exportworker` 每秒领取一个 queued，使用 30 秒 lease 和最多 15 秒渲染预算；进度在首行和每 100 行边界更新。取消或 lease 过期隔离旧执行器，旧回写不能产生可下载文件。清理/恢复每分钟执行，崩溃遗留 running 转 failed（EXECUTOR_INTERRUPTED），不自动重试；用户可重新确认快照并创建新任务。文件到期即拒绝下载，后台清理文件字节和快照引用，元数据保留到 7 天。

文件保存 PostgreSQL bytea，与状态成功同一次有条件更新，无额外存储服务或部署卷。query repo 关闭含大负载的 SQL 参数日志，避免把完整快照和文件输出到日志。迁移 `2026_10_10_007` 新增 `v22_data_snapshots/v22_data_views/v22_exports`，旧数据及任务不改写。

## 文件格式

- CSV：UTF-8 BOM，列名使用冻结 Schema 的显示名称；前置 `Scrapio.record_id/revision/schema_version` 三个元数据列，业务列名称规范不允许点号，避免重名。字符串以 `= + - @` 开头（含前置空白）或 TAB/CR 开头时加单引号，避免表格公式执行。真正的负数保持数值文本；多值/JSON 为序列化 JSON 单元格，null/缺失为空。
- JSON：数组，每条为 `{record_id, revision, schema_version, values}`；values 按稳定 field_key 保存选中业务字段，元数据不覆盖同名业务字段。使用 RawMessage 写入原始 JSON 数字，不把 int64 经过 float64；文件解析方仍需使用支持大整数的解析方式。未选业务字段不进入 values，缺失字段为 null。

确认页与任务元数据保存列和 Schema，可解释列名/类型。二者都不导出规则定义、HTTP 凭据、请求头或浏览器配置。
