## 页面与诊断

运行中心 `/app/runs` 增加方案 ID、状态、来源筛选及全部保留历史状态统计。来源“重试”由 `retry_of` 判断，不把重跑混进普通手动筛选；底层触发仍是 manual。统计以 owner/方案为范围，不依赖当前列表页，也不随状态/来源条件变化。列表最多 50 条，默认 25；游标锚点需仍满足筛选，锚点状态改变导致无法续页时重新读取第一页。

运行详情展示原发布版本、输入预算、结束原因、失败步骤/阶段、实际提交结果和来源。页面证据按 attempt / 步骤 / 列表轮次分组，详情页面关联同 run/attempt/step/list_page 的真实父列表文档；分页未载入父文档时仍提供父页面链接。不把不存在的失败文档、旧截图或编辑会话画面补进页面树。

选择页面后，在旁侧检查面板读取保存的逐字段命中、定位、原始 JSON、转换 JSON、无效记录和截断警告；可切换全部/无效记录。原始文档沿用 B07 的 UTF-8 分段与 hash 检查，以转义文本展示。面板不重新访问网站、不执行文档脚本、不修改记录。更早的页面证据和运行级 attempts 都提供真实游标分页，页面 attempts 仍明确 scope=run，不冒充页面独立尝试。

诊断事件从最新向前独立分页，包含无文档的入口、步骤、动作及终态。新的共用 Runner 对每个真实动作持久记录操作编号和类型，开始之后记录成功、失败或已知结果未知回执；不记录命令输入值。记录开始事件后再次检查取消，避免在该边界取消后继续派发。派发后的网络失败、取消或服务中断可能无法留下终结回执，只有开始事件不等于网站动作未发生。旧运行不会补造动作日志；原 B06 lease/cancel fencing 继续阻止旧 attempt 保存证据及正式数据。

| 计数 | 口径 |
| --- | --- |
| 已保存文档 | 该运行已持久化的所有文档数 |
| 已提取 / 有效 / 无效 | 所有已保存列表和详情文档中的提取记录，包含中间结果和重复项 |
| 输出候选 | 输出步骤去重后的候选，沿用执行摘要；与文档提取计数不同 |
| 本次写入 | 原子提交的新增、更新、未变总数；未变也生成本次来源观察 |
| 未覆盖 | 网站总量未知，显示“未知”，不把失败数或预算差值当成未覆盖总数 |

limited 表示时间、文档、候选、详情或分页上限造成的有限覆盖，保留实际停止原因；是否写入仍由 committed/counts 决定。partial 表示路径或输出检查未完整通过，有中间证据但本批不提交。失败定位、输出映射检查、检查点及事件共同解释缺失，不用一个“失败”标签代替证据。

## 取消与完整重跑

服务端 `controls` 返回当前状态允许的取消、重试及范围；页面按该结果开放入口。can_retry 表示当前状态允许请求，创建事务及 worker 仍校验版本、Schema、归档、容量与实时能力。运行中不开放重跑，取消被接受后不重复开放取消；queued 取消立即终止，running 等待原 worker 收尾，响应未知先刷新状态。

取消确认说明停止后续执行及本批写入，无法撤销已发生的网站动作。取消与最终提交在运行行锁下竞争：若提交先完成，取消返回已完成状态；若取消先被接受，旧 lease 不能再派生/写入。详情页及版本页运行面板都加入确认。

`POST /runs/{id}/retries` 仅接受 `{scope:"full_run",confirmed:true}` 和 Idempotency-Key：

1. 原运行必须已终止。读取该 owner 的原始输入，固定原 version_id、来源和预算，不允许通过重试请求扩大预算、改变域名或使用当前草稿。
2. 校验原冻结规则/hash、输出 Schema、发布契约、解释器与不可变发布版本一致；新建事务再次核对目标 Schema/归档/容量及能力。能力不兼容时明确拒绝，不偷偷改用新版或改表。
3. 新建独立运行和浏览器会话，从原入口重新执行完整路径。重新访问当前网站，可能重复输入、点击、导航和 HTTP POST；确认页明确展示这些行为及正式写入。
4. 成功后按原输出映射/策略写正式记录和新的来源观察，不修改原运行、旧文档或旧 attempt。按原唯一键合并记录，重跑不代表“不会产生网站副作用”。
5. `retry_of/retry_scope` 保存来源。同 owner 的 key 与原运行、scope、原输入绑定，重复请求返回同一运行，换原运行复用 key 为冲突。已知请求优先返回原结果，即使后续能力/Schema 变化也不重新创建。未知响应保留 key，用 `/runs/by-key` 查询；前端会话存储保留本地等待，离开会提示，结束本地等待不取消服务器运行。

当前没有“仅重试失败页面”或“从检查点续跑”。这两项需要定义可独立重放的输入、授权状态、分页/详情上下文与正式写入范围，后续单独落地；页面不展示这种按钮。D01 修复原失败输入仍是下一阶段产品能力，不能用当前草稿隐式代替历史正式任务规则。

## 接口与迁移

| 接口（省略 /api/v3） | 行为 |
| --- | --- |
| GET `/runs` | 新增 status/source 筛选，保留 owner/collector/cursor/limit |
| GET `/runs/statistics` | owner/可选 collector_id 的完整保留历史状态统计 |
| GET `/runs/{id}` | 新增 retry_of、retry_scope、controls |
| POST `/runs/{id}/cancel` | 复用 B06 fencing 和幂等取消语义 |
| POST `/runs/{id}/retries` | 显式 full_run 确认，202 新建/恢复原重试运行 |
| GET `/runs/{id}/pages` | 新增 parent_page_id，真实页面关系及分页 |
| GET `/runs/{id}/attempts`、GET `/pages/{id}/attempts` | 默认 25、上限 50，next_cursor/has_more；运行级尝试 |
| GET `/runs/{id}/diagnostics` | 持久事件从最新向前的 sequence 游标分页 |
| GET `/runs/{id}/coverage` | 从该 owner/run 的已保存文档聚合提取计数 |

迁移 `2026_10_10_008` 为 `v22_runs` 增加可空 retry_of 自引用和 retry_scope 成对约束、来源索引。旧新域运行默认无 retry 来源；不读取或迁移旧磁力/旧任务数据。新诊断沿用现有 JSONB 事件，没有新增执行队列或独立页面 worker。

修正前端 API 中重复 `checkpoints` 方法：正式运行改用 runCheckpoints，编辑器保留 checkpoints，避免后者覆盖前者；同时删除重复 table 读取定义。类型检查包含相关调用组件。
