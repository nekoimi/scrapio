# B06：正式执行与持久化

开发收尾日期：2026-10-10。正式运行以 B05 的 `version_id` 为固定输入，使用新的 v22 任务、文档和事件域，共用 `extract.v1`、`internal/output` 及试采的浏览器/HTTP 获取适配器。当前是单实例、有界运行；真实 PostgreSQL 事务、浏览器和页面验收留待发版，不将短检查等同于端到端验收。

## 使用流程

1. 在「检查与发布」发布或查看历史版本，打开版本摘要中的正式运行面板。
2. 确认使用的版本、页面来源和预算。默认值来自发布时试采配置，但试采的 confirmed 不会作为正式运行授权，调整配置后需重新确认。
3. 创建后返回 202 和 run_id，后台持久领取。界面展示固定版本、attempt、步骤/角色、状态、停止原因、文档诊断和有序事件；SSE 失败后仍可轮询/手动刷新。
4. 执行完整路径后，在事务中重新判断共享表记录的 created/updated/unchanged，原子提交本批记录、观察、修订及最终状态。界面展示已提交与否、三类计数、记录 ID/修订、来源及最终数据 JSON。
5. 失败路径、无效候选、同键不同值冲突或 0 有效候选不提交本批。所有候选与诊断文档仍保留；全部未变可以成功，仍保存本次观察。
6. 响应丢失时按 sessionStorage 中的原请求键查询，不自动再触发；刷新版本摘要后可从该方案的运行历史继续查看。取消是幂等请求，停止后续派生及正式写入，不撤销已经发生的网站动作。

## 任务、租约与恢复

迁移 `2026_10_10_003` 新建 `v22_runs`、`v22_run_attempts`、`v22_run_documents`、`v22_run_events`，为已有新域 observation 补 run/version 及 document/run 组合外键。

- 创建带 `Idempotency-Key` 和输入指纹，owner/操作键事务串行化；同键同输入返回原运行，不同输入 409。触发来源由服务器固定为 manual，不接受客户端伪造来源。
- 每 owner 最多三个活动运行、1000 条历史，版本与记录来源不可独立删除；达到容量明确拒绝，后续 D05 补保留治理。列表每页 1～50 条，按时间/ID 稳定倒序；列表省略规则、完整输出及写入明细，详情返回完整摘要。
- 单正式 worker 通过 `FOR UPDATE SKIP LOCKED` 领取 queued，增加 attempt，分配唯一 lease_token。租约 45 秒，执行中每十秒续租；取消检查约一秒，数据库操作有单独超时。
- 文档、事件、会话日志、续租和最终写入都核对运行状态/attempt token。数据库 `clock_timestamp()` 判断租约；取消或 token/租约失效的在途 worker 无法保存后续文档或记录。
- 浏览器会话 ID 在创建外部会话前保存到 run 和 attempt；结束/取消/异常关闭会话，独立浏览器 TTL 三分钟兜底。
- 服务重启不马上覆盖仍有效租约。过期 running 按持久状态结束为失败或取消，保留 attempt/文档并关闭日志中的会话，明确 `LEASE_EXPIRED_OPERATIONS_NOT_REPLAYED`；不重新排队或重放点击/POST。queued 保留，排队超过十分钟明确 QUEUE_EXPIRED。
- 用户取消与提交在 run 行锁上串行化：取消先获锁则后续事务零写入；提交先获锁并成功则取消返回原终态，不能声称已撤销提交。

## 正式写入事务

1. 锁 run，核对 token、未过期租约和取消状态。已终态的同 attempt 再次完成直接返回，不重复写入；过期 worker 不具备写权限。
2. 锁逻辑表，核对 owner/Schema/hash；读取本 attempt 的持久文档，检查内容 hash，并选择输出步骤/角色的候选。共享表锁同时保护尚不存在的唯一键，避免并发新增竞态。
3. 在锁内重新读取当前记录，用共用 Prepare/PreviewBatch/Merge 判断类型、唯一键、更新和空值策略。试采和执行阶段预判都不作为最终数据库状态依据。
4. 逐来源保存 observation：原始映射候选、来源 URL/角色、文档/本地记录序号、version/run、稳定 write_key。最终合并值写 record；新增/更新才写 revision，unchanged 不产生伪修订。`keep_existing` / `preserve_existing` 仍保留真实 incoming 观察。
5. 记录、所有 observation/revision、run/attempt 终态和终态事件在同事务提交；提交前再次核对租约。整批异常回滚，不部分提交记录。
6. 提交响应未知时读取持久终态；完成操作具有终态幂等性，重试 Finish 不重写观察。数据库恢复仍失败时租约过期收尾；运行状态是提交结果的依据。

成功有限覆盖也保留 limited，不把已执行部分说成全站完成。失败/partial 的输出只作为诊断预判；`summary.committed`、`counts` 和 `writes` 才代表本批正式写入。大整数在 JSONB 读取中使用 UseNumber，页面使用 values_json/字段 raw_json 和 value_json 精确显示。

## 接口

前缀 `/api/v3`，认证/错误和成功 envelope 沿用 v3；契约版本 `run.v1`，OpenAPI `0.12.0-b06`。

| 接口 | 用途 |
| --- | --- |
| `POST /collectors/{id}/runs` | 带请求键，version_id、confirmed、allowed_origins 和 budget；202 + Location |
| `GET /runs?collector_id=...&limit=...&cursor=...` | 当前 owner 新域运行分页，cursor 是上一页末 run_id |
| `GET /runs/by-key` | 按 Idempotency-Key 恢复原请求 |
| `GET /runs/{id}` | 状态、固定版本、attempt/进度、输入及提交结果 |
| `GET /runs/{id}/results` | 按文档事件序号分页，每页 1～10；内容/字段诊断与出处，不返回完整原文资产 |
| `GET /runs/{id}/events` | 有序 SSE，Last-Event-ID/after、每批 50、连接窗口 45 秒，终态后关闭 |
| `POST /runs/{id}/cancel` | 幂等取消，queued 立即终态；running 停止派生与写入 |

对象 owner 隔离，不可访问对象返回 404；版本/Schema/幂等键冲突 `409 RUN_CONFLICT`，无效配置/不可用能力 400，创建/存储超时 `408 RUN_TIMEOUT`，客户端查询原请求。`supports_version_runs=true` / `run_available=true` 仅表示协议实现接入，实际能力仍在创建/执行时校验。
