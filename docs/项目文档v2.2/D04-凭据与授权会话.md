状态：开发收尾，2026-10-10；真实迁移、并发、浏览器网络与页面验收待发版。接口契约 `0.22.0-d04`，迁移 `2026_10_10_012`。下一阶段 D05：Schema/容量/审计。

## 使用流程

设置页 `/app/settings` 管理当前用户的新域凭据。新增时选择 HTTP 认证头或浏览器 Cookie、准确 origin、有效期和保存方式；秘密只在首次保存或替换时输入，不回显、不进页面缓存。列表显示名称、用途、范围、revision、到期和撤销状态；已有版本保留 `${credential:uuid}` 引用，不复制秘密。

HTTP 请求面板可选择同 origin 的可用认证头凭据，并保存到 `http_request.credential_ref`；旧 `${secret:name}` 部署引用继续可用。浏览器工作台增加授权面板，选择 Cookie 凭据并保存 `browser_auth.credential_ref`，关闭旧会话后重新打开。授权由当前已保存草稿取得，试采和正式运行分别读取其冻结定义的引用；不会从最近编辑会话继承 Cookie。

“检查作用域与运行环境”检查用户、准确 origin、类型、有效期、秘密运行时可读性和浏览器新协议。返回 `website_authorization=unverified`、`network_accessed=false`；浏览器协议探测会访问内部浏览器服务，但不访问采集目标。是否真正登录需明确打开页面/HTTP 取样或实时试采核对。网页跳回登录页不被可用性检查冒充“已登录”。

此轮授权方式是导入 Cookie 请求头，支持普通 HTTPS 站点会话；不支持密码动作录制、验证码处理、跨 origin SSO、localStorage token 或自动登录续期。Cookie 到期后更新凭据并重新打开会话/实时验证；不把密码存成工作流动作字符串。

## 保存、范围与部署

- 独立 `v22_credentials`，owner 限定所有读写和引用解析；每用户最多100行，列表包含撤销墓碑。HTTP 认证头限定 Authorization、Cookie、X-API-Key、API-Key、X-Auth-Token；固定前缀与秘密分开。浏览器 Cookie 只允许 HTTPS，host-only、路径 `/`、Secure/HttpOnly；不导入任意 domain/path 属性。
- 加密保存使用 AES-256-GCM 随机 nonce，以 owner/id/kind/origin 绑定 AAD。密钥只从 `SCRAPIO_CREDENTIAL_KEY` 环境读取：32字节随机值的标准 Base64，不能复用默认 JWT key；未配置时只禁用加密保存，公共采集与环境引用继续可用。更新不能在保留旧秘密的同时更换 kind/origin。
- 环境引用仅允许部署明确提供的 `SCRAPIO_SECRET_<NAME>`，不允许引用 DB_PASSWORD/JWT_SECRET 等任意环境键。数据库保存环境名称而非实际值；环境的外部值变化无法由数据库 revision 自动识别，运维轮换后应保存凭据元数据、重新实时试采。
- 秘密最多8KiB、Cookie最多40项、有效期最多366天、遮挡选择器最多10个。客户端 UUID 幂等创建、expected_revision 更新；请求指纹含秘密时使用 HMAC，不保存裸秘密哈希。查询只返回元数据，SQL 会话禁用参数日志。撤销清除当前行密文但保留引用墓碑；备份与旧证据不作追溯擦除。
- 凭据更新/撤销与旧编辑会话过期同事务。工作台、截图保存、SSE 刷新和试采/运行的动作/快照边界重新检查凭据版本；已发出的网络请求无法撤回，浏览器旧上下文由关闭/TTL清理。不会承诺撤销能中断已经派发的请求或立即停止所有页面后台请求。
- 发布检查记录凭据 revision/updated_at，凭据变更后旧检查 hash 失效；变更前创建的实时试采不能用于发布，需重新试采。已发布版本仅保留引用，正式执行再次检查当前秘密可用性，轮换秘密无需把明文写入新版本。

部署示例：`docker-compose.example.yaml` 已传入 `SCRAPIO_CREDENTIAL_KEY`；环境引用需要逐项在 scrapio 容器 environment 中传入。生成密钥可使用 `openssl rand -base64 32`，值存部署环境并单独备份，不提交到 YAML/仓库。数据库恢复必须配合原加密密钥；此轮不提供批量密钥重加密功能，错误密钥会拒绝解密。

## 浏览器协议与隐私

两个仓库的 `EditorSessionCreateRequest` 追加 `authorization_json`，只有临时 RPC 请求携带 Cookie/遮挡策略/到期时间。授权创建使用 `editor.auth.v1`；新 `GetEditorSession` 探测返回 `AUTHORIZATION_SUPPORTED`。旧服务拒绝新协议，Go 不得忽略授权改为公共会话。

scrapio-browser 在注入之前创建独立 browser context；不支持新上下文时失败，不退回共享 profile。Fetch 请求阶段拦截所有导航、重定向和子资源，只有未过期且准确 origin 相同的请求能继续，其余阻断。跨站资源被阻止可能影响页面外观或站点功能，跨站授权须另行扩展，不以放开 Cookie 范围解决。

浏览器授权截图由像素遮挡完成，不修改页面 DOM/state token：输入框、文本域、iframe 和所选 CSS 范围被遮挡。HTML 固定快照在惰性副本上遮挡 CSS 内容和属性；已知 Cookie 值对检查结果/URL/错误做精确替换。HTTP Cookie 回显按独立 Cookie 值脱敏，其他认证头按注入秘密精确替换。

这些策略不是任意个人信息或编码秘密识别。保存样例前仍须人工核对，B02 手动截图遮挡保留；已有快照/样例/版本不追溯修改。遮挡结果就是实际离线提取/回归输入，不假称保留未脱敏原文。gRPC 沿现有内部服务连接，部署应处于受信任私有网络；本轮未增加传输 TLS。

## 接口

| 接口 | 用途 |
| --- | --- |
| GET/POST /credentials | 当前用户列表/幂等创建 |
| GET /credentials/{credential_id} | 元数据及未知保存结果核对 |
| PATCH /credentials/{credential_id} | expected_revision 全元数据更新，secret 留空保留 |
| DELETE /credentials/{credential_id}?expected_revision=... | 撤销、密文清除和旧编辑会话过期 |
| POST /credentials/{credential_id}/checks | 当前范围和运行环境检查，不访问目标 |

API上限5秒、前端凭据请求8秒；请求未确认时保留本地编辑并先读取原ID，不自动创建/替换。设置页离开时提醒未保存/未知请求；工作台选择保留尚未匹配的旧引用，不能静默切换到公共采集。`supports_credentials` 与探测得到的 `supports_browser_authorization` 分别描述存储与浏览器协议能力。
