# 多输出与仅传递结果 O5-02 实施与验收记录

日期：2026-10-14。本轮继续落地 CO-O5-02；O5-01 保留，O5-03～09 未实现。开发完成与真实发版验收分开，本轮只修改 scrapio 主平台。

## 1. 产品行为与使用入口

一个采集器可以在同一个页面输出电影记录 `records`、评论入口 `comment_links` 等不同结果；任务阶段逐端口选择保存到独立业务表或仅传递给下游。仅传递无需创建中间业务表，但输出、观察证据、来源和分发计划仍持久化，可用于追查和局部补采。

配置顺序：

1. 采集器工作台「④ 分页与输出」保留主端口 `records`，新增命名端口，分别配置记录定位、字段映射和稳定身份。保存、测试并发布新采集器版本。
2. 任务编辑器选择该版本，在「数据表与保存绑定」为每个端口选择保存方式，分别预演。附加端口默认展示“仅传递”，用户保存任务草稿后才生效。
3. 下游阶段的上游连接选择来源端口，再确认字段映射、过滤和数组展开。切换端口会清除旧连接规则，提示重新配置，避免复用另一端口的字段。
4. 发布任务版本，再隔离试采或正式执行。输出/观察页面标明端口；`passed` 显示为“仅传递”。活动运行继续使用冻结版本。

首版附加端口使用 CSS/XPath/JSONPath 表单配置；没有为每个附加端口新增浏览器点选工作台。主端口的已有点选功能继续保留。多个端口共用一次获取、动作和分页路径，不用于分别打开不同网页；不同网页仍拆成独立采集器与任务阶段。

## 2. 定义、版本与兼容

沿用 `collector.v1` 和 `task.v1`，增加可选字段；缺省时旧单端口行为与采集器 Schema 哈希保持兼容。

| 配置 | 本轮语义 |
| --- | --- |
| `definition.output` | 保留主端口 `records` |
| `definition.additional_outputs` | 最多4个附加端口，每个包含 `records` 定位与完整 `output`；合计最多5个端口 |
| `stage.save` | 主端口的保存策略 |
| `stage.additional_saves` | 每个附加端口恰好一个 `{port, save}`，不能遗漏、重复或绑定未声明端口 |
| `save.mode` 缺省或 `table` | 原业务表、Schema版本、唯一键、映射、更新与null策略 |
| `save.mode=pass_through` | 不携带业务表绑定，不写业务记录；仍保存不可变运行输出 |
| `edge.port` | 明确选择上游已声明端口；只使用该端口 Schema 校验映射 |

每个端口有独立字段与输出身份；端口名称符合 `^[a-z][a-z0-9_]{0,63}$`，不得重复或占用保留名称 `records`。各端口继续遵循字段1～30个、身份字段1～5个及原类型约束。版本的输出契约哈希包含全部端口，任务 Manifest 冻结每个端口 Schema 和保存绑定。

`pass_through` 输出决策为 `passed`，连接只能选择 `emit=valid`；没有业务记录创建/更新语义，不允许 `created` 或 `changed`。当前任何两个阶段/端口都不能绑定同一业务表，避免未定义的合并与覆盖。

多端口候选带显式 `port`，其样例预期使用 `{ "port": "comment_links", "values": {...} }`；回归比较包含端口，防止把相同值的不同端口当成同一输出。旧单端口候选缺省为 `records`，旧样例仍使用普通字段对象。

## 3. 分页、事务和恢复

所有端口提取同一份已获取文档；主端口决定下一页、重复页和空态结束。附加端口允许零结果，但不能用附加结果掩盖主端口缺失且没有空态证据的失败。主端口确认空态后，即使附加端口有结果也正常结束。

页数、总时长、记录数、证据字节、运行输出数、存储字节与分发容量沿用原预算；记录预算按全部端口合计。预算耗尽时标记受限，不宣称其他端口已经完整覆盖。同样的文档不会为每个端口再次访问网页。

每页事务按表ID锁定该阶段全部业务表并重新校验绑定，然后提交：

> 各端口业务保存决策 → 各端口观察与不可变输出 → 对应端口分发计划 → 输出计数 → 页检查点。

任一端口的数据库写入、输出预算或分发失败，整页回滚；已提交的前页保留。无效候选/业务唯一键冲突仍按原规则记录观察、不派发，工作项最终标记部分通过。试采保留同样输出与分发证据，正式业务写入为0。

不可变输出的幂等键为 `(item_id, port, output_identity)`；同一身份可以在不同端口各保存一次。同端口重放内容不同仍拒绝，不覆盖原输出。只有来源端口匹配连接的输出才注册派发计划，原 outbox、背压、租约、输入合并和检查点恢复机制继续使用。

局部补采核对历史输出的阶段及端口，不用其他端口或最新业务表值代替。来源链展示端口；仅传递输出同样计入保留和容量策略。活动运行使用的附加业务表也禁止直接升级 Schema，避免运行途中改变契约。

迁移 `2026_10_14_001` 添加 `co_run_outputs.port`、`co_observations.port`，旧行默认 `records`；原输出唯一约束替换为按端口唯一索引。启动迁移链已注册，没有删除旧数据，也未修改浏览器协议或部署配置。
