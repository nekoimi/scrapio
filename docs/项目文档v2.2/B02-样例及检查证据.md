# B02：样例及检查证据

B02 将 B01 成功快照转为有名称、页面角色、预期结果和保留引用的样例，并持久保存单样例提取检查。新产品域独立使用 `v22_samples/v22_sample_checks`，不引用旧 workflow 样例或历史采集数据。

## 使用流程

1. 在方案工作台保存提取规则，通过 HTTP、粘贴或浏览器保存成功快照并预览。
2. 在「样例与检查证据」选择新建，设置名称和正常/字段缺失类型。输入快照、步骤与 list/detail 角色固定，后续不能替换；不同输入需新建样例。
3. 编辑预期 JSON，也可点击「从预览填入首条预期」生成当前首条字段输出和计数，再人工核对。该按钮不自动保存或认定当前输出正确。
4. 浏览器样例默认不保存截图。需要截图时读取同版本画面，拖框遮挡敏感区域或遮挡整图，再确认允许保存。服务端重新读取同 session/page_state 的 PNG，按比例黑色覆盖并重新编码，只保存处理后的图片。页面已变化、关闭或图片超限时拒绝附图；取消附图即可保存固定输入。
5. 保存样例后点击「验证并保存检查证据」。验证当前已保存草稿，不访问网站、不重放动作、不写正式业务记录、不投递插件。缺少预期返回「未判定」；完整且符合预期返回「通过」；不符合、截断或提取失败返回「失败」。
6. 查看历史检查的原值/输出/诊断和预期差异，点击字段定位配置。规则或样例修改后旧证据标为历史/过期，仍保留原定义、原预期与原结果；重新验证才产生新证据。
7. 「带入预览」恢复保存输入、步骤和角色，会话关闭后仍可离线验证。删除受保护样例前先解除保护并保存；删除样例及其检查/图片后，原快照日志仍保留。

## 预期结果契约

```json
{
  "record_count": 2,
  "valid_count": 1,
  "invalid_count": 1,
  "fields": [
    { "record_index": 0, "field_key": "title-key", "value": "第一条", "errors": [] },
    { "record_index": 1, "field_key": "title-key", "value": null, "errors": ["REQUIRED_EMPTY"] }
  ]
}
```

- 计数可选，`record_count` 检查范围总数，valid/invalid_count 检查本次预算内候选计数。
- `record_index` 从 0 起，0～19；使用稳定 `field_key` 定位。断言必须配置 value 或 errors；显式 null 与省略 value 不同。
- value 比较 JSON 类型和值，数字使用精确十进制归一化，不经 float64 或 JavaScript 数字；对象不受键顺序影响，数组顺序有意义。
- errors 精确比较错误码集合。显式预期的失败字段可作为负例通过；任何未被预期覆盖的失败字段仍使检查失败。样例类型是用途标签，不自动将错误认定为符合预期。
- 已删除字段、未覆盖记录、计数下限或截断不能判通过。没有字段的非空记录不能判通过；显式期望空输入仅说明这个离线样例符合预期，不代表方案具备正式运行放行资格。
- `{}` 无断言，状态为 `unconfigured`，仍保存全部字段诊断。预期最多 64 KiB、100 个字段断言、每值 8 KiB。输入/提取预算沿用 B01。
- API 接受 `expected` 对象或 `expected_json` 文本二选一。界面使用文本传输，保留大整数；返回 `expected_json` 供精确编辑。预期哈希经过 JSON 对象键和精确十进制数值规范化，避免 PostgreSQL JSONB 重排、指数展开产生误报。

## 数据、保留与证据

迁移 `2026_10_09_004` 创建两张新表：

| 表 | 保存内容 | 生命周期 |
| --- | --- | --- |
| `v22_samples` | owner/方案/成功 capture 引用、固定步骤/角色、用途、样例 revision、保存规则 revision/hash、预期/hash、动作摘要、保留保护及可选已遮挡 PNG | 每方案最多 100 个；乐观锁修改/删除；快照有外键引用，不能被独立清理 |
| `v22_sample_checks` | 样例/草稿 revision、定义副本/hash、输入/hash、预期副本/hash、解释器版本、字段结果、差异、失败原因与时间 | 每样例最近 20 次；修改样例不改历史证据，删除样例级联删除 |

动作证据只复制取样前已完成回执的 command_id、类型、状态、前后页版本、错误码与时间，最多最近 50 条，并显示截取状态。没有动作输入值、URL、任意错误文本，不意味着可重放或已验证动作正确性。

截图最多 2 MiB、4096×4096 且不超过 800 万像素、最多 50 遮挡矩形；按像素解码和重新编码移除附带元数据。默认 `excluded`；附图策略为 `user-reviewed-masked-png.v1`，表示用户明确检查和设置遮挡，不声称自动识别网站中的所有秘密。图片经 owner 授权读取，检查保存哈希且 `Cache-Control: no-store`。HTTP/离线样例不接受任意上传图片冒充页面证据。

外键采用延迟 `NO ACTION` 保护 capture；合法删除整份方案时，方案→样例/快照的级联可在事务结束时同时完成，不因样例引用阻塞。当前产品仍使用归档方案，未新增物理删除入口。B05/D05 若要对发布绑定的证据作长期保留，须接入独立保留引用后调整最近 20 次清理策略，不得直接依赖会过期的检查 ID。

## 接口

| 接口 | 用途 |
| --- | --- |
| `GET/POST /api/v3/collectors/{id}/samples` | 游标分页/保存样例，保存需当前草稿 revision 和 Idempotency-Key |
| `GET /api/v3/samples/by-key` | 保存响应丢失后按原 key 查询，不自动重新截图 |
| `GET/PATCH/DELETE /api/v3/samples/{id}` | 读取含快照/改预期名称保护/合法删除；修改和删除需样例 revision |
| `GET /api/v3/samples/{id}/screenshot` | 授权读取处理后图片 |
| `GET/POST /api/v3/samples/{id}/checks` | 最近 20 次摘要/验证并保存；验证需草稿与样例 revision、请求键 |
| `GET /api/v3/samples/{id}/checks/{check_id}` | 固定历史证据和结果 |
| `POST /api/v3/collectors/{id}/previews` | 支持 sample_id，与 capture_id 二选一；样例步骤/角色不能被覆盖，不自动创建检查证据 |

检查同 key 重发会复用原证据，只要该证据仍处于保留范围；客户端不会自动重试。保存的同 key 重发先查库，即使原浏览器已关闭也不再次读取截图。样例修改冲突保留本地编辑，可明确重读服务端版本。
