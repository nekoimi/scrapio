# C05：首页与方案健康

状态：2026-10-10 开发收尾。短时边界、接口契约和前端局部检查完成；真实 PostgreSQL、浏览器与发版页面验收另行保留。

## 1. 日常使用闭环

再次打开 `/app/home`，能继续未发布草稿、找到最近数据及提交来源、查看需核对的方案、下次计划和最近运行。首页保留 URL 创建入口，空数据表提示继续试采、发布和正式运行。健康列表在 `/app/collectors/health`，方案概览嵌入同一健康组件。

首页分区最多展示 6 项；方案、数据表、当前记录、草稿、活动运行和需核对方案的总数独立统计。健康列表每页默认 25、最多 50 项，ID 倒序游标分页。锚点不再符合用户、归档或筛选条件时返回 404，重新读取第一页。

页面沿用新应用的浅色、蓝色主操作与中性状态样式。异常、有限覆盖和正常结果都有文字，不只依赖颜色。首页数据、浏览器能力、身份和创建草稿分别加载、报错及重试；浏览器失联不阻断已有数据展示。切换方案、筛选及离开页面后，迟到响应不覆盖当前视图。

## 2. 数据和时间口径

只读当前 owner 的 `v22_collectors/v22_versions/v22_runs/v22_schedules/v22_schedule_events/v22_data_tables/v22_table_records/v22_table_record_revisions`。不导入或查询旧磁力、旧工作流、试采结果与下载任务。本轮没有新增数据表、迁移或后台 worker。

首页采用 PostgreSQL `REPEATABLE READ, READ ONLY` 事务；所有分区共用数据库时钟和同一可见快照。`as_of` 为快照时点，`window_start=as_of-24h`。

| 展示项 | 口径 |
| --- | --- |
| 最近 24 小时新增/更新/未变 | 完成时间在 `[window_start, as_of]` 内、`succeeded/limited` 且 `committed=true` 的正式写入决策累计；同一记录多次更新会多次计数，不是净增或唯一记录数 |
| 最近有效采集 | 最近一次已提交的成功或有限覆盖运行；全未变仍为有效观察 |
| 最近有效观察 | 当前表记录的最大 `last_observed_at`；未变观察也会推进 |
| 最近实际变化 | 当前表记录修订的最大创建时间；未变观察不制造修订 |
| 当前记录数 | 数据表目前保存的记录数；使用十进制字符串，聚合计数同样避免前端整数精度丢失 |
| 下次运行 | 未归档方案已启用计划的 `next_at`，展示计划时区及固定发布版本；设备时区展示日期，预计触发不保证实际立即执行 |

首页指标进入 `/app/runs?committed=1&since=...&until=...`。页面传给接口的是 `committed=true`；接口 `false/省略` 表示不限制提交状态。`since/until` 必须成对 RFC3339，按完成时间包含边界，跨度大于零且最多 31 天。运行中心历史统计仍是该方案范围的全部保留历史，页面明确说明与窗口不同。时间窗口冻结，后续分页不滑动。

## 3. 健康判断及跳转

最近创建、最近完成、最近有效提交和活动运行数量分别返回。新排队或执行中的任务不能遮住上次完成失败。最近成功可以替代先前失败的近期判断，但不能抹去仍阻断的调度决定。

| 证据 | 展示及后续操作 |
| --- | --- |
| 尚无完成运行 | 尚未运行；继续草稿或查看最新活动运行 |
| 最近 succeeded | 最近运行正常；零新增、全部未变不报警 |
| 最近 failed/partial | 需处理；带入该运行和结束原因，进入现有证据页 |
| 最近 limited | 有限覆盖需核对；单独警告并链接预算与运行证据 |
| 最近 cancelled | 已取消；不作为采集故障报警 |
| 调度 disabled_invalid/disabled_unavailable/skipped_capacity | 调度阻断，进入计划页检查；手动成功不会替代这个调度决定 |
| 主动暂停、重叠跳过或排队 | 展示实际决定，不自动判为故障 |
| 归档方案 | 不进入活动首页、健康列表和下次计划；直接健康读取可用，提示不再触发新的定时运行 |

“查看数据”优先进入最近有效运行**实际写入**的表。当前发布版本的目标表单独展示，修改/重新发布到另一张表不改变过去运行的来源。近期运行可包含归档方案的保留历史，归档不删除已保存记录或历史证据。

所有健康响应 `baseline_status=not_configured`，不绘制推测趋势，不以零新增、总量未知或一次有限覆盖推断字段质量下降。持久问题、阈值、跨运行基线和有条件恢复属于 D03，本轮不提前实现。失败输入带入修复属于 D01。

## 4. 接口及读取边界

OpenAPI：[阶段 0 接口契约草案](阶段0接口契约草案.yaml)，版本 `0.18.0-c05`。

- `GET /api/v3/home`：同一快照首页概览。
- `GET /api/v3/collectors/health?attention=true&cursor=...&limit=25`：未归档方案健康分页。
- `GET /api/v3/collectors/{collector_id}/health`：方案近期健康及来源。
- `GET /api/v3/runs`：增加 `committed/since/until` 筛选，游标锚点必须匹配全部条件。
- capabilities 增加 `supports_home_overview/supports_collector_health`，独立于浏览器就绪。

概览仓储读取在认证后有 5 秒 deadline；前端概览/健康请求 8 秒。401、404、408、500 分别说明认证、不可读资源/锚点、超时和存储异常，失败不返回虚假的空首页或健康状态。响应只包含运行摘要允许字段，不返回定义、请求输入、原文、记录值、lease 或浏览器会话。列表有界，聚合查询依然需通过实际数据量验证执行计划；本轮不声称已做 PostgreSQL 性能实测。
