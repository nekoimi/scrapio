# B01：提取与即时预览

本阶段把已保存的 `record_set`、`json_records` 和成功快照连接起来，提供逐字段原值、转换值、校验诊断及候选记录。预览不访问目标网站、不打开详情/下一页、不写正式业务记录、不投递插件。新产品域仍与旧采集数据隔离。

## 操作流程

1. 保存记录范围和字段。字段新增「类型、清洗与校验」，支持名称/顺序、稳定字段键、类型、必填、多值、空白处理、正则和日期格式。JSON 树点选和网页点选继续用于配置定位规则。
2. 用 A07 HTTP/离线入口保存 JSON 或 HTML，或打开浏览器页面后点击「保存当前浏览器 HTML 快照」。浏览器取样只读取当前 DOM，不重新打开 URL；需要支持 `snapshot` 操作的 scrapio-browser。
3. 在「提取与即时预览」选择已保存步骤和 list/detail 角色，自动预览，也可手动重试。列表和详情分别验证各自字段；详情访问仍通过 A06 明确确认的动作完成，本接口不自动合并两页数据。
4. 表格显示范围、实际预览条数、有效/无效记录、逐字段命中、输出和原值。展开查看诊断，点击输出定位对应字段配置；原值和转换值的 JSON 字符串保留大整数精度。
5. 修改字段后保存会自动刷新预览（250ms 合并连续变化）。未保存修改会阻止检查；修改 revision、输入、步骤或角色会标记过期，晚到响应丢弃。浏览器页面变化不改变已有固定快照，但会提示快照已不代表当前页面。

旧草稿没有 `field_key` 时回退到名称；表单保存会补充键，后续重命名与排序保留该键。字段键在同一页面角色内唯一。

## 字段契约

HTML 字段沿用 `name/locator/extract/attribute`，JSON 字段沿用 `name/pointer`。两者共用以下选项：

| 选项 | 执行语义 |
| --- | --- |
| `field_key` | 稳定诊断键，最长 128 个字母、数字、下划线或连字符。 |
| `type` | 缺省保持 JSON 原类型/HTML 文本；可选 string、integer、number、boolean、date、datetime、json。 |
| `required` | 缺失、null、空字符串、空数组或转换后为空报 `REQUIRED_EMPTY`；0 和 false 为有效值。 |
| `multiple` | HTML 每个匹配元素分别处理；JSON Pointer 指向数组时逐项处理。单值 HTML 多命中报错，不静默取第一项。 |
| `clean` | 缺省保留文本；trim 去首尾空白，whitespace 合并空白。清洗针对文本，非文本报错。 |
| `regex` | 最长 512 字符的 RE2 表达式；清洗后取第一个捕获组，无捕获组取完整匹配；无匹配/非法表达式明确报错。 |
| `date_format` | Go layout，自定义无时区格式按 UTC；date 默认 `2006-01-02`，datetime 默认 RFC3339。 |

处理顺序固定为「取原值 → 空白处理 → 正则 → 类型转换 → 必填检查」。多值每项分别处理，一项转换失败则整条记录无效；全部空值的必填多值字段无效。JSON 单值 Pointer 选中对象/数组时可保持原 JSON 值；标量类型不能静默串化复杂对象。

整数使用 int64 范围，并保留 JSON Number 输出；数字拒绝 NaN/Infinity 与非法 JSON 数字，保留输入数字文本；布尔只接受 true/false；date 输出 `YYYY-MM-DD`，datetime 转 UTC RFC3339。未配置字段的记录不算有效候选。合法可空字段缺失返回 null，多值缺失返回空数组。

## HTML 定位与来源

- 重复记录字段相对于每个容器，单页和 detail 相对于文档；省略 locator 读取容器自身。CSS 支持常用结构选择器及前缀 `:scope`；XPath 必须选元素，重复项以 `.` 开头，实际越出当前容器也会报错。
- 文本使用保存 HTML 的 DOM 文本，跳过 script/style/input/textarea 及 hidden 子树；不保留计算样式/布局/innerText，不能保证和浏览器 A06 的当前 DOM 基础值完全一致。后续试采与正式提取使用同一固定文档解释器，避免另写一套转换逻辑。
- 链接/图片先保存原属性字符串，再解析成绝对 URL；浏览器使用保存的 document.baseURI，HTTP/离线使用文档 base 标签和来源 URL。片段去除，非法协议/嵌入凭据/已知秘密查询拒绝；允许展示站外链接但不自动访问。
- `value` 与已知秘密属性不可提取。不穿透 iframe/Shadow DOM，不加载图片/脚本，不执行 JS。来源显示定位规则、URL、快照与页版本；当前页面的坐标高亮仍由 A06 只读 DOM 检查提供，不给旧快照伪造可用坐标。

## 后端接口与共用解释器

`POST /api/v3/collectors/{id}/previews`：

```json
{
  "expected_revision": 4,
  "capture_id": "固定快照 UUID",
  "step_id": "items",
  "stage": "list"
}
```

服务端读取同 owner、同方案的成功快照，验证内容哈希，并从已保存草稿读取规则。客户端不能替换规则；revision 不匹配返回 409。可以用旧快照验证新规则，响应绑定规则 revision、快照 revision、内容/定义哈希和 `extract.v1` 解释器版本。`sample_id` 在 B02 接入，本阶段显式拒绝。

`internal/extraction.Extract` 是无网络/数据库/文件访问的解释器，返回候选和全部字段诊断；`CandidateValues` 只选有效记录。`internal/field` 提供共用选项及转换。B04/B06 的新试采和正式运行必须调用同一解释器并在发布版本中冻结定义；本阶段没有正式运行调度/写入器，不能宣称已完成运行一致性的实环境验收。旧 v2.1 workflow 不改语义，也不拿旧执行器冒充新正式执行。

每次预览最多 20 条记录、每页面角色 30 字段、每字段 50 个值/8 KiB 原值及转换值，总响应最多 2 MiB。HTML 记录计数最多 1000，`match_count_lower_bound` 为 true 时是下限；JSON 返回数组总数。`truncated` 单独表示预览覆盖被截取，不混同总数下限。节点/深度/上下文预算受限，截断字段不算有效。0 条记录返回真实空结果和 `NO_RECORDS`；部分字段失败保留其他诊断，不因首个错误停止整份预览。

## 浏览器快照

`POST /api/v3/browser-sessions/{id}/captures` 携带 `Idempotency-Key`、expected_revision、page_state_id。使用现有 `InspectEditorPage` 的 `snapshot` 操作和独立能力探测，不改变 protobuf 消息布局；需部署新的浏览器服务，旧 A06 服务不误报支持。

快照绑定 owner/session/方案/revision/page_state，拒绝未确认动作。浏览器加锁并检查读取前后页版本，通过惰性模板文档保存结构/属性，去掉脚本、样式、输入值、textarea 内容及已知秘密属性；Go 再做规范化与脱敏。原 DOM 序列化最多 2 MiB，保存 HTML 最多 1 MiB，RPC JSON 最多 2 MiB。仅基础脱敏，任意网站秘密回显/个人信息仍需后续治理。

日志沿用 `v22_captures`，新增 session_id、page_state_id、base_url，迁移版本 `2026_10_09_003`。网络/存储中断后只按原 key 查询，不自动重发取样；成功快照可在会话关闭后继续离线提取。浏览器快照的 `network_accessed=false` 指本次没有主动访问目标，不代表原页面从未访问网络。
