# 同运行重复输入合并 O5-01 实施与验收记录

日期：2026-10-13。用户选中 CO-O5-01，本轮仅实现该项；O5-02～09 继续未选。开发收尾与真实发版验收分开，本轮未修改 scrapio-browser。

## 1. 场景与产品契约

同一榜单采集器执行不同入口/分页后，多个不可变输出可能都指向同一电影输入。下游电影阶段可以选择“相同完整输入只执行一次”，复用一个工作项，保留每一个上游输出和数组元素的来源。手动根输入也支持这一选择。

新增阶段配置 `input_policy`：

| 配置 | 行为 |
| --- | --- |
| 缺省或 `keep_all` | 所有来源独立创建工作项，保持旧版本行为 |
| `merge_identical` | 本次运行、本阶段、固定采集器版本与规范化完整输入相同，复用同一个工作项 |

采用采集器校验后完整 JSON 输入的确定性哈希，不只比较 URL。字段顺序不影响身份；其他输入参数、采集器版本或阶段不同不会合并。不擅自去掉查询参数、凭据引用、语言、对象ID等影响执行的字段。阶段边界同时隔离固定保存绑定、输出映射、错误策略与离线证据；即使多个分支用了同一个采集器，也不跨阶段合并。

启用合并等于用户选择**一次执行、共同结果**，不是只复用下载页面：工作项执行/重试/失败/未知动作确认共享，下游只按该工作项输出派发一次，不为每个来源重复派发。合并项在排队、运行、完成、失败、TTL跳过或等待确认时均可关联新来源，晚到来源不重启它、不重发输出。`merged` 是分发回执状态，不是独立工作项或自动成功；运行最终结果依赖实际工作项状态。

首次物化的输入创建实际工作项，随后到来的相同输入关联该项；不做“挑最新来源值”或自动替换。活动运行的来源仍可能增加，完整核对时应在运行结束后重新打开工作项，再分页查看。

需要逐来源重复动作或逐来源刷新时使用 `keep_all`。多上游 Join、跨分支页面缓存或每来源独立结果还不在本项范围。

## 2. 数据与事务

迁移 `2026_10_13_005` 添加：

- `co_work_items.dedup_key`，只在合并策略下设置；同 run/stage/key 的部分唯一索引防止重复创建。旧工作项键为 NULL。
- `co_item_sources` 将每个完整 `co_run_inputs` 快照关联到实际工作项，标记创建或合并；已有工作项来源回填，不改旧结果。
- `co_lineage` 主键从单 target 扩展为 target/output/edge/element，保存多个上游来源，保留原映射哈希、输出身份和数组元素身份。

根输入物化与下游分发均持有原运行事务锁：查合并身份 → 追加来源快照 → 创建或关联工作项 → 写来源链/分发回执 → 推进游标，同事务提交。下游仍使用 O3 原输出/连接/展开序号回执与计划游标幂等；崩溃回滚不会只留下半条来源。合并不替代同一来源重复派发防护。

每轮处理最多10个来源；合并不消耗新工作项或待处理槽位，队列满或工作项预算已满时仍可关联已有工作项。原输入数量/快照、输出数量/字节、派发元素、运行时长等容量约束继续有效；不因为能合并就允许无限来源。根输入预算校验与尚未物化根输入的工作项预留仍采用保守上限，不提前用去重预测扩大任务预算。

试采、正式运行和其他运行各有独立去重域；跨运行 TTL 仍是 O4 的单独策略。失败补采创建新运行，选取一次规范化输入；新来源保留原运行/工作项/输入引用，原工作项全部来源可继续查询，不重新按每个来源扩增执行。

## 3. 界面与接口

任务编辑器的当前阶段运行配置增加“当前阶段重复输入”选择，说明共享失败与下游结果。保存草稿后需发布新版本；活动运行和计划仍使用原冻结版本。

运行阶段表展示来源输入、实际工作项、合并减少数、分发合并数及冻结策略。工作项抽屉展示全部来源快照，区分创建和合并；来源链可以追溯多个上游。分发页的 `merged` 显示为“合并到已有工作项”，可跳到该项。

沿用现有接口，无新增路由：

- 能力接口增加 `input_policies` 与 `input_merge_scope=run_stage`。
- 运行详情增加 `source_count`、`merged_inputs`、`merged_dispatches`；原 `input_count` 表示实际工作项数。
- 工作项详情增加 `sources`、`next_source_cursor`、`lineage_has_more`；`source_cursor` 按输入ID分页，每页100条。主输入与尝试保留原字段。
- 递归来源最多20阶段，去重关系防止重复路径放大；当前响应显示前100条并明确更多标记，可从来源和上游工作项继续查。完整来源关系不删除，不将有限展示冒充完整证据。

OpenAPI 顺序生成追加 `co-o5.cjs`，仅扩展所选 O5-01 配置和投影。认证、所有权、幂等操作、严格 JSON 与来源证据保留继续沿用。新增迁移由现有启动链注册，Dockerfile、compose和浏览器协议无需改变。
