# B03：数据表与输出确认

B03 建立新产品的逻辑数据表和保存步骤：固定输入 → 共用提取 → Schema/映射校验 → 键与保存预演 → 明确确认输出配置。所有数据域使用 `v22_*`，不导入旧 datasets/records/magnets。当前每个方案一个输出绑定，固定提取步骤和 list/detail 角色；没有在输出预演中导航或合并详情数据。

## 使用流程

1. 保存字段规则并取得成功快照，在底部选择提取步骤与角色。
2. 在「保存步骤 · 数据表与输出确认」选择新建，点击「从已保存字段生成新表草案」，检查字段类型、可空、多值，选择单字段或复合唯一键，再填写表名称。未声明类型的 JSON 字段生成 json 类型，作为唯一键前需确认标量类型并调整提取配置；不猜测首条样本就是完整类型。
3. 也可选择已有逻辑表。Schema 只读，来源与目标使用稳定 field_key 显式映射；不能仅凭同名就认为兼容。可空目标允许不映射，必填目标和全部唯一键必须映射；未保存的来源字段有明确提示。
4. 选择同键更新策略：更新变化字段，或保留已有记录；选择空值策略：不覆盖已有值，或允许覆盖。空值策略不能允许空唯一键。
5. 点击「预演保存结果」。服务端从保存草稿与输入重新提取，不接受客户端传入候选作为真实预演；展示新增/更新/未变/无效/冲突、键值、预计最终目标值、变化字段和诊断。
6. 预演通过且未过期后，确认保存输出配置。新表在这次确认事务内创建，既有表复用；同事务保存表/绑定和草稿 output，revision 增加。操作不写正式记录、观察、修订或插件事件。
7. 刷新或确认响应丢失后读取服务端绑定；预演响应丢失按原请求键查询。已成功确认且绑定 revision 未变化时，同检查重放先返回已保存状态，不再要求后来可能已变化的样例通过。未保存配置/未知请求在离开前提示；冲突保留本地配置。复制方案只复制提取定义，移除旧输出绑定，必须重新确认目标表。

## Schema、映射与键

```json
{
  "fields": [
    { "field_key": "url", "name": "来源地址", "type": "string", "nullable": false, "multiple": false },
    { "field_key": "score", "name": "评分", "type": "number", "nullable": true, "multiple": false }
  ],
  "unique_key": ["url"]
}
```

- 逻辑表最多 30 字段，唯一键 1～5 个标量字段，不支持 JSON/多值作为键。唯一键按列表顺序组合；字段名称用于展示，键和记录值使用 field_key。
- Schema 使用明确 string/integer/number/boolean/date/datetime/json 与可空、多值属性。来源静态类型必须兼容，integer 可写入 number，任意类型可写入 json；JSON 未声明来源类型会警告，再逐候选验证真实类型。输出不偷偷做第二套清洗或类型转换，转换由 B01 解释器完成。
- 映射一对一。目标可空缺省值为 null，非空值类型严格检查；任何提取错误仍使整条候选无效，不能靠遗漏映射把必填提取错误隐藏。
- 复合键的 JSON 值按精确数字规范化后 SHA-256，0/false 有效，null/空字符串/空数组无效；没有把显示名称拼接当记录身份，或用浮点数破坏大整数。
- 已有表 Schema v1 在 B03 不提供编辑入口；未来 D05 修改需要影响检查与新 Schema 版本，不能直接改变键或暗改旧记录。

## 预演与确认边界

`internal/output` 提供共用 Schema/映射/Prepare/Merge/PreviewBatch，B06 正式写入须复用这些语义，并在事务中重新判断数据库状态。预演使用 `extract.v1` 固定文档输入，最多 20 候选、目标记录最多 256 KiB、总结果最多 2 MiB。

| 情况 | 预演结果 |
| --- | --- |
| 新键 | created，预计新增 |
| 已存在键，策略生效后有变化 | updated，列出变化字段与预计最终值 |
| 已存在键，无变化或 keep_existing | unchanged；保留策略显示明确原因，目标值是预计保留值 |
| 同批相同键和相同目标值 | 首条正常预判，其余 unchanged/重复；不重复计新增 |
| 同批相同键但不同目标值 | 所有同键候选 conflict，阻止确认，不按顺序覆盖 |
| 缺键、无效提取、类型/映射错误 | invalid，阻止确认 |
| 0 候选或预览截断 | 阻止确认，不能声称完整检查通过 |

检查保存草稿 revision/hash、输入 hash、可选样例 revision、表 Schema version/hash、全部配置和结果，30 分钟有效。规则、输入、样例、表版本或页面本地配置改变会过期；确认事务再次校验保存状态，不能提交客户端临时 Schema 绕过检查。

确认只保证输出配置可用，不预留键、不保证正式运行届时仍是新增。其他运行可能在预演后更新记录，因此 B06 必须重新检查并原子保存。普通草稿 PUT 只能保留已确认 output，不能手写/替换/删除它绕过确认；输出变更使用专用确认接口。B05 还需验证 output 对应规则的当前兼容性，不能沿用旧草稿预演当发布放行。

## 数据模型与接口

迁移 `2026_10_09_005` 创建：

| 数据表 | 用途 |
| --- | --- |
| `v22_data_tables / v22_data_table_schemas` | owner、表名称与不可变 Schema v1/hash；每 owner 最多 100 表 |
| `v22_output_checks / v22_output_bindings` | 有界保存预演与草稿输出绑定；每方案最近 20 次加当前绑定证据，绑定证据保留引用 |
| `v22_table_records` | 全部逻辑表共享物理记录表；JSONB 目标值、复合键/hash、Schema、revision 和首次/最近观察 |
| `v22_table_observations` | 写入身份/结果、每次候选值、来源 URL、页面角色、run/version/document/capture 引用与时间 |
| `v22_table_record_revisions` | 按 record/revision 保存变化后的 JSONB 值、变化字段与观察关联 |

B03 创建记录/观察/修订模型和读预判，未开放正式写入；B06 接入运行和事务写入后才产生记录。run/version/document 暂时保留明确引用列，待 B05/B06 新模型建立时补相应关系。被输出检查引用的 capture、被绑定引用的 check 使用延迟外键保护，删除整个方案可级联完成；不得单独清理保留证据。发布版本长期保留引用在 B05 补充，不能直接依赖最近 20 次保留窗口。

| 接口 | 用途 |
| --- | --- |
| `GET/POST /api/v3/tables` | 同 owner 分页/显式创建表，创建需请求键；界面默认在确认时建表 |
| `GET /api/v3/tables/{id}`、`GET /api/v3/tables/{id}/schema` | 读取表元数据及完整不可变 Schema |
| `POST /api/v3/collectors/{id}/output-checks` | 保存输入/样例二选一，目标表/拟建表二选一，重新提取和保存预演 |
| `GET /api/v3/collectors/{id}/output-checks/by-key` | 按原请求键恢复预演，无重复取样 |
| `GET /api/v3/collectors/{id}/output-checks/{check_id}` | 读取检查结果与固定配置 |
| `PUT /api/v3/collectors/{id}/output` | 携带 expected_revision/check_id 原子确认；丢失响应同检查可重放，不能重复建表 |
