# C01 样例集与全链路回归落地记录

## 交付

- 样例增加 `expected_outcome`：`success`、`error`、`empty_list`。预期报错需指定错误包含文字，避免任意故障被误判通过；空列表只适用于列表角色。旧样例迁移后默认为 `success`。
- 离线预览和批量回归报告预期、实际结果与实际错误。正常详情/JSON 批量样例经工作流的提取、转换、校验、数据集准备及保存决策预览；列表样例使用与任务执行相同的链接发现逻辑。预览不写正式记录、观察、修订或插件队列，也不访问网络。
- 发布仍要求至少一个成功产出样例；列表采集器要求能发现详情的正常列表样例和正常详情样例。预期错误和空列表样例参加回归，但不能单独满足发布门槛。
- 历史文档被样例引用期间，数据库外键禁止删除文档。删除草稿样例或其所属版本后，引用解除。C04 的保留期清理需要沿用该约束。

## 验证

- `SCRAPIO_TEST_DEV_C01=1 go test -timeout 120s ./internal/repo/workflow_repo -run TestDevRecordTemplatePublication -count=1`：在 `get_magnet_dev` 验证 HTML/JSON 正常与缺字段样例、列表与空列表样例、发布门槛、文档保留及离线预览不写库。
- `go test -timeout 120s ./...`、`web` 目录 `npm run build` 和 `git diff --check`。

## 发版验收

用实际采集器保存正常详情、结构变化导致的缺字段页面与空列表历史页面；离线回归确认三类预期和错误详情，再验证发布门槛。真实浏览器获取及部署环境迁移随发版验收。
