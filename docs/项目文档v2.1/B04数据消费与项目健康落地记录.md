# B04 数据消费与项目健康落地记录

## 已落地

- 数据集记录查询改为服务端筛选：唯一键/字段内容、来源、最近新增或变化、起始日期，筛选与分页作用于整个数据集。列表显示最近有效变化及来源数量，未标识来源也可单独筛选。常用视图按数据集保存，重开页面可复用或删除。
- 来源覆盖按数据集汇总每个来源的记录数、观察次数和最后观察时间。记录详情继续保留观察、运行、原文及字段修订证据。
- CSV 导出复用相同筛选条件，包含唯一键、当前字段 JSON、首次和最近发现时间。1000 条以内直接返回；超过 1000 条转后台导出任务，最多 100000 条且生成内容不超过 50 MiB，单数据集最多同时排队 5 个任务。后台任务在服务重启后恢复，结果保留 7 天。CSV 对以公式符号开头的唯一键加前缀，避免表格软件执行公式。
- 项目健康接口汇总每个数据集的当前记录数、近 7 天新增/变化和最近有效更新；按采集器提供最近运行、最近成功时间和待处理问题。项目页显示这些指标并提供问题入口。采集器停用、未发布、已发布但从未运行、最近失败/取消/部分成功、已启用定时但连续 7 天无成功运行均有提示。
- 新增筛选视图、导出任务持久表及相关查询索引。管理界面使用现有 v2.1 样式，数据页提供筛选、视图、覆盖、导出状态；项目页提供数据变化和健康信息。

## 验证

- `go test -timeout 120s ./...` 通过；`web` 执行 `npm run build` 通过。
- 显式启用 `SCRAPIO_TEST_DEV_B04=1` 后，在 `config/dev.yaml` 的 `get_magnet_dev` 开发 PostgreSQL 中验证筛选、通配字符、来源覆盖、视图、CSV、后台任务及项目健康。测试先断言数据库名称并清理测试数据。
- 发版后仍需验证真实数据量下的查询与导出耗时、浏览器下载体验。大数据量查询可进一步增加专用搜索索引或后台查询任务。

## 当前边界

- 导出内容以数据库 `bytea` 保留 7 天，适合单实例和小团队；超过 100000 行需缩小筛选条件。CSV 下载和视图操作沿用现有登录认证与项目访问模型。
- “最近有效更新”取新增或更新修订的时间；仅重复观察、不改变字段的运行不会刷新这个指标。
