# scrapio v2.1 改造与实施计划

> 状态：实施计划草案。依据 [v2.1 产品规划](采集平台v2.1产品规划.md)和[管理界面产品设计](前端管理界面v2.1产品设计.md)，对照 2026-09-25 的 `scrapio`、`web/` 与 `scrapio-browser` 代码编制。本文是待实施任务与验收口径，不表示功能已完成。
>
> 部署边界：单实例 Go 控制平面及内置前端、一个浏览器执行服务、PostgreSQL。云盘、aria2、STRM、运行时 AI 和下载插件不构成 v2.1 核心交付。

## 1. 交付目标与原则

v2.1 的交付单位是用户能走通的路径：**创建数据集与采集器 → 获取样例 → 预览完整采集过程 → 发布 → 手动/定时/API 运行 → 查询记录及来源 → 从异常修复规则**。单独增加表、节点或页面，不算完成该路径。

实施时沿用已有 `workflow_runs`、`crawl_tasks`、`task_attempts` 的持久任务能力，但重新定义用户对象和写入契约。普通 HTTP/JSON 由 Go 获取，必须浏览器渲染或交互时才调用 `scrapio-browser`。预览和正式运行使用同一解析与决策代码，只在“提交写入、发送外部事件”处明确分流。发布只能接受当前执行器真实支持的配置。

## 2. 当前代码基线与产品差距

以下结论针对当前实现；表中“已有”仅表示可复用的代码基础。

| 领域 | 现有基础与证据 | v2.1 缺口 |
| --- | --- | --- |
| 定义与发布 | `internal/workflow/definition.go` 有 JSON 定义；`internal/repo/workflow_repo/workflows.go` 有草稿、发布、运行版本 | 校验接受 `pagination`、`persist`、`event`、`cron`、`api` 等类型，但 `internal/workflow/worker.go` 未按这些类型执行；发布只做结构校验，可能出现“运行成功但规则未执行” |
| 获取 | `internal/drission_rod/browser_client.go` 和 `scrapio-browser/app/downloader/browser.py` 有通用 gRPC 执行协议 | 工作流 worker 无论页面类型都调用浏览器；没有统一的 HTTP/JSON 获取结果。协议包含 `profile`、`headers` 等字段，但 Python 通用执行器没有按请求切换 Profile/应用 Headers；通用动作只有 `wait/click/input/script`，尚无滚动与逐动作结果 |
| 发现与分页 | worker 的 `discover` 可从根任务创建详情任务，提取器支持 CSS、XPath 和有限 JSONPath | 无受控分页、每页/每次运行任务上限、跨域策略和稳定的发现去重；列表、分页、详情尚未组成同一可预览流程 |
| 通用数据 | `sources`、`resources`、`documents` 及旧磁力迁移已存在，资源 API 可查询 | `persistResource` 依赖 `number/links/title/actress`，最终调用只写 `magnet` 的 `SaveCollected`；唯一约束按来源划分，同一数据集跨来源合并、字段 Schema、版本、来源证据和变更历史未建立 |
| 运行与回放 | 租约、重试、取消、任务尝试和原文/截图存储已存在；有提取测试、文档回放、版本 diff 接口 | 运行只归为成功/失败等基础状态；摘要由任务结果覆盖，缺少完整计数、部分成功/受限结束和字段级过程；回放只取首个提取节点，不代表整个版本流程 |
| 触发与调度 | `internal/job` 为旧 provider 注册 cron；工作流 API 可手动创建持久运行 | `workflow_repo.StartRun` 固定记录 `manual`，尚无工作流定时注册/恢复、API 触发授权、并发策略与下一次运行时间 |
| 管理界面 | `web/` 有登录、旧磁力/下载/运维页面；后端已有若干 `/api/v2` 能力 | `web/src/router/route.ts` 与 `web/src/views/` 尚无项目、数据集、采集器工作台和运行详情的 v2.1 主路径；旧首页仍以资源和下载状态为中心，模板演示路由仍较多 |
| 可选扩展 | `internal/script` 有受限 JS 转换，插件队列和 AI 解析代码已存在 | 不应将这些代码当作 v2.1 核心能力已交付；脚本、插件订阅和 AI 的界面、授权、版本与效果验收放到 D 阶段 |

**首要阻断：**在完成新的发布校验之前，现有 `/api/v2/workflows/versions/publish` 仍可能发布执行器会跳过的节点。v2.1 工作台不得直接把旧的“校验通过”解释为“可发布”。

## 3. 目标实现边界

### 3.1 统一执行契约

以受限模板生成同一份带 `schema_version` 的定义：单页详情、JSON 接口先交付；列表到详情、分页列表后交付。定义明确入口、获取器、页面角色、发现规则、字段、数据集、唯一键、预算、触发设置及可选外部动作。节点保留内部表达能力，但发布前要对**节点类型、配置字段、执行顺序和浏览器能力**逐项核对；未知字段和无法执行的组合报出 JSON 路径及原因。

统一 `FetchResult`：请求方法和目标、最终 URL、状态码、内容类型、正文或文档引用、耗时、错误、可选截图及动作结果。HTTP 获取由 Go 实现；浏览器仍通过现有 gRPC 通道。浏览器能力用服务端可验证的能力清单驱动表单和发布校验。先补全基础动作与结果，再决定是否开放 Profile、Headers、Cookies、会话复用；不能把仅存在于 proto 的字段作为已支持能力。获取入口与发现 URL 要校验协议、域名和解析后的目标地址，防止工作流绕过访问边界。

`crawl_tasks` 继续承载页面任务与租约；按页面角色和深度创建根页、列表页、详情页。每次派生任务带运行级去重键，重试不能重复生成子任务。运行预算至少包括页面数、任务数、深度、耗时、单页发现数量和目标域名；达到上限要记录已覆盖范围与 `limited` 结束原因。任务完成与记录保存要有可重试的幂等边界。

### 3.2 数据模型增量演进

建议新建以下业务表（最终列名、索引与约束在首个数据库 PR 中定稿），**不直接把旧 `resources` 改名为 `records`**：

| 表/关系 | 最小字段与约束 | 用途 |
| --- | --- | --- |
| `projects` | `id`、名称、目标、负责人、状态、时间；初始化一个默认项目 | 业务目标和健康汇总；单实例组织，不引入租户边界 |
| `datasets`、`dataset_fields` | `project_id`、`record_type`、显示字段、字段类型/必填/多值、唯一键规则、空值更新策略；Schema 版本 | 让同类数据跨采集器复用；磁力只是一个预设模板 |
| `records` | `dataset_id`、`canonical_key`、当前规范化 JSON、状态、首次/最近发现时间、内容哈希；唯一 `(dataset_id, canonical_key)` | 数据集内去重、查询和稳定记录 ID |
| `record_observations`、`record_revisions` | 关联 `record_id`、采集器/版本、运行/任务/文档、来源 URL、原始字段、规范化字段、保存决策、时间；修订保存字段差异 | 一条记录可有多个来源与多次观察；支持新增、更新、未变和追溯 |
| `workflow_samples`、`sample_assertions` | 采集器、页面角色、文档/截图引用、样例来源、预期字段/链接或预期失败、备注、保留标记 | 离线预览、回归和发布门禁 |
| `workflow_schedules`、`credential_refs` | 时区、cron、启停、并发策略、下次运行；凭据标识与授权范围 | 定时恢复和秘密引用；密文或外部秘密留在控制平面，不写入规则、文档和日志 |

现有 `workflows` 逐步关联项目和数据集；现有 `workflow_runs/crawl_tasks/documents` 增加必要的触发、预算、页面角色、最终 URL、错误阶段和聚合字段。记录写入结果固定为 `created/updated/unchanged/invalid/conflict`；失败页和重复跳过单独计数。默认更新策略为逐字段合并，空值不覆盖已有非空值，具体规则由数据集 Schema 声明。唯一键缺失必须是无效候选，不能算成功。

旧 `magnets` 保持原样；现有 `resources` 与 `legacy_download_states` 暂保留供旧接口和插件使用。迁移时以**已迁入的磁力资源**为输入，创建默认项目、磁力数据集、记录与来源观察，并保存 `legacy_resource_id → record_id` 映射；避免再次从 `magnets` 重复导入。迁移脚本可重复执行、可核对行数和异常清单。过渡期避免无约束的双向同步：确定一个正式写入路径，旧入口通过适配器写入或维持旧视图，切换后再逐步退役。历史任务与下载状态不随 UI 改造删除。

### 3.3 API 与界面契约

沿用 `/api/v2` 前缀增量增加项目、数据集、记录、样例、预览、发布检查、调度和质量接口；旧路由在迁移期保留。接口以项目和数据集为入口，页面任务的内部 ID 仅作详情定位。列表统一分页、过滤及稳定排序；运行详情的任务树分批加载，不一次返回全部页面。预览返回每一步的输入、输出、字段原值与转换值、预计保存决策和是否真实访问网络，并明确 `dry_run=true` 时不写正式记录、不发送插件事件。

界面按[前端产品设计](前端管理界面v2.1产品设计.md)落地“项目 / 数据 / 采集器 / 运行 / 设置”五个一级入口。新工作台用表单编辑与高级 JSON 编辑维护同一版本定义；遇到表单不能表达的已支持字段时显示只读提示，不能静默丢失。旧磁力、下载和模板演示页先从主导航移出，确认新路径可用后再删不再使用的页面与 API 客户端。

### 3.4 `web/` 视觉实现依据

[管理界面 v2.1 交互原型](管理界面v2.1交互原型.html)是 v2.1 页面布局、配色、组件外观和主要交互的**视觉基准**；[前端管理界面产品设计](前端管理界面v2.1产品设计.md)确定信息架构与状态语义。开发时先逐屏查看原型的项目、数据、采集器、运行、设置和创建向导，再在现有 Vue 3 / Element Plus 项目中实现；原型中的模拟数据和 Toast 不作为真实业务行为。

- **统一样式变量**：从原型最终生效的样式提取色彩、字体、间距、边框、圆角、阴影和断点，在 `web/src/theme/` 建立 v2.1 设计令牌。主画布为中性蓝灰，深靛蓝侧栏、白底选中导航、蓝色交互强调；绿色仅表示健康/通过，橙色表示关注，红色表示失败。原型文件中存在早期样式和后续覆盖，取浏览器最终呈现效果，不机械复制首个 `:root` 块。
- **应用外壳与组件**：保留原型的项目切换、顶部面包屑、页面标题和操作区，以及卡片、指标、状态徽标、问题提示、筛选工具栏、表格与侧边检查面板的视觉层级。将这些做成可复用 Vue 组件或样式规范，避免各阶段分别仿造、出现多个风格。
- **关键页面映射**：A 阶段完成项目概览、数据集与记录、创建向导、采集器三栏工作台及发布检查；B 阶段完成运行趋势、来源健康、页面任务树和右侧检查面板；C 阶段在同一工作台内增加样例回归、字段差异、质量提醒。实际数据字段、错误状态与按钮行为以 API 契约为准。
- **响应式与可访问性**：沿用原型的桌面多栏、窄屏收起侧栏、表格横向滚动、工作台预览区下移和运行检查区纵向排列。键盘焦点、表单标签、状态文字、加载/空/失败状态以及减少动画偏好都要在真实组件中保留。
- **验收方式**：每个阶段在相同尺寸下对照原型截图检查布局、颜色、间距、层级和交互状态；至少覆盖桌面、窄屏以及空数据、加载、失败、部分成功。视觉核对后再用真实 API 验证点击路径，不以静态截图代替功能验收。确需偏离原型时在对应任务中记录原因和更新后的设计决定。

## 5. 迁移、发布与验证策略

1. **先盘点后迁移**：导出旧表数量、来源、重复键和存储占用；对现有数据库做备份。新增表、索引和外键先以兼容迁移上线，再分批回填。迁移日志记录版本、已处理数、异常数和可重试游标。
2. **双入口过渡，单一写入归属**：旧磁力 API/下载插件在过渡期保持可读可用；新采集器写 `records`。需要共存的旧采集入口通过明确适配器进入统一写入服务，避免 `resources` 与 `records` 长期双写但语义不同。切流后核对总数、唯一键、来源、历史状态和抽样字段，再移除旧导航。
3. **灰度顺序**：先交付阶段 0 的校验与只读能力；再开放 A 的手动创建/预览/运行；随后开启 B 的调度和分页；最后上线 C 的提醒及保留期清理。每阶段都可停止新入口而保持旧数据可查。不可逆的旧表清理不放入 v2.1。
4. **验证矩阵**：单页 HTML、JSON 数组、浏览器渲染页、列表详情、分页停止、缺字段、跨来源同键、重复派生、超预算、重启租约、浏览器失联、旧磁力迁移各有真实或固定样例。数据库迁移在旧版本快照上演练，浏览器能力以 `scrapio-browser` 联调记录确认。
5. **交付门槛**：Go 单元/集成测试、前端构建、原型视觉对照和主路径交互验收均通过；发布检查与执行器能力矩阵一致；从记录能逆向找到采集器版本、运行、任务及原文；`静默成功` 为零。部署后由试用样例测量产品规划中的首次入库、查询和故障定位指标。

## 6. 开工前需要定下的少数选择

- 选定三类真实验收站点及两类数据集，明确哪些需要浏览器和登录态；这决定 JSONPath 子集、动作和预算的首版边界。
- 明确磁力旧入口在 A 阶段后的维护方式：继续只读，还是通过统一写入适配器接入；据此确定映射和切流范围。
- 根据实际磁盘容量确定文档/截图默认大小与保留期；默认先只限制新增内容，清理任务经备份演练后开启。

这些选择不阻塞阶段 0 的发布校验、任务语义修正和迁移盘点。
